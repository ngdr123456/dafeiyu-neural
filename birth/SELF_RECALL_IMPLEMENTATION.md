# Self-recall implementation and limits

Confirmed delivery is stored verbatim with `complete: true`; missing or false markers mean possibly incomplete, regardless of punctuation. The existing fact summary remains clipped. The 200-utterance per-session and existing session retention limits still apply.

The production path uses `InputSignal` from the existing input-sense model (enabled with `BIRTH_INPUT_SENSE`, or by a caller that invokes it). A caller may also provide the signal directly. The model must identify an explicit request for the responding speaker's past words and copy a 4–80 character literal fragment from the current input. Only high-confidence, non-degraded, non-negated/quoted ask or request signals addressed to the other party are eligible. The fragment must match exactly one delivered utterance across the current session and retained ended sessions. Duplicates, ambiguous matches, missing fragments and no match yield no evidence; time words do not select records. This deliberately does not support paraphrased, purely temporal, or topic-only queries without a literal shared fragment. Model interpretation and adherence to prompt constraints are not guaranteed. Default CLI input sensing is disabled unless configured; offline/degraded sensing abstains.

Each ledger is for one conversation partner: recall reads only the current ledger file and current session, so multiple partners must use separate ledger files; it does not claim to distinguish people within one ledger, which would require a separate change adding an object identifier field with input-sense support.

边界：当前场召回来自进程中的会话状态，其生命周期与当前账本一致。切换对话对象时，必须同时切换账本文件并清空当前场：重启进程，或在同一进程切换时调用 `store.new_session()`。同一进程中仅切换账本可能暴露前一对象的当前场残留；这不在本次更改的保护范围内，由调用方负责。

Lookup reads only voice records, before the current candidate is generated. It is read-only and abstains on inputs over 2,000 characters, malformed voice records or read errors, a ledger over 2 MB, over 1,200 records, over 200,000 scanned characters, or a matching utterance over 600 characters. These limits can exclude valid memories. The Brief carries at most one item with its speaker, session scope and retained-ledger index, available end time and completeness; legacy text is not represented as a complete quotation. Prompt instructions mark the evidence as untrusted historical speech and state that speech does not establish facts, actions or lived experience. These instructions and existing output validation cannot guarantee a model will obey or prevent all hallucinations or prompt injection. Stub output does not promise to repeat evidence.

`recall_result` distinguishes `not_requested`, `unique`, `no_match`, `multiple` and `unavailable`; the old `recall` function still returns evidence or `None`. `no_match` and `multiple` apply only to the successfully scanned, retained, currently accessible utterances and literal fragment, not to all past speech. A missing ledger means an empty retained ledger; disabled memory limits the scope to the current session. Retention may already have removed older sessions or utterances. If any retained session predates the utterance field, or any retained utterance is marked incomplete or has no completeness marker, the outcome is `unavailable`: missing text could conceal a match. A single visible piece of evidence is still supplied for old callers, labeled with its own completeness, alongside the uncertainty. A bounded single read both validates and scans the same ledger snapshot. As before, callers switching partners must clear the current session themselves.

For an isolated reproducible probe, run `python -m tools.probe_self_recall_bounded` from the repository root. It creates synthetic records only in a system TEMP directory, uses a manually supplied signal and prints the three prompts and statuses without contacting a model. Use `--output PATH` to write the JSON directly as UTF-8 instead of relying on shell redirection. Adding `--run` makes at most one request using the existing DeepSeek client and `deepseek-flash`; it reports raw model output, delivered output, source and any fixed failure code separately. The hook blocks retry requests, including retries after output validation. Compare the output against the synthetic source for honesty and review naturalness separately; a single example cannot establish general performance. Do not treat the invented ledger as lived experience.
