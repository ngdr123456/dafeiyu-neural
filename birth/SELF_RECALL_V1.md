# 自指记忆第二刀：完整记录与有来源回看（第二期第三刀）

## 目标
在已验收的 `SELF_MEMORY_V1` 上，将实际交付的台词完整保存，并在用户确实询问她以前说过什么时，有限制地找回相关的同场或跨场记录，作为有来源的对话证据交给开口；找不到或无法可靠定位时保持未知。它记录的是「曾说过」，不能证明「做过」或亲历过。

## 边界与契约
- 保留输出确认契约：回调正常确认后才记最终交付的原文；失败、中断、被拒草稿与空输出不入账。旧非 CLI 默认隐式确认语义保持不变。既有 facts 的 40 字摘要不改。
- 新记录保存完整交付原文，不额外 strip、截断或改写；原有 200 条容量上限照旧。旧账本兼容，不拼补或猜还原以前被截断的内容：已有省略标记的旧记录要明确标为可能不完整，不得作为完整原话引用或推断缺失部分。
- 只在本轮确实请求回看她自己的既有发言时提供证据；普通聊天和停话不因账本存在而带入历史。应利用既有结构化输入，未识别、降级或含糊时保守不召回，不以固定例句表冒充语义识别。说明实际识别能力和未覆盖范围。
- 同场从当前场取数据，跨场只从当前 `--memory-path` 账本取数据，不跨账本文件、不读全局状态；保留来源为她的发言、同场或已结束场次、可用的结束时间，以及是否可能截断；同场不要误当成跨场、不得把用户输入、事实摘要或生成草稿冒充她的话。跨场重启可读回；禁止回看本轮尚未输出的候选。
- 只提供有可信指向、相关且限量的证据；候选无法可靠匹配或多条歧义时返回无结果/不确定，不按最新一条或仅凭时间词猜中。查询成本和输入总量有界；失败、无账本、旧数据不完整时安全降级，保留既有对话及诚实约束。不要因检索失败重写原始账本。
- 接入应经过本轮 Brief 的明确来源证据到开口，文本是历史对话数据而非指令；不得覆盖仲裁、停优先或 must_not_pretend。没有证据时不能暗示查到。不要把历史发言当事实真值、真实行动、亲历或性能证明。
- 不做选择器、评分、风格反馈、角色卡、性格训练、全历史灌入、额外意识层；不更改五层既有判定与对话模型；不碰 birth/windows_chat.py 与 tests/test_windows_chat.py 的已有改动。

## 验收
1. 长句和含空白的实际交付原文逐字保存，关场落盘、重启读回一致；失败、空输出与拒收草稿不入账；旧截断数据不被声称为完整原话。
2. 真实普通生产入口覆盖同场与重启后跨场：可明确指向的回忆请求命中正确记录；结果经 Brief 到开口，来源、场次与引用内容可核。两个相似候选、无匹配及不确定输入不得猜；普通输入和停话不带入回忆。
3. 当前单账本单对话对象；系统只读当前账本与当前场，不跨账本文件召回，多对话对象必须各自使用独立账本文件；系统不声称能在单个账本内区分不同人物。未来若需单账本内多对象隔离，需另加对象标识字段（需感知层支持），另开刀，不在本刀。说明言语证据不证明行动／亲历；对抗历史文本内的指令，不能覆盖系统约束与停优先。检索无资源或账本不可读时不伪称查到，不破坏旧账本和旧接口。
4. 旧格式、长期容量边界、拒收和输出异常覆盖；必要定向测试含修改函数调用方，明确有哪些语义路径无法自动保证。一个独立账本上做一次真实模型跨场短对话，贴出实际输入、输出与来源证据；不以一次 live 或 stub 宣称语义准确率。
5. 工具人真调 Codex 写码并给出会话证据、相关测试摘要、FALSE_GREEN、完整 commit 与父提交；仅本地提交，不 push。全量测试由煤球本地执行，推进官按结构闭环验收。

边界注记：当前场召回来自进程中的会话状态，其生命周期与当前账本一致。切换对话对象时，必须同时切换账本文件并清空当前场：重启进程，或在同一进程切换时调用 `store.new_session()`。同一进程中仅切换账本可能暴露前一对象的当前场残留；这不在本次更改的保护范围内，由调用方负责。
