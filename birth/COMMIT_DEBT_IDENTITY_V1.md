# 上场多笔债的身份（COMMIT_DEBT_IDENTITY_V1）

> 底层缺口：动力层的输入是上场未了账，但账上的债没有身份——drive／arbitrate／articulate／pipeline 六处都只取 `prior_session.commitments_pending[0]`。用户点名第二笔时，认账、开口话题、消账全落在最老那笔。

## 问题

上场留下两笔未兑现：A「我答应你周末讲那个故事」、B「我答应你明天聊月亮」。

用户说「月亮的事呢」：

- 判催债是对的（主题命中 B），
- 但 why、stub 话题、say_intent 话题、`pressed_frame`、`resolve_prior_commitment` 都取 `[0]`，于是回答和消账都落在 A。
- 用户明确说「月亮的事已经补了」，被销掉的是 A，B 还在——账错了对象。

## 原则

**债有身份。** 本轮用户话点到哪一笔的主题，就认哪一笔。催债动作点不到可落最老一笔；销账另用保守规则，不能把催债默认目标当作已兑现身份。

- 认账只看账上那笔债的文案主题词是否出现在用户话里，不扫用户句式的禁词表。
- 一笔都没命中 → `None`。
- 命中多笔时：命中词数多者优先；同数取更长词；最高分仍并列则 `None`，不假称认出唯一身份。

## 接线点（全部走同一个认账函数）

新增 `commit_extract.match_pending_commitment(user_text, prior) -> str | None`，返回账上被点到的那一笔原文。

1. `drive.py` S12a 与兜底 5a：why 用认出的那一笔（认不出才 `[0]`）。指纹前缀「上场承诺｜」不变。
2. `arbitrate.py` 催债分支：`say_intent` 的话题取自认出的那一笔；同时写 `ThoughtBrief.pressed_commitment`。
3. `types.ThoughtBrief` 增字段 `pressed_commitment: str = ""`（工程师通道；不上台）。
4. `articulate.py` stub 催债模板：话题优先读 `brief.pressed_commitment`，没有才回落 `[0]`。
5. `commit_extract.pressed_frame`：`prior_press` 的目标优先读 `brief.pressed_commitment`。
6. `arbitrate.py` 在选 dominant 之前写 `recognized_prior_commitment` / `recognized_same_commitment`，独立于 `press_commit` 与 `pressed_commitment`。即使 meaning/org 胜出也保留身份。
7. `pipeline.py` 用户明示已兑现时，认出唯一身份只销该笔；未认出且仅一笔则销该笔；未认出且多笔则一笔不销。同场采用相同规则，`resolve_commitment(match=...)` 精确移除目标；§6 仍只读同场。

同场与 prior 同时有债时，销账身份在两边合并去重的 pending 中竞争；只点名同场那笔不会连带销掉 prior 的单笔，反之亦然。未点名的单笔回落只适用于合并后仅一笔。催债动作仍沿各自的现有口径，不把 prior 变成 §6 对象。

`user_presses_prior_pending` 的判定改为先调认账函数：认得出 → True；认不出仍走既有「跨场回指＋催答应／约定壳」分支，行为不变。

**题眼优先取账上文案的内容词，空时回落二元组。** 从账上文案的二元组中排除虚词／代词／功能字（至少覆盖：的了呢吧吗啊呀哦嘛和与跟同是在我你他她它您咱就都也还又很太把被让给对从到这那个一上下来去会要想说聊讲），只保留两个字都不在该集合里的内容词，有内容词时取位置最靠后的一个；内容词为空时回落最后一个二元组（恢复「上海」「小说」这类本身含功能字的真正内容词的题眼）；只有二元组本身为空才返回空串，由 arbitrate 用「这事」，不把整句债当话题。不追加 `compact[:3]` 这类「前三字」伪词。例：「我答应你下次聊月亮和海边的事」→「海边」，「我答应你周末讲那个故事」→「故事」，「我答应你下次去上海」→「上海」，「我答应你下次聊小说」→「小说」。

## 不做

- 不改同场 `last_commitments` 的 §6 口径（仍只看同场）；只修同场销账身份。
- 不改「催债不立新债」（COMMIT_IDENTITY_V1）：认出的那笔销账后，台上新应下的约定仍进候选，不回填成 pending。
- 不加禁词、不改台上句式、不做语义模型或向量匹配；认账只用账上主题词。
- 本次同批输入作用域修复见 INPUT_INTENT_V1；不改变仲裁主导层规则。

## 已知误认（本刀不修）

- 认账以「任一主题词出现在用户话里」为准，时间词也算命中。账上 `[故事, 明天聊月亮]`、用户「明天再说吧，上次答应的事已经补了」会认成月亮那笔并销它（改前销最老一笔）。这是关键词认账的边界，不用语义模型，本刀不修。
- 两笔主题高度重叠时，用户只说共同主题词（如「月亮」）最高分并列则不能销账；说出差异词（如「海边」）才认后一笔。时间词仍可能构成唯一最高分，这是账上主题词匹配的残余边界。

## 验收（单测）

1. 两笔债 A、B，用户点名「月亮」→ `brief.pressed_commitment == B`，drive why 与 stub 话术都是 B，A 未被销。
2. 两笔债 A、B，用户泛指「你上次答应我的事呢」→ 仍落 A（最老一笔），两笔都还在。
3. 两笔债 A、B，用户说「月亮的事已经补了」→ 只销 B，A 仍在账上。
4. 单笔债行为与改前一致。
5. 仅运行本刀直接相关测试与调用方，不以全量绿灯代替真实模型验收。
6. 两笔互含 A/B，用户「海边那事已经补了」→ 只销 B，pending 剩 A，resolved 只含 B；drive why／say_intent／stub 话术均指 B。
7. 长债题眼不落虚词尾：「我答应你下次聊月亮和海边的事」→「海边」；stub 话术含「海边」、不含「聊的事」。
8. 内容词为空时回落最后一个二元组：「我答应你下次去上海」→「上海」，「我答应你下次聊小说」→「小说」；连二元组都没有时话术用「这事」，不塞整句债。
