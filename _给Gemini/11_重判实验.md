## 〇、判据（先写，来自 Claude）

```
· 同输入重判不一致 **≥25%** ⇒ 标签噪声太大，任何文本近似物能解释的上限都受限
· 去掉读数后 mechanical 翻成 none 的比例 **≥50%** ⇒ 标签主要是读数的回显
· 两项都低于判据 ⇒ 标签可用
```

**★ 且我事先发现：第二项在这份数据上**结构上不可判**（215 行只有 24 行存了 `mech`，其中 mechanical 只有 **3** 条）。**
**⇒ 所以本次只跑了「同输入重判」这一半，用 text-only 条件。**

## 一、结果一：**同输入重判不一致 30%** ⇒ 判据成立

```
215 行 × 2 遍（都 text-only，不传 mech）
  两遍一致 **150**
  不一致   **65（30%）**

不一致的方向（pass1 → pass2）：
  too_little → none        11
  none       → too_little  10
  mechanical → off_topic    5
  mechanical → none         4
  too_little → off_topic    3
  mechanical → too_little   3
  none       → off_topic    3
  too_little → mechanical   3
```

**⇒ 按判据（≥25%）：**标签噪声太大**。**

**★ 直接后果：那 20 条 mechanical 里，按 30% 的翻转率，**大约 6 条可能只是噪声**。**

**★ 所以 Claude 那句「不把 mechanical 计数当训练目标」有数据支持 —— 不是保守，是必要。**

---

## 二、结果二：**去掉读数后，mechanical 从 9.3% 涨到 29%**

```
原判定（带读数）   mechanical **20 / 215 =  9.3%**
text-only（去读数）mechanical **62 / 215 = 29.0%**

转移矩阵（原 → text-only）：
  原 none（176）      → none 88（50%）｜**mechanical 43（24%）**｜too_little 20｜off_topic 12｜…
  原 mechanical（20） → **mechanical 16（80%）**｜none 3｜off_topic 1
  原 too_little（13） → too_little 5｜none 3｜mechanical 3｜off_topic 2
  原 off_topic（3）   → off_topic 2｜too_little 1
  原 boundary（2）    → boundary 2
  原 too_much（1）    → too_much 1
```

### 这个方向说明什么

```
· mechanical 在去读数后**很稳定**（80% 保留）
  ⇒ 它**不是**读数的回显
  ⇒ 按 Claude 的判据（翻成 none ≥50%），**不成立**（实测只 15%）

· 但 none 里有 **43 条（24%）**在去读数后变成 mechanical
  ⇒ 方向是**单向的**：读数让 judge **更宽容**
```

**⇒ 正确表述：**

> **读数**不是** mechanical 的来源，而是**它的稀释剂**。**
> **`JUDGE_SYSTEM` 把读数定为唯一依据，结果是：读数"正常"时放过，",
> 而"像不像复读"这件事读数里根本没有，于是被放过。**

**⚠️ 这一条是**线索**不是定论**：pass1 是 text-only、original 是带读数，两者混合了「噪声」与「去读数」。
**⇒ 严格说，只能说「去读数后 mechanical 率上升 19.7 个百分点」，**不能**说"因为读数"。
**⇒ 要分离，需要**同一批数据**都带读数重判一遍（而那要求 mech 被存下来 —— 只有 24 行有）。**

## 三、这两条结果合起来意味着什么

```
① 标签有 30% 的自身噪声        ⇒ 单条判定不可信，只能看大样本趋势
② 去读数后 mechanical 翻三倍   ⇒ 训练时的标签被读数系统性稀释
③ 两者叠加                     ⇒ **mechanical 这个计数，既不可靠也不稳定**
```

**⇒ 所以我上一轮那些"文本近似物"的尝试，上限本来就很低 —— 不是近似物不好，是**被预测的对象本身有 30% 噪声**。**

**★ Claude 的判断在这一点上完全正确：先把标签效度查清，再谈改进。**

## 十、★ 长度效应**反转**：Claude 那条只在带读数的标签下成立

```
                 <40 字   40–60 字   >60 字
原始标签（带读数）    6%  →    10%  →   **22%**   ↑ 上升
去噪标签（text-only）**35%** →  22%  →    13%     ↓ **下降**
```

**⇒ 同一个量、同一批数据，两种标签下方向**相反**。**

**⇒ 所以 Claude 的「用户话越长越容易被判 mechanical」**在去噪标签下不成立**。**

**★★ 而且读数的方向很反常：**

```
短输入：35% → 6%    读数**压制** mechanical 29 个百分点
长输入：13% → 22%   读数**推高** mechanical  9 个百分点
```

**⇒ 可能解释（**未验证**）：长输入的轮次里读数更容易"异常"（张力高/敏化高），
judge 看到读数异常就判 mechanical —— 这会让 Claude 原来那句「读数在驱动标签」**部分复活**，
但只在长输入上，且 `>60 字` 只有 **23** 条。
