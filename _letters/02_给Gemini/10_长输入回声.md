# 长输入 → 回声：真正的失控点（2026-10-28 第三轮）

> **性质**：执行者离线核查。**判据先写、后看数据。**
> **缘起**：Claude 指出的长度效应（<40 字 6% / 40–60 字 16%），我复核后顺着他那条"内容计划"的线索往下查，
> 结果发现他指错了 prompt —— 也因此这条结论和他不同。

---

## 一、先纠正一处：`RENDER_SYSTEM` 在训练里**从未执行**

**Claude 的推断：**

> 「生成 prompt（`04_render.py` 的 `RENDER_SYSTEM`）要求完整、不选择、不添加的重述：
>  『一个字的新内容都不许加』，第 8 条『不要遗漏…材料里有几件事就说几件』…
>  用户话越长，回声越长。**这是长话更容易判 mechanical 的最直接解释。**」

**代码事实（三处，都可复核）：**

```python
# train.py:330
use_render: bool = False          # ← 训练默认**不开**渲染层

# train.py:770
t = Trainer(use_api=not a.offline, use_think=not a.offline)   # ← 默认**开**思考层

# pipeline.py:624-632
if self.thinker is not None:
    response_mode = "brain"       # ← FRAME_SYSTEM
elif self.renderer is not None:
    response_mode = "render"      # ← RENDER_SYSTEM；**elif**，thinker 在时永不执行
```

**⇒ 双保险：`use_render=False` 让 `renderer` 为 None；即使打开了，`elif` 也保证 thinker 优先。**

**⇒ 结论：`RENDER_SYSTEM`（含第 8 条「不要遗漏」）**在训练里从未生效**。**

**★ 数据侧吻合：`action_observation.mode` 在 12 条有记录的行里**全是 `brain`，0 条 `render`**（另 203 条是字段后加之前的历史数据，标「未知」）。**

**⚠️ 所以「放宽 RENDER 第 8 条」（Claude 第 4 步的条件 B）**做了也不会有任何效果**。**

## 二、那长话效应来自哪：**FRAME 第 6 条 × 信息量**

**真正生效的生成 prompt 是 `FRAME_SYSTEM`（`engine/think.py:52`），它的第 6 条是：**

```
81  6. **说短**。一到三句。不要总结，不要排比，不要分点。
```

**判据（先写）**：若"长度效应"来自"说不出短"，则输出应大量超过三句；若"说短"被遵守，则问题在**篇幅与信息量的冲突**上。

### 数据

```
用户话长度 vs 输出长度  相关系数 **0.41**（全体 215｜mechanical 0.41｜none 0.42）

长度档      n   输出长度中位  句数中位  mechanical 率
<40       110       24         1         **6%**
40–60      82       33         2        **10%**
>60        23       39         2        **22%**

输出超过三句的轮次：**4 / 215 = 2%**
```

### 判定

```
✅ 「说短」**被遵守**（只有 2% 超过三句，句数中位 1–2）
    ⇒ 所以"说不短"不是原因
✅ 但输出长度仍随输入增长（中位 24 → 33 → 39 字）
✅ mechanical 率随输入长度单调上升（6% → 10% → 22%）
```

**⚠️ `>60 字` 只有 23 条 ⇒ 按纪律写「线索」，不下方向结论。**
**⚠️ 相关系数 0.41 是**相关**，不是因果。**

## 三、推断（**未验证**，但可检验）

```
用户的话信息量大（60 字、含 3 件事）
  × FRAME_SYSTEM 要求「一到三句、不许总结、不许排比」
  ⇒ 只有两种出路：
       (a) 漏掉一些 → too_little
       (b) 把它压缩进一两句 → 压缩必然丢血肉、留骨架 = **回声**
  ⇒ (b) 正是 tutor 说的「换个语序递回去」
```

**★ 为什么这个解释比 Claude 那个更贴合数据：**

```
· RENDER 第 8 条：在训练里从未执行（代码三处可证）
· FRAME 第 6 条：**唯一生效**，且方向上要求"短"
· 数据：句数达标（2% 超三句），但机械率随输入长度上升
  ⇒ 不是"太长"，是"在够短的篇幅里装不下"
```

## 四、这个发现对下一步的影响

**Claude 第 4 步（生成层 A/B）的对象要换：**

```
他写的：条件 B = 放宽 RENDER 第 8 条（允许只回应其中一句）
实际该改：条件 B = 在**长输入**下放宽 **FRAME 第 6 条**的篇幅上限
          （或明确允许"只回应其中一件事"，并允许说三到五句）
```

**判据可以沿用他给的那组，但要看的方向多一条：**

```
· B 的 mechanical 率低 ≥8 个百分点
· AND too_little / too_much / boundary / fabricated 合计率上升 ≤5 个百分点
· ★ 新增：B 的输出句数**允许上升**，但要检查「重复自己」有没有跟着升
  （放的代价是啰嗦，不是回声）
```

**⚠️ 而且这一步**必须有 API**，要你批准。**
