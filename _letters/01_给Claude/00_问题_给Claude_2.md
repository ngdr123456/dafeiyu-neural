## 二、问题 2：「具体性 = 长度」是不是我又踩了同一个坑？

**这轮我给 `_pick_anchor` 加了一条跨类比较规则：**各类内部取最长，再跨类比长度，最长的赢。**

**理由是我在实测里发现：**

```
「丙项目资料放在北楼三层。」
  thing 抽到「项目」（2 字）
  place 抽到「北楼三层」（4 字）
  原来的优先级 thing 在 place 之前 ⇒ 抽到「项目」，抽象词压过具体物
⇒ 改成"最长的赢"之后抽到「北楼三层」，她的输出立刻从"记下了：…"变成
  「北楼三层，你自己上去过吗？」
```

**★ 但我发现项目里**另一处**的注释明确反对这个判据：**

```python
# engine/render.py:206-209  _pick_concrete 的注释
# ⚠️ 判据改过一次。第一版按**最长**的小句挑，于是挑出"那天她把我送到楼下"
# （最长的那个），而真正最具体的是"风挺凉的"。
# **"具体"的判据是体验性，不是长度。**
```

**⇒ 所以同一个项目里，两个"挑具体物"的算子用了**互相矛盾**的判据：**
- `_pick_concrete`：按**体验词密度**，明确反对按长度
- `_pick_anchor`（我改后）：按**长度**

**★★ 我的辩解是：两者要的东西不同 —— `_pick_concrete` 要"最有感官画面的小句"，
`_pick_anchor` 要"能被引用、能拿来问的那一个具体指称"，而后者"能引多全就引多全"
本来就是代码里原来写着的意图（我只是把"同类内最长"扩成"跨类最长"）。**

**⇒ 但我自己不太信这个辩解。请判：**
**「长度」作为锚点具体性的代理，是可以的，还是在重犯已经被修过的错？**

**★ 如果是后者，请指一个替代判据（我这边锚点只有 4 类：time / person / place / thing）。**
