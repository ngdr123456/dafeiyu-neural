## 〇、 针对你发现的「坑 ②/③」做一处关键加固（在 `tools/seed_ledger.py` 中统一封装合法 `input_origin`）

你在第三节抓出的「坑 ②/③」极其关键：
> `p._input_origin = {...} 无效 —— turn() 第一行就是 self._input_origin = normalize(input_origin, raw, topic_id)，默认 input_origin=None 会把它覆盖掉 ⇒ 台账里 session_id 全是 None；且 normalize() 要求带 schema=1 / input_sha256=digest(raw) / topic_id`

**请立刻看这一条对 `tools/seed_ledger.py`（以及接下来的 `G2` 和 `F5` 实验）的直接影响**：
- 如果 `seed_ledger(path, turns)` 写入的历史行和 `run_one_live(question, history)` 调用 `p.turn(question)` 时没有显式传入带相同 `session_id`（例如 `session_id=0`）的合法 `input_origin`，那么实时轮的 `session_id` 就会变成 `None`！
- 一旦 `session_id` 是 `None`，你刚写的「同场最近 5 轮保底并入 `sources`」和 `_unfinished_focus` 的同会话检查就会在 `run_one_live` 里失效！

### ★ 1 分钟加固动作（仅改 `tools/seed_ledger.py`）：
在 `tools/seed_ledger.py` 中写一个 5 行的辅助函数 `_make_origin(raw: str, session_id: int = 0, run_id: str = "seed_exam")`（调用 `input_provenance` 的 `digest` 算出合法的 `input_sha256`、`schema=1`、`session_id=session_id`）：
1. `seed_ledger()` 在写入预置历史轮时，若调用方未传 `input_origin`，默认用 `_make_origin(raw, session_id=0)` 填充；
2. `run_one_live()` 在调用 `p.turn(question, input_origin=...)` 时，若存在预置历史，默认传入与预置历史**同一个 `session_id=0`** 的合法 `input_origin`（若预置历史为空，即测首轮无记录场景，也传入合法 `session_id=0`）。
这样接下来跑 508/772/868、`G2` 和 `F5` 时，100% 不会踩 `session_id=None` 或 `schema/hash mismatch` 的坑！
