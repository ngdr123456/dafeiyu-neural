## 一、 五大系统架构级病灶（全有代码与数据铁证）

### 架构病灶 1：【状态生命周期断层】`Character.learn()` 只在训练批处理结束后（`Trainer._regrow`）运行，单轮运行期（及 `shell.py` 真人交互时）性格是冻结的！
- **代码病灶**：
  - 在 `train.py:585`，`self._regrow()`（调用 `Association.derive_from_ledger` + `ch.learn()`）只在 **36 轮循环全部跑完之后** 才执行一次！
  - 在 `pipeline.py:515`，每一轮 `ch = Character(self.character_path)` 读进来的都是**本轮训练开始前的旧 `character.json` 快照**（也就是上一场 36 轮结束时留下的 `boldness = 0.74`！）；更糟的是，紧接着下一行 `ch.update_state(mst.to_dict())` 又用 `polarity_from_mech(mech)` 把内存里的 `ch.polarity` 覆盖了！
- **架构后果**：
  1. 在 36 轮训练过程中，第 1 轮到第 36 轮看到的 `boldness` 根本不是实时演化的，而是冻结在上一场的旧值！
  2. **最致命的是**：当用户打开 `shell.py`（或界面）跟她做真人交互时，根本没有外层的 `Trainer._regrow()`——她在跟真人聊天的整个生命周期里，**`Association` 和 `Character` 永远不会更新**！

---

### 架构病灶 2：【单轮管线时序倒置】“未感知先裁决”——`ruminate()` 跑在 `cognition.extract()` 结算当轮 `REBUFFED` 之前！
- **数据铁证**：
  - 看你报的数字：36 轮里 `当轮算子 = 10`、`空档回想 = 26`，$10 + 26 = 36$！
  - 既然第 1 轮和第 26 轮发生了 `REBUFFED`，而且你写了 `if _enc == "REBUFFED": self._idle_gated = ...`，**为什么 36 轮里没有任何一轮的 `ruminate()` 被拦截掉（$10 + 26$ 刚好占满 36 轮）？**
- **时序根因（Act Before Sense）**：
  - 思考一下因果时序：第 $t-1$ 轮她做出了 `BOLD` 探照；第 $t$ 轮用户开口回了一句退缩敷衍的话 `raw_t`。
  - 系统在什么时候才能判定“第 $t-1 \to t$ 轮遭遇了 `REBUFFED`”？
    **必须在第 $t$ 轮跑完 `cognition.extract(raw_t)`（拿到 `has_new_claim == False` 且 `len_ratio < 0.85`）之后！**
  - 可现在的管线顺序是：**第 $t$ 轮 `turn()` 一进门（还没抽 `raw_t` 的 `claims`！），就先调了 `self.ruminate()`！**
  - 在 `ruminate()` 执行的那一刻：
    1. 第 $t$ 轮的 `claims` 还没抽出来，系统根本不知道用户刚说的这句 `raw_t` 就是一次 `REBUFFED`（碰壁）！
    2. 哪怕到了第 $t+1$ 轮开头去查台账最后一条 `entries[-1]`（即第 $t$ 轮），第 $t$ 轮本身不是 `BOLD`（`BOLD` 是第 $t-1$ 轮 `entries[-2]`！），如果只查 `entries[-1]` 的 `encounter`，永远查不到 `REBUFFED`！

---

### 架构病灶 3：【控制流旁路脑裂（Split-Brain Decision Bus）】`Responder + Character.modulate` 算出的 `bid` 只控制了被丢弃的模板层，大脑层的 `Frame.stance` 完全绕过了 `bid`！
- **代码病灶**：
  - 在 `pipeline.py:470-532`，系统花了大力气跑阶梯 `Responder.choose`、机制相位 `mcond`、以及性格层 `Character.modulate(R1–R4)`，算出最终动作 `bid`（例如 `R4` 因受挫把 `ASK_DETAIL` 右移收敛为 `REFLECT` / `ACKNOWLEDGE`，或 `TURN_IMMUTABLE` 让位给 `JUXTAPOSE`），然后传给 `self.responder.render(bid)` 生成模板字符串 `ren.output`。
  - **但是！** 到了第 624 行 `if self.thinker is not None:`（大脑模式，占线上 >95% 轮次）：
    - 模板 `ren.output` 被大脑输出直接覆盖丢弃；
    - 而 `_build_frame` 里的 `Frame.stance` 调的是 `stance_for(mst.phase)`——**它只读了原始的 `mst.phase`，根本没读经过 `Character.modulate(R1–R4)` 修正后的 `bid` 和 `char_note`！**
- **架构后果**：
  - **双轨脑裂**：当 `mst.phase == "ASKABLE"` 而 `Character.modulate(R4)` 因受挫介入把 `bid` 右移收敛成 `REFLECT` 时，模板轨在刹车，**大脑轨的 `Frame.stance` 却还在按 `ASKABLE` 踩油门（“张力已起，他还在讲，你有话可问。直接盯住他话里那个具体的词问一句”）！**
  - 也就是说，**整个 `Character.modulate`（R1–R4）在大脑模式下被 100% 旁路架空了**！

---

### 架构病灶 4：【工作记忆多头竞争与观测盲区】`Frame` 内 4 个注意力框并列轰炸，缺乏唯一的「工作记忆焦点仲裁器（`FocusPacket`）」
- **架构病灶**：
  1. `ruminate()` 在 `turn()` 开头无条件先跑，哪怕几毫秒后当轮算子 `Thought` 命中并把 `idle_thought` 在 `Frame` 中屏蔽掉，`ruminate()` 也已经把那对历史 `Claim` 写进 `ruminations.jsonl` 并记入 `seen_pairs` 白白作废了！
  2. `Frame` 里同时存在 `anchor/concrete`、`thought`、`unfinished_focus`、`idle_thought` 四套注意力指令。在没有当轮算子的 26 轮里，轮轮塞入 `idle_thought`，直接淹没了高价值的 `unfinished_focus`（导致 `自我连续性` 从 `6/36` 跌到 `3/36`）。
  3. `action_observation.observe()` 只接收了当轮 `Thought.quotes`，没有接收 `unfinished_focus` 和 `idle_thought` 的引文，导致后两者的真实执行率（`STRONG / WEAK`）处于观测盲区。

---

### 架构病灶 5：【无界累加器顶死饱和】`boldness` 用全量历史差值线性求和后再 `clamp`
- **数学病灶**：
  - `boldness = clamp(0.5 + 0.08 * (C - R), 0, 1)` 是对全量历史计数先算总账再截断。
  - 这违反了有界状态机的设计原则：一旦长程运行后 $C - R$ 攒到 $+20$（未截断值 $2.10$），天花板 `1.00` 之上就堆积了 $+1.10$ 的隐形泡沫——此后哪怕连续遭遇 10 次 `REBUFFED`，`boldness` 依然纹丝不动停在 `1.00`，系统彻底丧失负反馈调节能力。

## 二、 架构级重构方案：将 `Pipeline.turn()` 收敛为严格的「五段式单向状态机拓扑」

不需要大拆文件，只需要在 `pipeline.py` / `character.py` / `stance.py` / `action_observation.py` 中把数据流与时序拧成一条 **单向、无脑裂、单轮自闭合的五段式管线**：

```text
[Stage 1: SENSE 感知]
  MarkerEngine.parse(raw) + Mechanism.step(raw) → mst
  + cognition.extract(raw) → claims_t
        │
        ▼
[Stage 2: SETTLE 结算上一轮遭遇 (t-1 → t 单轮增量闭合)]
  若台账最后一条 entry_{t-1} 与本轮同 session_id 且 entry_{t-1} 为 BOLD：
    用 (entry_{t-1}, raw_t, mst.is_closing, claims_t) 当场判定 CONFIRMED / REBUFFED！
    当场增量更新 character.json 的 boldness（每步内 clamp: CONFIRMED +0.03, REBUFFED -0.06）
    并得出本轮实时状态：last_encounter ("CONFIRMED" | "REBUFFED" | "") 与 current_boldness
        │
        ▼
[Stage 3: ARBITRATE 工作记忆单焦点短路仲裁 (FocusPacket)]
  严格按优先级短路求值（前序命中则绝不调用后续算子，不白耗 seen_pairs）：
    Priority 1 (input):      cognition_ops.think(claims_t, ...) → 若命中，作为唯一 focus
    Priority 2 (unfinished): 若无 P1，且 last_encounter != "REBUFFED"，且存在 unfinished_focus → 作为唯一 focus
    Priority 3 (idle):       若无 P1/P2，且 last_encounter != "REBUFFED" 且 boldness >= 0.42
                             且距上次抛出 idle 已隔至少 1 轮 → 此时才调用 self.ruminate()！
    Priority 4 (lexical):    若 P1/P2/P3 皆空 → 才启用词级 _pick_anchor / _pick_concrete
        │
        ▼
[Stage 4: DECIDE 动作与姿态同构裁决 (消除模板轨与大脑轨脑裂)]
  1. 初始动作：Responder.choose(markers) + mcond.action
  2. 认知对齐：若 focus 非空且初始动作为兜底 REFLECT → 冲突类升级为 JUXTAPOSE，好奇类升级为 ASK_DETAIL
  3. 性格裁决：Character.modulate(bid, ..., last_encounter=last_encounter, boldness=current_boldness)
     （若 R1–R4 介入将 bid 右移收敛为 REFLECT / ACKNOWLEDGE / SILENCE，记录 char_note）
  4. ★ 同构注入 Frame.stance：stance_for(mst.phase, final_bid=bid, char_note=char_note, last_encounter=last_encounter)
     —— 若 modulate 介入收敛了 bid，Frame.stance 必须同步切换为收敛姿态（绝不允许模板在退让、大脑还在追问！）
        │
        ▼
[Stage 5: SPEAK & OBSERVE 生成与全覆盖观测落账]
  1. Frame 组装：只渲染唯一选中的 FocusPacket；self_state 注入实时 current_boldness 与 last_encounter
     （当 boldness >= 0.60 且非 REBUFFED 时，显式提示可用「有件事我想知道——」提问）
  2. Thinker.think(frame) 生成输出
  3. action_observation.observe(..., thought_quotes=focus.quotes, thought_origin=focus.origin)
     统一观测 input / unfinished / idle 三类焦点的 STRONG / WEAK 落地率，写入 LedgerEntry！
```

## 三、 请逐项核对这四处具体代码落点

### 1. 修补「状态生命周期断层」与「时序倒置」（Stage 1 & Stage 2）
- 把 `cognition.extract(raw)` 放在 `ruminate()` 和 `Character.modulate()` **之前**；
- 在 `cognition.extract(raw)` 拿到 `claims_t` 后，直接调用 `association` 的单步判定函数评估 `(entry_{t-1}, current_turn)` 是否构成 `CONFIRMED` 或 `REBUFFED`；
- 无论是在 `train.py` 还是 `shell.py` 单轮对话里，一旦判定出新的 `CONFIRMED` 或 `REBUFFED`，**当轮立即增量更新 `Character` 的 `boldness`（每步内 `clamp`：`CONFIRMED` $+0.03$，`REBUFFED` $-0.06$）并落盘**，让紧接着的 Stage 3（`ruminate` 门控）、Stage 4（`modulate` R4）和 Stage 5（`Frame.self_state`）立刻吃到刚刚发生的遭遇结果！

### 2. 修补「控制流旁路脑裂」（Stage 4：`stance.py` 与 `pipeline.py`）
- 在 `stance_for()`（或 `_build_frame` 组装 `stance` 时）传入经过 `Character.modulate` 裁决后的 `final_bid` 与 `char_note`：
  - 当 `char_note` 非空（即性格层 `R1–R4` 介入把动作向右推到了更保守的 `REFLECT` / `ACKNOWLEDGE` / `ACKNOWLEDGE_CLOSE` / `SILENCE`）时，**用性格收敛姿态覆盖原始 `mst.phase` 的进攻型姿态**（例如：`「性格收敛（%s）：这一轮不要追问，不要翻旧账，只用一句简短的话平实接住或承认他刚说的事。」`）！
  - 这才真正做到了：**性格层一踩刹车，模板轨和大脑轨同时减速！**

### 3. 修补「工作记忆多头竞争」（Stage 3：短路求值单焦点 `FocusPacket`）
- 把 `self.ruminate()` 从 `turn()` 开头移到 `cognition_ops.think()` 和 `unfinished_focus` 判定**之后**：
  - 只有当 **`self._pending_thought is None` 且 `unfinished_focus is None` 且 `last_encounter != "REBUFFED"` 且 `boldness >= 0.42` 且上一轮没有刚抛过 `idle_thought`（至少隔 1 轮冷却）** 时，才调用 `self.ruminate()`！
  - 这样既不会在有当轮算子时白白消耗 `seen_pairs`，也不会让 `idle_thought` 泛滥成灾去挤占 `unfinished_focus` 的自我连续性！

### 4. 修补「观测盲区」（Stage 5：`action_observation.py`）
- 传给 `observe()` 的 `thought_quotes` 取当前唯一生效焦点的 `quotes`（无论来自 `input` 当轮算子、`unfinished` 悬念、还是 `idle` 空档回想），并在 `action_observation` 字典中增加 `"thought_origin": "input" | "unfinished" | "idle" | ""` 字段。
