## 二、 唯一收尾项：第 6 道门（`声明目标流程` / `actual_source_change_reconsider`）精准排查与复绿

你在第五节如实汇报了 `check_charter()` 六道门当前“五绿一红”：

- 但含 5 个实时 API 用例的 `spec/有界目标承诺模型诊断_20261008.json` 中，`actual_source_change_reconsider` 出现 `semantic_fit_observable=false`（`4/5` 通过，总门红）。

在重跑该诊断脚本前，请先核查一个**极可能与本次 `think.py` 改动直接相关的结构性原因**：

### 1. 核查 `_needs_fact_guide(self)` 是否漏掉了 `relational_context` / `self_goal` 激活态
在《去助手化与训练器修复》中，我们将包含关键规则的 `FACT_GUIDE` 从 `FRAME_SYSTEM` 移出，改为按 `_needs_fact_guide(self.raw)` 条件注入：
> `FACT_GUIDE` 原文包含：**“旧话与新话冲突时保留更正，不把旧说法当成当前事实；问到既往说过的事情或指代，先查下面的原话记录，有原话就点出原话，不凭印象编造。”**

请注意：
- `actual_source_change_reconsider`（更正既往信息源/说法后重新核对）依赖的正上面那句**“旧话与新话冲突时保留更正，不把旧说法当成当前事实”**！
- 但在 `think.py` 中，`_FACT_ASK` 正则目前只匹配了 `r"收着|谁收|在哪|叫什么|上次说|按你之前|你记得|什么模型|你是谁|…"`。如果 `actual_source_change_reconsider` 的提问原话没有命中这几个词，而它是靠 `self_goal.applies(frame)`（即 `frame.relational_context.get("groups")` 非空，或 `frame.own_task.get("goal_selection")` 非空，或含问号/核对指令）触发的目标核对流程，那么此时 **`FACT_GUIDE` 就根本没有注入到 `Frame` 的 Prompt 里**！

### 2. 修复建议（1 行条件补齐，零副作用）
请检查 `engine/think.py` 中的 `_needs_fact_guide`。如果它目前只接收 `self.raw` 或只跑了正则，请将其条件扩展为：**命中 `_FACT_ASK` 正则，或者当前帧已激活 `relational_context["groups"]` / `own_task["goal_selection"]`**：

```python
def _needs_fact_guide(self) -> bool:
    if _FACT_ASK.search(self.raw or ""):
        return True
    if (self.relational_context or {}).get("groups"):
        return True
    if ((self.own_task or {}).get("goal_selection") or {}).get("selected"):
        return True
    return False
```
*为什么这样改最干净？*
- 日常倾诉轮（包括 `A 还是 B` 纠结轮）中，`relational_context["groups"]` 为空且无核对目标，依然 **100% 不会注入 `FACT_GUIDE`**，去助手化效果完全不受影响；
- 一旦进入关系记忆核对或声明目标流程（`relational_context["groups"]` 或 `goal_selection` 非空，例如 `actual_source_change_reconsider`），**100% 必注入 `FACT_GUIDE`**，确保 Thinker 严格遵守“旧话与新话冲突时保留更正，不把旧说法当成当前事实”。
