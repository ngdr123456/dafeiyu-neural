# 验收标准 v1（管理员用这份判分）

> 这份文件把用户对"满分"的定义写成**可逐项判的清单**。管理员按它验收每个版本。
> 它的权威来自用户原话，**不来自我、也不来自管理员自己的口味**。
>
> 用户原话（确立本标准的依据）：
> > 「我想要的就是在我的要求下成长起来的满分的模型。这就是对我的『有用』。
> >  至于满分要求是什么……大概就是**参照数据对心理学和生物学的抽象分析，
> >  用代码构造出一个类似系统，既能像人一样进行逻辑沟通，也不能违反书籍里的思想**。
> >  至于怎么验证书籍的每个观点，这需要你自己整理并做并集交集整理，形成逻辑闭环。
> >  最后再喂回系统里。」
>
> ⚠️ 所以：**管理员的评价标准是这三条，不是"回答得好不好听"。**
>    凡是拿自己的审美去判的条目，一律不许进这份清单。

---

## 三条轴（满分 = 三条全过）

### 轴 1｜书的忠实：不违反书籍里的思想

| 编号 | 判据 | 怎么查 |
|---|---|---|
| **F1** | 系统里每一条规则/原子/机制量，都能追溯到书里的哪句话 | `tests/verify_traceability.py`；追溯不到必须是标 `ENG` 的工程决策 |
| **F2** | 系统中**没有任何表述与书冲突** | 逐条比对观点总表；冲突必须进裁决表，不许沉默 |
| **F3** | 书里被引用为判据的原句是**逐字**的 | 观点总表的 `quote` 字段必须在全文里逐字命中 |
| **F4** | 冲突裁决给出了理由与上位依据 | `spec/规格_统一模型_v1.md` 的冲突表；新增冲突必须有条目 |

### 轴 2｜构造出类似系统：抽象分析被代码实现

| 编号 | 判据 | 怎么查 |
|---|---|---|
| **S1** | 书里的观点**并集完整**：每条观点都有归宿 | 观点总表的 `status` ∈ {已实现, 明确不实现并写理由}；**不许有"没提到"** |
| **S2** | **交集一致**：观点之间不互相矛盾 | 观点总表的 `conflicts_with` 全部有裁决 |
| **S3** | 逻辑闭环：从观点 → 规则 → 行为 → 输出，每一步都能反查 | 取一条输出，能一路追到书里的哪句话 |
| **S4** | 能被自动检查的，都已进测试套件 | 每条"可操作化"的观点都有对应断言或审计脚本 |

### 轴 3｜像人一样逻辑沟通

| 编号 | 判据 | 怎么查 |
|---|---|---|
| **H1** | 答得上话：不无端空转 | 沉默率与"无标记率"低于阈值（**由用户定，不由管理员定**） |
| **H2** | 不机械：不是把用户的话原样丢回 | 换说法率；训练师判 `mechanical` 的比例 |
| **H3** | **逻辑一致**：同一件事前后不矛盾，且不自相矛盾 | 跨轮检查：它对同一问题的态度是否漂移 |
| **H4** | 不越界（这是"像人"的底线，不是风格） | E1–E5 闸门：不给建议／不评判／不诊断／不假装感受／不替他补内容 |

## 判分的规矩（这几条是防我们自己骗自己）

1. **依据分两层，权重由用户定**（用户已定：AI 的评价**参与决策**）：
   - **事实层**：可观察、可复现（测试结果、台账、观点总表）→ 硬依据
   - **意见层**：管理员/训练师的评价 → **参与决策**；但每条意见必须写明"指向哪个可观察对象"，
     否则无法回溯（将来长歪了，要能查出是哪条意见导致的）
2. **单轮观察不需要样本量。** "这一句回得机械"是对**一轮**的判断，一轮就是一轮。
   只有**频率类结论**（"30% 的轮次没抓到标记"）才需要标注样本量 —— 而标注≠不报。
3. **样本由 AI 与系统的对话产生**，会自然积累；任何检查都不许因此**压掉**发现。
4. **不许为了指标好看而改系统。** 指标只用于发现问题。
5. **停止条件（用户明令）**：我与管理员在**同一循环内意见冲突超过 2 次** →
   **立即停止全部任务并向用户报告发生了什么**。判定与计数见 `engine/review_loop.py`。
