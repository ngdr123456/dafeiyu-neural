# 删除批量提案批准入口

用户授权按最终目标选择改进或删除（D-028）。执行者选择删除桌面管理员栏的“批准全部提案”和“全部驳回”，并删除其回调 `Studio.on_decide_all`。

依据是实际接线：旧回调只调用 `admin.log_decision`，写授权流水、历史结案记录并追加待办；Trainer、Pipeline及两个规则学习器不读取这些批准状态来改变下一轮。它没有完成改进的执行与验收，批量批准也无法表达每条建议的不同对象、证据和实施条件。将它接成任意自然语言提案自动改代码，超出了目前已有的有界规则学习机制，不能以此冒充最终目标中的自主发展。

保留管理员观察、评价、改进建议、重审及历史记录。建议区明确写“尚待实施与验收”，并说明历史批准只是授权，不是生效证明。原有行为回退学习、命题关系学习、验证与淘汰机制照常运行；没有改训练方程、门控、三书边界或学习阈值。

删除范围限桌面批量提案登记入口。待批申请中的查阅授权与报案授权仍保留，因为它们实际控制相应权限；历史决策接口及旧网页面板的逐条决定兼容路径也保留，不扩展成自动执行器。原决定、任务和训练记录没有删除。

32个测试脚本在门控开、关两环境共64次通过，6项变异检查捕获违例。实际稳定exe在隔离副本检查两个按钮缺席、“重审”仍在；模拟API、禁止网络的按钮训练完成6轮并恢复开始按钮。源更新与启动验收通过。真实35个state文件在验证期间未变，本轮未调用真实API、未追加真实训练。

验证记录：`删除批量批准验证_20261006.json`、`点击开始训练验收_20261006.json`、`桌面启动器验收_20261006.json`。

用户关闭当前训练台后重新打开根目录 `启动训练台.exe` 即加载新版，无需重打包。没有擅自终止正在打开的用户窗口。

当前删除的是误导性的批量登记入口；管理员建议到有证据、可执行、经验证改进的完整自动链仍未建成，不能将本次UI整理记作学习能力提升或心理阶段发展。用户首批的原文忠实度与话题连续性问题仍保留在复核报告，后续继续处理。
