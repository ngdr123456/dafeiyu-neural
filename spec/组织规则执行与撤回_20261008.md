# 组织规则从报告进入执行

承接 D-020、D-022、D-029、D-030、D-031，用户本轮允许执行者继续操作。本轮推进 M2 的有界规则发布断点，不是另立发展理论，也不是认定前两批机械回应已找到结构原因。

## 回望及原书对应

此前 `organisation_refinement.py` 已能从旧条件碰撞中形成引用归属分支，并检查后来材料、旧能力及整份反证，但始终只在报告中产生候选。生产 Pipeline 仍使用旧条件习惯。这导致“记录了变化”与“变化支配执行”没有接上。

重新核对《自我的发展》p71、p73、p76–77：结构由部分间联系及其法则规定；当前反应不足时需要调整联系法则；新组织须整合有用旧材料，增加联结或语言分类不能单独称为发展。p76 对结构获得条件的讨论有限，不能把下列字段和次数说成书中的算法。

DB 关于期待与实际结果的讨论保留为后续主体目标的依据。本轮只记录“规则算出的角色”和“声明来源的评审角色”是否相符，不将其称为生理奖赏、多巴胺变化或主观体验。M 的态度自由及原有伦理闸门继续约束运行，不用“让人继续说”作奖赏；创造途径和整体意义对象仍待实现。

## 实际接通的变化

新增 `engine/organisation_runtime.py`，只解释一个有边界的算子：在既有条件中，根据禁止／否定提示词是否属于一个已结束的引用选择命题角色。算子和观察特征由工程设计，两个分支的角色取自有出处的反馈；没有写死“提示词被引用就必然是用户肯定”。

1. 从已有失配及一致分支反馈形成候选，保存守卫条件、旧映射、原文、形成时点和不可改写的程序指纹。
2. 形成材料与后来验证分开，原文重放和更换题号不算新材料。现有每分支 3 条形成、2 条后来验证是局部工程门槛，不能给阶段背书。
3. 启用前重新核对来源哈希、逐字位置及引号所有权。旧记录缺原文时保留历史候选，不靠模型补写，也不自动迁移为启用版本。
4. 规则版本、角色反馈、结构证据及启用／撤回事件同次原子保存。保存失败一起恢复内存；严格训练继续识别学习降级并中断。
5. `RelationLearning.predict` 解释通过验证的版本。`RelationBridge` 将结果接入当前轮判断：只有全部出现位置都确认非肯定、且当前 API 未肯定该标记，才可压下旧标记。新规则不能增添肯定标记、越过感知门控或改变 R1/R2/R3。
6. 当前反馈反驳整份候选时，在当前轮撤回。冻结分支及失败保留；撤回的条件返回未知，不复活原来的错误合并。其他条件使用当前学习器，不从冻结快照复活已经退出的映射。
7. 运行留痕记录确实执行的 `RESOLVE_PROPOSITION_ROLE`、程序版本、原文指纹、位置和计算结果；反馈另存一致／不一致。这是程序操作的观察，不替自由生成回复猜测语义动作。

旧 `derive` 报告仍返回冻结的研究候选，原 `enabled_in_pipeline=False` 描述该候选对象本身，不是新运行版本的状态。执行者须读取同一记忆中的 `organisation_runtime.versions/events` 及本轮 `execution`，核对是否实际提交并使用；不能单看任一候选字段或显示计数推断执行发生。

以前的单值规则被有界条件分支替代，属于本次局部规则修改；候选的冻结分支不随后来反馈偷改。撤回后若需提出不同法则，仍须新版本和新证据。本算子尚不支持任意新特征或新原则的开放生成，不能说已经实现完整自主重组。
