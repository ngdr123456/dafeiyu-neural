# 桌面软件对齐与后续更新

已更新项目根目录的 `启动训练台.exe`。同名旧程序保留在 `build/studio/archive/启动训练台_旧版_20261006.exe`，原来标明作废的另一个 exe 未改动。没有启动正式训练，也没有改真实状态文件。

## 现在如何使用

双击项目根目录 `启动训练台.exe`。程序包含 Python 和 tkinter 运行环境，加载同目录 `engine/` 的界面与引擎源码；不需要额外安装 Python 来启动这个 exe。它需要与 engine、rules、corpus、spec、state 保持在完整项目目录中，不是可以单独复制走的独立应用。

常规代码、关系规则、显示适配和任务清单更新后，关闭软件，再打开同一个 exe 就会读到更新。不在训练过程中热替换已加载代码，避免一段训练混用多个版本。

## 此次界面对齐

- 发展显示优先读 `state/devlevel_verified.json`。旧显示文件只是投影时，可信文件缺失或损坏会报读取失败，不能偷偷显示旧升级结果。
- 在原有发展状态文本下显示规则记忆的候选、固化和退出数量，明确“学习规则不计作阶段升级”。同时读普通对话与训练目录的记忆；没有真实规则时显示尚无经历规则，不用测试样本填充数字。
- 统一读已有记忆的 `rules`、`events`、`kind` 字段。以后新增遵循这个结构的规则记忆，可自动进入显示，名称未知时显示文件名，不必每增加一种记忆就改界面分支。
- 保持原有控件与刷新时机。没有增加控件、定时器、焦点监听或改动训练操作；已有暂停、继续、评审等交互仍由现行源码提供。

显示适配集中在 `engine/studio_status.py`，只读文件，不构造 Pipeline、不训练、不更新发展状态。坏掉的记忆明确标读取失败／格式错误，不能伪装为0。

## 为什么以后少重打包

旧 exe 内嵌了界面和引擎，项目源码更新可能仍运行旧版本。新 exe 只打包稳定启动器与所需标准库，**不打包项目引擎源码**。`studio_bootstrap.py` 明确设置项目根路径，直接编译项目 engine 的当前源码，绕过旧字节码缓存；必需源码缺失时明确报错，不暗中运行旧代码。

`tools/build_studio.py` 可复现构建过程，并从现有引擎源码收集所需标准库。今后普通源码变更和数据更新不重打包；新增当前 exe 未包含的第三方依赖、换 Python/tkinter 运行环境、修改稳定启动器时仍需重新构建。这是实际维护边界，不承诺永远零修改。

## 已验收的事实

`tools/verify_studio_runtime.py` 在临时完整副本验证了真实打包 exe：

1. 检查包内没有 training_studio、pipeline、relation_learning 的冻结副本。
2. 加载最新 UI、Pipeline、关系学习与适配模块，报告实际路径和 SHA256。
3. 创建隐藏的实际 tkinter 界面并读取状态文本，没有按训练按钮。此检查验证窗口构建和读数，不冒称进行了完整视觉审美验收。
4. 修改副本中的 relation_bridge 源码，再运行同一个 exe，精确读到变化后的 SHA256，且新增标记变量确实从执行后的模块读出，无需重打包。使用 exe 默认目录定位，未依赖命令行指定项目根。
5. 删除必需源码，exe 明确返回缺失错误，不挂起等待不可见的对话框，也不降回内嵌旧界面。

真实 state 的36个文件哈希和清单均未变。正式训练/API未启动。29个回归脚本在两个感知门控环境共58次通过，5项原有变异均捕获；后续显示容错及分行调整另做状态适配、旧面板与打包程序验收复查。
