## 一、五大病灶 → 五处修复

### 病灶 1：状态生命周期断层（`boldness` 冻结在上一场）

**他的铁证：`train.py:585` 的 `_regrow()` 只在 36 轮全跑完后调一次；
`pipeline.py:515` 每轮读的是旧 `character.json`；而 `shell.py` 真人交互里**根本没有 `_regrow()`**。**

**⇒ 修：新增 `Character.settle_encounter()` + `Pipeline._settle_previous_encounter()`，
**单轮内当场结算并落盘**。**

```python
# character.py
BOLD_GAIN_CONFIRMED = 0.03
BOLD_GAIN_REBUFFED = -0.06      # ← 受挫权重是确认的两倍（故意的）

def settle_encounter(self, encounter):
    delta = ...                  # +0.03 / -0.06
    self.polarity.boldness = max(0.0, min(1.0, self.polarity.boldness + delta))
    self._last_encounter = encounter
    self.save()                  # ← 当场落盘
```

### 病灶 2：时序倒置（未感知先裁决）

**他的算法：36 轮里 `当轮算子 10 + 空档回想 26 = 36` ⇒ `_idle_gated` **生效 0 次**。**
**根因：`ruminate()` 在 `turn()` 一进门就跑，而那时 `raw_t` 的 claims **还没抽**。**

**⇒ 修（五段式的 Stage 1→2→3）：**


**测试 S1/S2 把顺序钉死（`extract` < `settle` < `arbitrate`）。**

### 病灶 3：控制流旁路脑裂（`modulate` 在大脑模式下被 100% 架空）

**他的铁证：模板 `ren.output` 在大脑模式下被丢弃，
而 `Frame.stance` 调 `stance_for(mst.phase)` —— **只读原始相位，完全不看 `bid`**。**

**⇒ 修：**
```python
# pipeline：把裁决后的 bid + char_note 挂到实例
self._final_bid = bid
self._char_note = char_note

# _build_frame：传给 stance_for
stance_for(_phase, ..., final_bid=self._final_bid, char_note=self._char_note)

# stance.py：性格层踩刹车 ⇒ 覆盖相位姿态
if char_note and final_bid in _CONVERGED:
    return "【性格收敛（%s）】这一轮不要追问、不要翻旧账…" % char_note
```

**★★ 而我第一版写错了（F6 抓到）：**
```
只判 `final_bid in _CONVERGED` ⇒ 而 `REFLECT` 是**阶梯的默认兜底**，
不是"性格踩刹车" ⇒ **每一轮**都变成「性格收敛」。
⇒ 必须判 **`char_note` 非空**（= 性格层真的介入了）。
```
**测试 S6/S7 分别钉住"该覆盖"和"不该覆盖"。**

### 病灶 4：工作记忆多头竞争（四个注意力框并列轰炸）

**他的铁证：没有当轮算子的 26 轮里**轮轮塞 idle** ⇒ 淹没 `unfinished_focus`
⇒ 自我连续性从 6/36 跌到 3/36。**

**⇒ 修：`_arbitrate_focus()` 短路求值**
```
P1 input      ：有当轮 Thought ⇒ 胜出，**不耗 seen_pairs**
P2 unfinished ：有悬念且没碰壁 ⇒ 胜出，**不耗 seen_pairs**
P3 idle       ：① 无 P1 ② 无 P2 ③ 上一轮不是 REBUFFED
                ④ boldness ≥ 0.42 ⑤ 上一轮没刚抛过（冷却一轮）
                ⇒ **全部成立才调 ruminate()**
P4 lexical    ：都没有 ⇒ 才用词级锚点
```
**测试 S4 把 P3 的七个组成钉住。**

### 病灶 5：无界累加器顶死饱和

**他的数学：`clamp(0.5 + 0.08*(C-R), 0, 1)` 先算总账再截断
⇒ 36 轮 `C=9,R=1` ⇒ 未截断 1.14 ⇒ 截到 1.00，**泡沫 0.14 堆在天花板之上**

## 三、★ 我要如实说的三件事

### ① 12 轮验证的样本量不足

**他要求"跑 12 轮或 36 轮，报三类焦点的触发次数 vs STRONG/WEAK 落地次数"。
12 轮里只有 3 次当轮算子 + 1 次 idle ⇒ 分不出三个焦点各自的落地率。**

**⇒ 要看漏斗是否真的在工作，**必须跑 36 轮**。这一条我还没跑。**

### ② 病灶 4 的第 3 点（观测盲区）我只做了一半

**他说：`action_observation.observe()` 只接收当轮 `Thought.quotes`，
没有接收 `unfinished_focus` 和 `idle_thought` 的引文 ⇒ 后两者的落地率是盲区。**

**⇒ 我加了 `_focus_origin` 记录来源，**但没有**把 idle/unfinished 的 quotes 传给 `observe()`。**

**原因：`observe()` 的 `thought_quotes` 语义是"这条思考引用的两段原话"，
而 `unfinished_focus` / `idle` 各自有自己的两段 —— 直接替换会让 `thought_level`
把"她引了 idle 的话"算成"她执行了当轮 Thought"。**

**▶ 正确做法应该是 `observe()` 接收**多个来源**并分别记 level，
那是 `action_observation.py` 的接口扩展，我没有自己定。**

### ③ 病灶 1 我只修了"单轮结算"，没修"`shell.py` 没有 `_regrow()`"

**他说：真人交互时 `Association` 和 `Character` 永远不会更新。**

**⇒ `boldness` 现在每轮结算了，但 `Association.derive_from_ledger()`（那个算
`confirmed/rebuffed` 总量的批处理）仍然只在 `train.py` 里调。**

**⇒ 而 `boldness` 已经不再依赖它（改成逐步增量了）⇒ 影响有限。
但 `_last_encounter` 与里程碑仍然要跑 `learn()` 才会更新。**

**▶ 这一条需要决定：`shell.py` 里要不要每轮（或每 N 轮）跑一次 `derive_from_ledger`？
那是重活（要遍历整个台账），不该每轮跑。我倾向"每 N 轮或退出时"，
但那是产品决策。**
