# M2 第一段：让原话之间的关系实际参与下一轮

承接 D-020、D-021、D-022、D-029、D-030 和最终行动方案。用户本轮授权继续自主解决问题，仅极高风险决定再询问。本记录是执行结果，不是新的用户理论裁定。

## 原书到代码的对应

回读《自我的发展》p71–77：结构涉及部分之间的关系法则；内部平衡、选择与整合不能被累积联结数量替代。p73 的失配与适应指向组织调整，p77 强调新原则及有用材料的整合。p76 对发展条件的讨论有限，p80 又提醒一般认知原则不足以给出人格的特殊组织。

因此，本轮先建立可改变的关系对象，供后续规则作用。`engine/relational_memory.py` 是工程设计的组织基础，不能把它的接入叫作系统自己长出了新原则。DB 数值仍是代理，M 的伦理、意义边界保持，创造途径仍未实现。

## 已接通的过程

1. API 理解层在原有结构化请求中附带抽取关系，不增加日常轮次的 API 请求数。初始关系词表为保管人、已说要联系的人、具体位置；对象、值、时间及证据必须来自连续原字。每轮最多八条，未知和不合法结果不能成为肯定事实。
2. 台账增加 `proposition_reading`，含原话哈希、抽取来源、言说关系及字面拒绝项。旧台账缺该字段时仍能读；不批量补写历史。
3. 从有效台账按输入来源、训练批次和场次重建关系。以对象、关系和时间为键，明确更正留下 `corrects` / `superseded_by` 联系，旧话不删除。普通矛盾不被最后一句覆盖；撤销更正后重放能重新显示旧冲突。
4. 选中关系及其来源进入真实 Pipeline 的大脑简报，同时进入内容复核。长对话挤掉原话检索窗口时，关系来源仍可在需要时进入简报。无关话题不携带整张关系表。
5. 新版本评价为 7；旧版本训练评价不改写。现有 exe 读取最新外部源码，无需重新打包。

“input_author”只是本输入来源的叙述者位置，并未独立核实真人身份。图中“reported”只指原话被如此陈述，不确认外部世界真假。“现在”也是当时原话的时间措辞。相近名称不自动成为同一个对象；代词、隐含更正和任意关系仍可能抽取不到。这些是下一轮表示学习与语义复核的材料，不隐藏为已解决。

否定、禁止、引用和未知保存在来源节点，但不进入肯定关系的当前值。此处的保守检查不是不可修改的心理定律；今后的候选规则可以发展，必须带出处和反例，并继续保护言说归属。

## 本轮发现并处理的反例

第一次实际诊断期待系统在只更正保管人后，自动改变联系计划。复查确认这是诊断材料混淆了关系。保留 `关系组织真实诊断_20261008_问题复述失败.json`，补上“保管人更正不能改写联系计划”的检查，改用明确更正联系人计划的材料；不把旧失败改成通过。

同时修正空关系表的解释：没有结构化抽取不等于没有原话依据；大脑及复核仍须查原话。原话已有明确答案时，只重复问题不能视作接住问题。字面校验失败继续阻断，新增具体校验错误代码用于排查，没有放宽闸门。

首次完整 API 对照通过后，又发现关闭关系层的回答把有限检索遗漏说成“从未记录过”。保留该通过原件，完善限定并重验：检索片段不能证明完整台账中从未出现。关系简报最多选择四组，每组最多十二条来源节点；更正引用最多显示八项并保留总数、截断标志。原始台账不裁剪，重放可以重新选取；十条针对性测试包含百条旧陈述被更正后的上下文边界。

回归暴露性格文件及经历读取未及时关闭，已使用有界句柄读取；性格保存改用已有的原子写入，沿用 Windows 短暂共享冲突的有限重试。

## 下一段主线

继续 M2：把真实失配作用于“支配关系的规则”，而不止改一个联系人值。冻结旧规则与失败原因，建立有边界的规则解释器及候选版本，让经历能提出、修改、拒绝或退出候选。将形成材料与后来验证分开；同时检查未参与形成的场景、旧能力保留、重启及关闭规则的对照。反例要撤回整份受影响候选，重新拟合必须生成新版本。

随后连接系统自身的目标、计划、实际动作、期待和观察结果；只有这条链有可核对对象，才能讨论奖赏代理与组织变化如何相连。暂不降低阶段阈值，也不把工程表的增量当发展。

行动重排已经识别本轮关系基础验收。基线、实际内容和反例仍优先；基础验收有效时下一工作细化为 `STRUCTURE_RULE_LEARNING`，不跳到 M3。任何源码变化令旧验收失效，任何新失败可以把顺序退回修复阶段。
