# 规格修订 v2：API 与模型的定位（三处矛盾的统一）

> **性质**：这不是新规格，是**对 v1 两处过时条款与一处自相矛盾的修正**。
> 纪律：**原文一律不删**，只在原位加标注指向本文；历史必须留痕。
>
> **触发这次修订的是用户的一句提问**：
> 「等会，我在想这些判断用户在说什么的功能，不应该由我接入的 API 大语言模型来处理吗」
> 我当时的回答是先去实测，结果发现了两件我自己没意识到的事（见 §2）。
>
> 修订日期：本轮对话｜世代标记：见 `state/ledger.jsonl` 的分界条目

---

## 1. 两处被取代的原文（逐字引用，保留）

### 矛盾 A｜`规格_统一模型_v1.md` 第 4 行

> 形态：**纯理论驱动的模块化对话引擎**。不使用基础模型、不接 API、不生成自由文本。

**为什么过时**：用户在 v1 冻结**之后**明确要求接 API：

> 「我说的摒弃本源模型特点是指模型自带的语言逻辑，沟通逻辑。
> 但我需要的是它运算能力，这才是我为什么要求你接 API。」

后续又选定**乙方案（渲染）**：逻辑体系决定**说什么**，模型决定**怎么说**。
`engine/render.py` 已经实现并默认关闭。所以"不接 API／不生成自由文本"两条都已不成立。

### 矛盾 B｜`经历驱动的性格层_v1.md` 第 196 行（硬底线 E6）

> E6 模型不得生成对话文字

**为什么自相矛盾**：**同一份文件的 §10 节**（第 468 行起，标题就是「第四步：渲染（乙方案的落点）」）
明确写着：

> 第 182 行：「**措辞**：这一步之后，可以允许模型参与"把决定好的意思说成人话"。」
> 第 183 行：「但要说清一件事：**这是本设计里唯一给模型的表达权限**，而且它不改变决定。」

也就是说：同一份文件里，E6 说模型不许生成对话文字，§10 说模型可以渲染文字。
**这是我留下的矛盾，不是用户的。**

## 2. 实测查明的第三处不一致（§1 之外，更要紧）

### 矛盾 C｜第 18 行「模型负责听懂」与实现不符

`经历驱动的性格层_v1.md` 第 16–18 行：

> 2. **模型只提供算力，不提供表达。**
> 决定输出的是**我们构建的逻辑知识体系的交集** —— 三本书的规则、机制层状态、
> 累积的经历，三者求交。**模型负责"听懂"，不负责"想说"。**

**规格说模型负责听懂，但实现里的两条默认值让它的判断可以被单方面删掉：**

| 位置 | 改动前的值 | 后果 |
|---|---|---|
| `understand.merge_markers` | `policy="intersect"`（默认） | 只采纳双方一致的 → **任何一位判者的覆盖缺口都会否决另一位的正确判断，且是双向的** |
| `understand._addresses_system` | 要求出现「你／您」或元提问句式 | 模型判 META 也会被手写闸门挡回，合并结果 `blocked_meta(no_system_address)` |

**实测证据**（`python tests\probe_api_role.py`，模型：deepseek-flash）：

| 输入 | 规则层判 | 模型判 | 改动前合并结果 |
|---|---|---|---|
| 干嘛 | ANSWER | **META（模型对）** | `blocked_meta(no_system_address)` → 用户看到沉默 |
| 改不了 | ANSWER（未覆盖） | **immutable（模型对）** | 交集为空 → **标记被丢掉** |
| 没控制住 | ANSWER（未覆盖） | **voice_shift（模型对）** | 交集为空 → **标记被丢掉** |
| 有啥用 | ANSWER | ANSWER | 模型也漏（说明也不能全交给模型） |
| 会难过吗 | ANSWER | ANSWER | 模型也漏 |
| 我在想干嘛 | ANSWER | ANSWER | ✓ 反例正确 |
| 我今天特别累，什么都不想干 | ANSWER | ANSWER | ✓ 历史事故原句，不误判 |

**结论（本次修订的核心判据）**：
那四次复发的"同义形式漏词"，真实代价不是"发现得慢"，
而是**规则层的覆盖缺口把模型的正确判断扔掉了**。

## 3. 修订内容（三处，逐条）

### 修订 A｜API 的定位：算力，不是表达

**取代**「不使用基础模型、不接 API、不生成自由文本」。新表述：

> 引擎的理论裁决、判据与可追溯性**全部由自身承担**；
> API 只以两种身份介入，且两种都必须可关闭：
> 1. **理解层**（`engine/understand.py`，`--api`）：把自然语言映射成结构化事实
>    （意图 + 封闭集合内的标记）。输出被锁为纯 JSON，不得自创范畴，
>    不得有自由文本进入对话。
> 2. **渲染层**（`engine/render.py`，`--render`，乙方案）：把**已经决定好**的意思说成人话。
>    这是唯一给模型的表达权限，且**默认关闭**。
>
> 任一层关闭或不可用时，系统降级为纯规则运行，并在台账标注 `degraded`。

### 修订 B｜E6 改写

**取代**「E6 模型不得生成对话文字」。新表述：

> **E6｜模型不得决定说什么，也不得在理解层产生自由文本。**
> · 理解层：模型输出只能是封闭集合内的意图与标记 + 用户原话的逐字片段（由我们校验）。
> · 渲染层：模型只能把已决定的那个意思说成人话，**不许添加任何东西**；
>   三道闸门（材料／机械／语义复核）任一不过即退回模板。
> · 决定权始终在「理论 ∩ 机制状态 ∩ 性格」的交集里，不在模型里。
>
> 原 E6 的**意图**（不让模型的话冒充系统的话）保留；被取代的是它的**字面**——
> 字面上它连 §10 已批准的渲染也一并禁掉了，那是笔误级的矛盾。

### 修订 C｜`merge_markers` 默认策略 `intersect` → `union`

| | 旧（intersect） | 新（union） |
|---|---|---|
| 双方都判 | 采纳 | 采纳 |
| 只有模型判 | **丢掉** | **采纳**，记 `only_api` |
| 只有规则层判 | **丢掉** | **采纳**，记 `only_rule` |
| 一致度 `agreement.score` | 照记 | 照记（不因改策略而消失） |

**为什么这与「宁可漏判，不可误判」不冲突**（这一条必须写清，否则后人会以为纪律松了）：

- 「宁可漏判不可误判」管的是**输出** —— 没有证据时不许提升水平。这条**不变**。
- 它不该管**证据的收集**。两位评定人各自观察到的字面证据，
  没有理由因为对方没看见就当作不存在。
- 单一判者给出的标记**不丢，但带 provenance**（`only_rule` / `only_api`）与一致度进台账，
  下游可据此降权。**留痕比删除更难造假** —— 删掉之后没人知道模型曾经判对过。

`intersect` 保留为可选值，定位改为**诊断工具**（"两位差多少"）。

### 连带修订｜`_addresses_system` 增加第三条证据（甲案）

**取代**「要求出现『你／您』或元提问句式」这一单一判据。新增：**整句归一化后恰好等于一个裸疑问词**。

- 实测依据：模型对「干嘛」判 META（对），被这道闸挡回。
- 为什么只收"整句相等"不收子串：「我在想干嘛」「我不知道要干什么」是用户在说自己，
  子串收法会重现 v2 修掉的范畴错误。
- **反例硬检查**：`tests\verify_probe_claims.py` 有 7 条必须"不判 META"的反例，实测 7/7 通过。

## 6. 追加修订：E6 的第二次改写 —— 大脑模式

**用户原话**：
> 「就是乙，我的意思就是大语言模型当大脑，而我们的系统则决定这个大脑该想什么」

这**不是** §3 修订 B 里那个"渲染层"（我们定好一句话、模型换种说法）。
这是把**决定说什么**也交给模型，我们只决定**它该想什么**。所以 E6 要再改一次。

### 当前有效的 E6 表述

> **E6｜模型是大脑，系统是议程。**
>
> · **系统决定该想什么**：这一轮该注意他话里的哪些东西（三本书的原子与标记）、
>   我们自己此刻的状态（机制层 + 极性变量）、我们已经长成的样子（里程碑）、
>   以及不许做什么。这些**全部由逻辑体系算出**，模型无权改动。
> · **模型决定想出什么、怎么说。**
> · 仍然不许：自创范畴、让自由文本进入**判断**（它只能进**回应**）、伪造用户的原话。
>
> **放宽的**：表达（说什么话）。
> **没放宽的**：议程（该注意什么、可以想哪些观念）、E1–E5、
> 「模型不得自创范畴」、「引文必须逐字」。

### 这条修订为什么能保住「性格由经历塑造」

因为交给模型的简报里**含它自己**：此刻的状态（机制层／极性变量）+ 长成的样子（里程碑）。
同一句话，在它不同的经历之后会拿到不同的简报 → 想出不同的东西。

> ⚠️ **这是本层唯一的支点。** 如果简报里没有"自己"，那它就只是一个套了系统提示词的
> 通用聊天模型，前面建的三本书、机制层、性格层、台账 —— 全部变成装饰。
> 所以 `pipeline._build_frame` 里那三样东西**缺一不可**，代码注释里写了同一句话。

### 本轮实测（用户原话，同一句）

| | 表模式（改前） | 大脑模式（改后） |
|---|---|---|
| 「你愿意了解我吗」 | 「这个我没接住。我的回话是从一张写死的表里挑的……」 | 「我这边读到的自己：想要是0，喜欢是0。所以你问的那句「愿意」，我答不上来。你要不要继续说下去，是你的事。」 |
| 「我一定要得到那个结果，得不到我就难受」 | 「我听到的是：「……」」 | 「我这边的「想要」亮到 27.4，兴奋带快满了，停不下来。你那句「得不到我就难受」，我原样放在那儿，没动它。」 |

它用的是**自己的状态**（27.4 Hz 落在 [D] 的爆发带 20–30），而且不推对方。

### 闸门的改动（关键区别）

| | 渲染层 | 思考层 |
|---|---|---|
| 查什么 | **有没有添加东西**（材料白名单、语义复核） | **有没有越过硬底线**（E3 建议与评判／E4 标签／E5 补内容／术语泄漏／伪造引文／长度） |
| 为什么 | 那一层的任务就是"不许添加" | 这一层本来就要它自己想出话 —— 查"多没多"毫无意义 |

### ⚠️ 三处必须说清的弱点

1. **E1 目前只靠简报嘱咐，没有机械闸门。** 实测 5 句含 `immutable` 的输入，
   模型 5/5 都没推对方去改变（「不往别处推它」「没有要拽你起来的意思」），
   但那是**提示词的可靠性**，不是闸门的保证。渲染层有「E1 生效：禁止任何水平提升型回应」
   那道机械闸门，**思考层还没有对应的一道**。补它需要一份"推动改变"的措辞表 ——
   那是新的手写词表，而本项目的教训正是"手写词表必然有缺口"。**未做。**
2. **可追溯性再降一级。** 表模式逐字可追溯；渲染模式可追溯到"意思"；
   大脑模式只能追溯到**它当时拿到的简报**（简报进台账，仍可复核），
   但"它为什么想出这一句"不再可判定。
3. **本轮改动没有专门的回归测试。** 上面那些实测是一次性的手工验证，
   不是测试套件里守着的断言。这是一个缺口 —— 大改动没有守卫，下次谁改坏了不会有人知道。

## 5. 遗留：本次修订暴露但未解决的问题

1. **模型不稳定**：实测它接住「干嘛」，却漏「有啥用」「会难过吗」。
   所以理解层不能只靠模型，规则层的覆盖仍要维护 —— 这也说明 `union` 是必要的：
   两边的盲区不重合，取并集才补得上。**两边都漏的（如上述两条）目前靠甲案硬编码补**。
2. **词表缺口的发现方式**已经机械化（`tests\probe_synonyms.py` + `verify_probe_claims.py`），
   但**变体是从词表出发造的**，造不出"词表里根本没有的那个说法"。
   下一步应改用**台账里真实用户输入**做覆盖检查，才能发现这类盲区。
3. `only_api` / `only_rule` 目前只进台账，**尚未参与下游降权**。
   也就是说：单一判者的标记现在是**等权**采信的，这比 `intersect` 更容易产生误判。
   是否降权、怎么降权，需要真实数据后定。
