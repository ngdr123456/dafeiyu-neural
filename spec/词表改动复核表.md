## 改动 1：`immutable` 标记补上"少一个句尾了"的写法

- **文件**：`rules\markers.json` → `immutable.patterns`
- **加了**：`改不了`、`回不去`、`不可能`、`没有办法`、`别提`
- **为什么算补完枚举**：这张表**自己**已经同时收了「改变不了」和「改变不了了」两种写法，
  却没有给「改不了了／回不去了／不可能了／没有办法了／别提了」配不带『了』的那一半。
- **实测证据（成对比较）**：

  | 输入 | 改前 | 改后 |
  |---|---|---|
  | 改不了了 | immutable → TURN_IMMUTABLE | 同左 |
  | 改不了 | **无标记 → SILENCE（整条行为丢失）** | immutable → TURN_IMMUTABLE（与左一致） |
  | 回不去了 | immutable → TURN_IMMUTABLE | 同左 |
  | 回不去 | **无标记 → ACKNOWLEDGE** | immutable → TURN_IMMUTABLE（与左一致） |

- **用户会受到的伤害**：少打一个字，就从「这件事已经发生。那么，从今天往后，你还握在手里的是什么？」
  掉成「（本轮不作回应，仅记录。）」—— 同一句话，一个字之差，一个回应一个沉默。
- **怎么自查**：把 `rules\markers.json` 里 `改不了`、`回不去` 删掉再跑
  `verify_probe_claims.py`，那两对会重新分叉。

## 改动 2：`voice_shift` 的被动侧补上 `让我` 族

- **文件**：`rules\markers.json` → `voice_shift.sub_patterns.passive.examples`
- **加了**：`让我`、`使我`、`没办法控制`、`不受我控制`、`它自己`、`它又来了`
  （主动侧加了 `我做的`）
- **为什么算补完枚举**：被动侧**本来就有**「它让我」。「让我」是同一个构造去掉主语。
- **实测证据**：「我不由自主」→ 命中 `voice_shift`；「让我很难受」→ 改前**无标记**，改后命中。
- **附带查出的结构缺陷**：这 7 条原本写在顶层 `patterns` 里，却不在任何 `sub_patterns` 里。
  判定顺序是「`patterns` 过粗判 → `sub_patterns` 定方向与证据」，
  所以它们**永远只能过门、不能作证据**，命中后 passive/active 皆空 → 直接 `return None`。
  这类"写了等于没写"比单纯漏词更坏：**加词的人会以为已经修好了**。
- **怎么自查**：删掉 passive 里的 `让我`，第 10 对会重新分叉。

## 改动 3：引擎 —— 门控候选扩成 `patterns ∪ sub_patterns.examples`

- **文件**：`engine\markers.py` → `MarkerEngine._detect`
- **改了什么**：算 `raw_hits` 时把 `sub_patterns` 里的例子一并当门控候选。
- **为什么必须改引擎而不是改词表**：改动 2 之后我发现，光往 `sub_patterns.passive` 里加
  「控制不住」「没控制住」**仍然不生效** —— 因为门控只看顶层 `patterns`。
  也就是说：**只要这个结构缺陷在，任何往 sub_patterns 里加的条目都是白加。**
  在词表里绕过它（把同一条在 patterns 里再抄一遍）等于把缺陷固化。
- **实测证据**：`控制不了` → `voice_shift`；`没控制住` → 改词表后仍无标记 → 改引擎后命中。
- **影响范围**：`sub_patterns` 目前只有 `voice_shift` 一个标记在用，
  `markers.py` 里也只有 voice_shift 分支读它 —— 改动不外溢。
- **怎么自查**：把 `gate` 换回 `patterns`，「没控制住」立刻掉回无标记；三套测试仍应全绿
  （22 + 37 + 集成），所以测试**抓不到**这个缺陷，只有成对比较能。

## 我**没有**动的一条（此条已由你决定：选甲，见上面改动 4）

### 裸疑问词：`干嘛` / `有啥用` / `咋答` / `做什么` / `会难过吗`

- **现象**：这些是"对着系统说"的话，但用户不写「你」。系统一律沉默，有时还反过来复述问句
  （「会难过吗」→「我听到的是：『会难过吗』。」—— 被问了却把问题念回去，等于没听见）。
- **根因**：`understand._addresses_system` 要求出现「你／您」或明确元提问句式。
  **这道闸是修范畴错误时立的**：当时「我今天特别累，什么都不想干」被当成在问系统，
  系统回了它一句「这句话我没接到题上」。
- **你选的处理**：甲（整句精确匹配）。已实现并已验证反例 7/7。

## 改动 6：极性变量重定（**你定："状态"的含义由我裁定**）

- **文件**：`engine\character.py`（`Polarity` 全部字段换掉、升 `_schema`=2）、
  `engine\shell.py`（两栏分开显示）、`spec\经历驱动的性格层_v1.md`（原位标注作废）
- **裁定**：**极性变量的名字必须能被一个机制量直接兑现；兑现不了的撤下，不许硬凑。**
- **为什么不是"改分母"** —— 这是关键。病根不在公式，在**名字**：
  `openness`（愿不愿意接话）／`directness`（说话直不直）／`warmth`（愿不愿意承认）
  是**我编出来的倾向，背后没有任何测量**；`interest` 的分子分母都是**他的**行为；
  `patience` 实算的是"话题平均多久被调度挪一次"。**没有量可读，就只能拿累积计数去凑，
  于是必然撒谎。** 改分母只会让谎撒得更精致。
- **改动内容**：

  | 新名 | 读哪个量 | 公式 | 出处 |

  | `wanting` 想要 | `w`（Hz） | (w−4.0)/(30.0−4.0) | [D] 静止带 3–5／爆发带 20–30 |
  | `liking` 喜欢 | `l` | l | [D] 想要≠喜欢 |
  | `patience` 耐重复 | `a`（敏化增益） | 1 − a/4.0 | [D] 失望累积成敏化 |
  | `structure` 结构压力 | `e` | min(1, abs(e)/0.60) | [E] 平衡化 |
  | `tension` 张力 | `tension` | tension/10 | [M] 张力趋零是病态 |

  旧的累积占比**没删**，搬到「行为分布（累积，非状态）」栏并标注它会漂移。
- **实测验证**（`tests\audit_polarity.py`，重写后审两件事并排看）：

  | | 幅度 | 轨迹 |
  |---|---|---|
  | 想要 | 0.900 | 可涨可落 |

  | 张力 | 0.818 | 可涨可落 |

  我第一版判据用"幅度 > 0.05"一刀切，会把它算进"确实在测状态"——那是**放宽结论**。
  改成两档后如实说：**能变但这批数据几乎没触发，只能说它在结构上不是常量，

### 为什么这不是空转（做之前先证）

扰动法实测 58 轮机制快照（`audit_behavior_sensitivity.py`）：行为选择对
`w`／`a`／`e` **完全不敏感**，对 `l` 93%、`tension` 29% 敏感。
所以 `patience←a`、`structure←e`、`wanting←w` 携带的是行为选择**现在忽略**的信息。
**若五个极性变量全部落在敏感字段上，"让行为读极性变量"就只是同一个数换刻度 —— 那就该停手。**

### 三条规则（每条只让动作更保守一档）

| 规则 | 触发 | 依据 |
|---|---|---|
| R1 耐心 | `patience < 0.35` 且本轮动作与上一轮相同 | [D] 敏化：同一动作反复做，效果递减 |
| R2 结构压力 | `structure ≥ 1.0` → 撤下断言型动作 | [E] 平衡化：重组期间不得假装已知道方向 |
| R3 里程碑 | 该动作的里程碑是"多半就停在那儿" | 跨会话经验（本层唯一真正跨会话的信息） |

### 三条结构性护栏与验证结果

| 护栏 | 验证 | 结果 |
|---|---|---|
| 只能更保守，绝不更主动 | 穷举 9 动作 × 极性网格 × 有无 immutable = **2304 组合** | **没有一次向左移动** |
| E1 不被绕过 | 同上，`immutable` 在场时结果须在 E1 允许集内 | 全部在集内 |
| 不用 `wanting`（讨好路径） | `wanting` 取 0.0 与 1.0 对比 | 裁决完全相同 |

端到端 **K1–K4**：证明管线**真的会调用** `modulate`，不是函数写对了却没接线。

### 过程中被验证抓出来的三个错（都是我自己的）

1. **`CONSERVATISM` 顺序排错** → R2（"不许下断言"）会把并排呈现降成
   **`TURN_IMMUTABLE`**，而它本身就在断言集里 —— 规则自己打自己。
   改：按"替对方定了多少东西"重排，并让 `ASSERTIVE` 成为序的**前缀**。
2. **验证脚本判据过严**：动作未被修改时我也要求它在 E1 允许集内，
   一次报出 **584 例假越界**。那种情况 E1 由下游「禁止提升」闸门负责。
   改：只检查"改动过"的结果。**检查器过严和过松一样糟 —— 它会淹没真问题。**
3. **R2 阈值是拍的**（`structure > 0.80`）→ 改成机制层自己声明的线
   （`abs(e) ≥ error_high`）。触发这个发现的是 K2 的失败：我本想用 character.json
   注入 `structure=0.95`，结果管线每轮用机制快照把极性刷回真实值 —— 这是对的，
   而它顺带证明**这个阈值根本达不到**。

### ⚠️ 必须跟着说的一句话

**三条规则在这批数据里都没触发过。** 机制层实测 `patience` 0.910–1.000（R1 需 <0.35）、
`structure` 0.017–0.682（R2 需 ≥1.00），唯一里程碑是复合式（R3 需 stop-主导）。

所以只能说**已接好、且不会误伤**，**不能说已在真实对话中起作用**。
我**没有**为了点亮它们而下调阈值 —— 那正是本模块一整轮在修的错
（已发现四例：`NOTHING_MORE`、`sub_patterns` 死条目、散文反例、R2 旧阈值）。

### 诚实代价

这一步之后，行为不再完全由"当下观察 + 机制状态"决定，还受**累积经历**影响：
**同一个输入在不同历史下可能得到不同回应。** 那正是"它有了过去"的含义，
也是可追溯性的一次下降 —— 每一处介入都进台账（`character_note` + notes），
所以仍能回答"这一轮为什么这样回"。

## 改动 8：修「像机器人」—— 一处坏词表引发的连锁（**你截图报的**）

**症状**：用户实测截图，三轮里两轮渲染被打回模板，输出全是生硬的「我听到的是：…」；
直接问「你在和我说话吗」得到沉默。

**根因（查台账 + 重放才找到，不是猜的）**：**一处坏词表同时污染了两层。**

`blame_external`（markers.json）与 `blame_hedge`（atoms.py）的触发词里都有
**`我认为`、`我估计`**。这两个词是**书里的举例**（p56「比如『我认为』或『我估计』」），
被当成触发词抄进了词表。后果是连锁的：

> 你说「我认为可以」→ 命中 `blame_external`（误判）+ `blame_hedge`
> → 材料里多出「那些不由你负主要责任的地方，你也责备自己」
> → 渲染时模型照着材料把它写进回复
> → 引文闸门／语义复核判"添加了用户没说过的意思" → **整句打回生硬模板**

**修法分两种（因为两张表的性质不同）**：

| 表 | 为什么不能一刀切 | 修法 |
|---|---|---|
| `markers.json` 的 `blame_external` | 「我认为」根本**不是外指的判据**，是抄错了 | **直接删**「我认为」「我估计」 |
| `atoms.py` 的 `blame_hedge` | **有原书出处**（p56 直接用了这两个词），且语料有明确期望 `我估计也有我的问题吧` → 应命中 | **加共现约束**：光有「我认为」不够，还得同句有自责语境（也／可能／也许／问题／错／责任…） |

共现约束是新机制 `Lexicon.requires_any`（与 triggers 同下标，空列表＝不约束），
由 `compose.recognize` 执行，**只作用于 triggers，anchors 不受影响**。

**实测结果**：

| 句 | 改前 | 改后 |
|---|---|---|
| 一个人可以同时是好的和坏的吗？我认为可以 | 命中 `blame_external`+`blame_hedge` → 渲染被打回 | 只剩 `opposed_pair` → **渲染通过** |
| 我估计也有我的问题吧。 | 命中 `blame_hedge` | **仍命中**（语料期望保住） |
| 我认为他不对 | 命中 `blame_hedge` | 不命中 |

### 同时修的两处（你批准的乙、丙）

- **乙｜拒因不再只记「未过」**：把 `Speech.violations` 的逐条明细写进台账。
  实测教训：台账只写"机械闸门未过"，我为了知道拦在哪一条，只能**重新调一次 API 重放**，
  而重放还未必复现（同输入模型措辞不同）。诊断能力不该靠运气。
- **丙｜台账行为与输出必须一致**：问「你在和我说话吗」时元提问库没命中，输出换成了
  沉默模板，**但台账仍写 `behavior=META_REPLY`** —— 台账说"我回应了"，用户看到的是沉默。
  改成按实际结果记（`META_REPLY` / `SILENCE`）。

### 戊｜窄兜底（你选的方案）

新增 `ASKED_ME_SOMETHING_I_LACK`：三条**同时**成立才触发 ——
① 前面条目全没命中 ② 有第二人称「你／您」 ③ 是疑问句。

**与被删掉的 v1 GENERIC 的区别**：GENERIC 把**识别失败**伪装成一次回应，让人分不出系统懂没懂；
这里只在**意图明确指向系统、只是词表没覆盖**时才开口，而且回话本身承认"我没接住"。

边界实测（都正确）：`你听得见吗`→兜底｜`我今天特别累`→ANSWER（范畴错误没回来）｜
`你说得对`→ANSWER（陈述不兜）｜`你在干嘛`→仍走 WHAT_NOW（不抢已有条目）。

### ★ 顺带发现、**尚未修**的一个新问题

「一个人可以同时是好的和坏的吗？我认为可以」这一轮的本质是**并排**——
把两件事放一起给你看。模板版是对的（「两句话放在一起：… / …」），
但**渲染版把它压成了一句**：「一个人可以同时是好的和坏的吗。」——**并排的意思丢了**。

原因：`stance` 映射里没有 `JUXTAPOSE`，它落到默认的 `observe_only`，
所以没人要求渲染版"必须把两边都摆出来"。三道闸门只管"有没有多加东西"，
**不管"有没有把该说的意思说丢"**。这是个真实缺口，未修。
