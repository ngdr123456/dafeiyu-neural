## 一、跨场累积设计（D-011）

### 1.1 问题

```
现状：Trainer._pipe() 每次新建 Pipeline → 新建 Mechanism
      ⇒ e / streak / prev / _tension 全部从 0 起步
      ⇒ **上一场结束时"还没解决的那点张力"整场蒸发**
```

实证依据（`tools/重放对账.py`）：254 轮真实对话由 **82 个会话**组成，
训练台账 33 个里 **22 个 ≤ 2 轮**，会话台账 49 个里 **38 个只有 1 轮**。
**会话极短 ⇒ 单场内 e 根本爬不起来**（4 轮最坏 0.293）。

### 1.2 设计：只 carry 一个量 —— **未解张力**

```
【不做】carry `e` 本身
        理由：e 是"本场结构受压"的即时读数，跨场携带会让它失去时间含义
【做】  carry 张力 —— 会话结束时若处于「未解」态，把它持久化并在下场衰减注入
```

**什么叫「未解」**：沿用机制层已有的 `unfinished` 信号（`mechanism.py` 的
"有待完成的任务"），**不新造判据**。

### 1.3 落盘格式（新增文件）

```
state/mechanism_carry.json
{
  "_note": "上一场未解的张力，跨会话携带。衰减后注入下一场。",
  "tension":        3.42,          ← 会话结束时的张力
  "unfinished":     true,          ← 机制层给的"未解"标志
  "at":             "2026-10-02T20:11:03+08:00",
  "schema":         1
}
```

**⚠️ 与 `devlevel.json` 分开两个文件** —— 一个是**发展水平**（只升不降），
一个是**张力**（会衰减）。混在一起会让"只升不降"那条不变量失效。

### 1.4 衰减注入

```
注入（会话开始）：
    carried = read_carry()
    if carried:
        dt_h   = 现在 - carried.at        （真实经过时间，不是轮数）
        decay  = 0.5 ** (dt_h / HALF_LIFE_H)
        tension_0 = carried.tension * decay
    else:
        tension_0 = 0.0

写回（会话结束）：
    if unfinished:  write_carry(tension=当前张力, at=现在)
    else:           clear_carry()      ← 解决了就清掉
```

**为什么按**真实时间**衰减而不是轮数**：会话之间隔的是小时/天，不是轮。
按轮衰减会把"隔了一周"和"隔了五分钟"算成一样。

**`HALF_LIFE_H` 是 ENG 常数，必须标注来源并列入校准**（初值提议 24.0，
**待真实数据校准，本方案不预设它是对的**）。

### 1.5 与 `e` 的关系

**张力不是 `e` 的输入**（现状也不是 —— `e` 只看 change/rigidity）。
张力只经 `devlevel.update()` 的 **A5 判据**（`fail_tension > TENSION_DRIVE`）参与。
所以跨场累积**不改 `e` 的公式**，只让"失效那一刻的张力"在下场还可能足够大。

**⚠️ 但这条有一个必须写明的后果**：跨场累积**单独不能救活生长链** ——
因为入口判断 `e >= ERROR_HIGH` 仍然过不去（e 每场从 0 起步）。
**它必须与第二节的公式重构一起上，才有意义。**

## 二、方案 B：e 的加权公式重构（D-012）

### 2.1 现状为什么卡在 0.5

```
change  ∈ {0, 1}
rigidity = min(1.0, streak/12)
x = (change + rigidity) / 2                    ← 当前
```

**致命处在于两者互斥**：`change = 1`（翻转）时 `streak` 被**清零** ⇒ `rigidity = 0`。
于是 `x` 只能落在 `[0, 0.5]`，**`0.5 ~ 1.0` 那一段永远是空的**。

**⇒ 根因不是"两个信号各压一半"，而是"两个信号不可能同时强"。**

### 2.2 重构：独立通道 + 噪声或（noisy-OR）

```
c = change                       ∈ {0, 1}
r = min(1.0, streak / STREAK_FULL)   ∈ [0, 1]     （STREAK_FULL 现状 12，ENG）

x = 1 - (1 - c) · (1 - r)        ← **noisy-OR：任一信号强，压力就强**
e = γ·e + (1 - γ)·x              （γ = error_memory，现状 0.75）
```

**为什么用 noisy-OR 而不是 `max(c, r)`**：

| 形式 | x 的值域 | c=1,r=1 能否同时 | 语义 |
|---|---|---|---|
| 现状 `(c+r)/2` | [0, 0.5] | **不能**（互斥） | 两者取平均，浪费一半 |
| `max(c, r)` | [0, 1] | 能（但取最大，丢弃另一个的信息） | 只看更强的那个 |
| **`1-(1-c)(1-r)`** | **[0, 1]** | 能 | **两条独立通路，任一通即受压** |

**语义上 noisy-OR 更贴合原设计意图**：注释原文说
「通道越是长期不变（**或**越是频繁翻转），平衡化压力越大」——
**那个"或"字，`max` 和均值都表达不了，noisy-OR 才是它的正确形式。**

### 2.3 ★ 上界证明（本方案的核心要求：达到 1.0）

**命题**：`e_n ∈ [0, 1]` 对一切 n 成立；且 `sup e_n = 1.0`。

**证明（归纳）**：

```
基础：e_0 = 0 ∈ [0, 1]                                    ✓

归纳：设 e_{n-1} ∈ [0, 1]。
      ① c ∈ {0,1} ⊆ [0,1]，r = min(1, streak/S) ∈ [0,1]
      ② x = 1 - (1-c)(1-r)
         ∵ (1-c) ∈ [0,1]，(1-r) ∈ [0,1] ⇒ 乘积 ∈ [0,1]
         ⇒ x = 1 - 乘积 ∈ [0, 1]                          ✓
      ③ e_n = γ·e_{n-1} + (1-γ)·x，其中 γ + (1-γ) = 1
         ⇒ e_n 是 e_{n-1} 与 x 的**凸组合**
         ⇒ e_n ∈ [0, 1]                                   ∎

上确界可达性：取 c 恒为 1（每轮翻转）⇒ x 恒为 1
             ⇒ e_n = γ·e_{n-1} + (1-γ) = 1 - γ^n
             ⇒ sup e_n = lim (1 - 0.75^n) = **1.0**       ∎
```

**⚠️ 一个必须写明的技术细节**：EMA **只逼近不达到** 1.0
（`0.75^n > 0` 恒成立）。所以：

```
**阈值必须严格小于 1.0** —— 设在 1.0 上仍然是不可达的
（这正是现状 ERROR_HIGH = 0.60 > 上界 0.50 那个错的另一种形态：
  把阈值设在值域的端点或端点之外）
```

**本方案建议把"阈值必须 < 上确界"写成一条不变量测试**（见第四节）。

### 2.4 新旧值域对照（供校准取值）

```
                            现状        方案 B
x 的值域                  [0, 0.50]   [0, 1.00]
e 的上确界                  0.50        1.00
每轮翻转时 e 的收敛        →0.50       →1.00
会话长度 4 轮时最坏 e       0.293       0.586
会话长度 5 轮时最坏 e       0.345       0.691
触发 0.60 需要连续翻转      不可能      约 4 轮（1-0.75⁴ = 0.684）
```

**⇒ 方案 B 之后，短会话（4~5 轮）也能越过 0.60。**
这是"按真实会话长度算"的关键改善 —— 会话极短这个现实不必先被改掉。

## 三、联动处理：三处副本 + 两个不可达分支

### 3.1 三处字面值 → 单一来源

**现状（审计已列）**：

```
【1】engine/mechanism.py    error_high: float = 0.60      ← 原始声明（MechanismConfig）
【2】engine/devlevel.py     ERROR_HIGH = 0.60             ← **抄的字面值**
【3】engine/character.py    "error_high": 0.60            ← **又一份硬编码字典**
（error_low 同理，两处）
```

**三个候选，本期须定一个：**

| 方案 | 做法 | 代价 |
|---|---|---|
| **(甲) 直连导入** | `devlevel.py` 改成 `from mechanism import MechanismConfig`，取其字段 | 与 `consensus.py` 的 `DEV_UNIT_IDS` 同法；但 `character.py` 那份也要改 |
| **(乙) 立 constants 模块** | 新建 `engine/constants.py`，三处都从那里取 | 彻底断掉"谁抄谁"；新增一个模块 |
| **(丙) 导入期断言** | 保留字面值，但加 `assert ERROR_HIGH == MechanismConfig().error_high` | 改动最小；抄错会当场炸；**但三份仍然并存** |

**我倾向 (乙)** —— 因为这次要同时改 4 个常数（error_high / error_low /
STREAK_FULL / HALF_LIFE_H），**只有单一来源才不会再漏**。
（此为建议，**请你裁**。）

**并且无论选哪个，都要加一条源码扫描测试**：三处的值必须相等
（`tests/test_threshold_sources.py` 已有 S1~S4，扩展即可）。

### 3.2 两个不可达分支的同步治理

```
【gate_open】  mechanism.py 的 abs(e) < error_high
   现状：恒真（门从不关）
   方案 B 后：e 能超过 error_high ⇒ **门会真的关上** ⇒ 本分支复活 ✓
   验收：重放里报「门关闭的轮次占比」

【R2 结构压力】 character.py 的 structure = min(1.0, e / error_high)，阈值 >= 1.0
   现状：structure 最大 0.833（数学）/ 0.682（实测）
   方案 B 后：e ∈ [0,1]、error_high < 1 ⇒ structure = e/error_high **能到 1.0** ✓
   ⚠️ **前提是 error_high < 1.0** —— 若把 error_high 定成 1.0，R2 仍然死
   ⇒ 这条要写进校准的取值约束
```

**⇒ 两个分支的复活条件都是「`error_high` 严格小于 `e` 的上确界」** ——
**与 E3 的不变式是同一条。三件事共用一个约束。**

## 四、验收基准：E3 由 XFAIL 翻转为 PASS

### 4.1 E3 现在为什么是 xfail

```python
# tests/test_e_upper_bound.py :: E3
不变式：ERROR_HIGH < e 的上界
现状：  0.60  <  0.50   → **不成立** → raise _Xfail(...)
```

### 4.2 翻转条件（一条，不含糊）

```
方案 B 落地后：e 的上界 = 1.00
               ERROR_HIGH 取任何 < 1.00 的值（校准定）
               ⇒ 不变式成立 ⇒ **E3 自动转为 PASS**
```

**⚠️ 不需要改 E3 的代码** —— 它本来就是按不变式写的（这正是上一轮把它从
"写死 0.60"改成不变式的价值：**路线定了它自己会转正**）。

### 4.3 配套要加的验收（配合 E3）

| 项 | 判据 |
|---|---|
| **E1 扩展** | 现有 E1 验"上界 0.5" → 改成**从源码取上界表达式**，验方案 B 的 noisy-OR 形式上界为 1.0（仍不重实现公式） |
| **E5（新）** | **阈值不变量**：`error_high` / `error_low` / `structure` 阈值 / `TENSION_DRIVE` **每一项都严格小于其变量的上确界** —— 这条把"把阈值设在端点"这类错误一次性挡住 |
| **R1（新）** | **重放复兴验**：用 254 轮真实台账重放，报（失效次数 / 平衡化次数 / not_grown 次数 / 折合升几级），**训练与会话台账分开、demo 单列** |
| **E3 转正** | 断言从 xfail 变 PASS，且 `_Xfail` 不再被触发 |

### 4.4 校准取值（本方案定**方法**，不定数值）

```
要定的四个常数：error_high｜error_low｜STREAK_FULL｜HALF_LIFE_H
方法：
  ① 用 R1 重放跑出 |e| 的**新分布**（方案 B 公式下）
  ② error_high 取该分布的一个高分位（并**强制 < 上确界**，由 E5 挡）
  ③ error_low   取低分位，且 **< error_high**
  ④ STREAK_FULL 用 stable_streak 的真实分布定（审计遗留项）
  ⑤ HALF_LIFE_H 用会话间真实时间间隔分布定（跨场累积的衰减速率）
**⚠️ 数值由真实数据定，本方案不预设。**
```

## 五、执行顺序（批准后）

```
第 1 步  单一来源落地（三处副本合一）        —— 先立地基，否则后面改一处漏两处
第 2 步  E5 阈值不变量测试（先写，后改）      —— 让"把阈值设在端点"当场炸

第 4 步  E1 扩展 + E3 转正（预期自动发生）
第 5 步  跨场累积（carry.json + 衰减注入）    —— 依赖第 1 步的 constants

```

**⚠️ 每一步都要 mutation 验证**（本项目已靠这条抓到 2 个覆盖缺口）。

## 六、风险与不可逆点

| # | 风险 | 应对 |
|---|---|---|
| 1 | **跨场累积让"只升不降"失效** | carry 放**另一个文件**，与 `devlevel.json` 分开 |

| 6 | 真实会话极短（49 个里 38 个 1 轮） | 方案 B 已把 4 轮的最坏 e 从 0.293 抬到 0.586；**但 1 轮会话仍不足以触发** —— 这条要如实记入"能触发多少比例"的预期 |

## 七、本方案不做的事

```
· 不动 ERROR_HIGH 的**数值**（数值留给第 7 步的校准）
· 不改机制层的其他常数（tension_scale、DOPAMINE_TAU 等）
· 不改性格层、L4、L5 的任何逻辑（只动 R2 依赖的阈值来源）
· 不碰界面
· 不在本方案里定阈值 —— 先有公式，后有分布，再有数值
```
