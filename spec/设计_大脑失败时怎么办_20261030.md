# 设计：大脑失败时怎么办（2026-10-30，**只出设计，未写代码**）

> **依据**：用户「三件事」第 2 条 —— 只出设计、先不写代码
> **背景数据**：36 轮里 **3 轮**大脑路径失败（8.3%），且**三次原因各不相同**

---

## 一、先看现在发生了什么（实测）

| 轮 | 失败类型 | 台账原文 | 退到哪 |
|---|---|---|---|
| 2 | `content_review_failed:ValueError` | 内容校验抛了个 ValueError（**未知错误**） | REFLECT 模板「你刚才说的是：…」 |
| 31 | `REJECT`（校验打回） | 大脑说"你说的'上次失败'我没记录过" —— **全局否定** | ASK_DETAIL 模板「发生什么了？」 |
| 36 | `think_failed:HTTPError` | 网络/接口错误 | ASK_DETAIL 模板「发生什么了？」 |

**⇒ 三种失败，**同一个出口**，而那个出口是最差的一种：**

```
「发生什么了？」= 一句**没有对象的探问**。
它的问题不是"不好听"，是**它假装自己接住了** ——
用户刚说了一句很重的话，她回"发生什么了？"，
等于说"我没在听，但你再说一遍"。
```

**★★ 而更糟的是：它还会被 `observe()` 标成 `ASK_DETAIL` / `QUESTION`，
进入统计、进入 BOLD 判定 —— **一次接口故障被记成了一次探照**。**

---

## 二、四层设计（按失败类型分层，不按"重试 N 次"糊在一起）

### 第 0 层：把失败**分类**，这是全部设计的前提

现在三种失败混成一个字符串塞进 `notes`。**先要把它们分成三类**：

```
A 类：**可重试的过程错误** —— HTTPError / 超时 / 5xx
     特征：与内容无关，重试大概率能过
     ⇒ 对策：**退避重试**（见第 1 层）

B 类：**有意见的拒收** —— content_review 的 REJECT
     特征：模型说了不该说的，**校验意见本身就是可用的信息**
     ⇒ 对策：**带着意见重试一次**（见第 2 层）

C 类：**我们自己代码的异常** —— ValueError / KeyError 之类
     特征：不是模型的问题，是系统的问题
     ⇒ 对策：**不重试**（重试只是把同一个 bug 再跑一遍），
             直接退到第 3 层，并且**要留痕到显眼处**（这不是"模型今天不稳"，是 bug）
```

**★ 我特别要强调 C 类**：轮 2 的 `content_review_failed:ValueError`
被当成"内容校验没通过"处理了，**但 ValueError 是异常，不是"不合格"**。
**⇒ 它暴露的是内容校验模块自己的 bug，而不是模型说了错话。**
**⇒ 这一类**重试没有意义**，且**必须报警而不是降级**。**

---

### 第 1 层：A 类（网络/超时）—— 退避重试

```
第 1 次失败 → 等 0.8s → 重试
第 2 次失败 → 等 2.0s → 重试
第 3 次失败 → **不再重试**，退到第 3 层

约束：
· **总耗时上限 8 秒**（否则一次网络抖动会让用户等 30 秒）
· 只对 A 类重试，B/C 类**不重试**
· 每次重试都记一条日志（`retry_no` / `wait_ms` / `error_type`）
  ⇒ 否则"重试了几次"永远查不到（这正是我上一轮查不出来的那类盲区）
```

**⚠️ 一个必须先想清的取舍：**
```
在 train.py 的 36 轮里，重试是**免费**的（没人等）。
在 shell.py 里，重试是**有感知延迟**的（真人在等）。
⇒ 两者应该用**不同的上限**：离线 8 秒、在线 3 秒。
   这个分叉必须显式写出来，不能共用一个常量。
```

---

### 第 2 层：B 类（校验打回）—— 带意见重试**一次**

```
第 1 次被打回 → **把校验意见原文附回去**，重试**一次**
第 2 次仍被打回 → 不再重试，退到第 3 层

为什么只重试一次：
· 校验意见是"你违反了哪条"，不是"你应该说什么" ——
  模型收到意见后**大概率能改对**，但如果它两次都改不对，
  说明它**根本没理解那条纪律**，第三次也不会。
· 且每一次重试都是一次完整的生成（成本 ×2），
  36 轮里 3 次失败 ⇒ 最多多 3 次生成，可接受。
```

**★★ 而这一层有个隐藏的好处，我要说明：**
```
轮 31 那次打回的意见是：
  「候选直接断言不存在"上次失败"且自己没说过那样的话，
    但 memory_scope 表明仅有有限片段、record_absence_verified=false，
    不能据此作全局否定；应说无法确认，而不是断言事实不存在。」

**这条意见本身就是一句很好的教学。**
带着它重试，模型有很大概率改成「我不确定我有没有说过那个」——
那正是我们要的**「不知道就说不知道」**。
⇒ 换句话说：**校验打回不只是"拦住"，它可以是"教一次"。**
```

---

### 第 3 层：全部失败时的出口 —— **最轻、不追问**

**这是最重要的一层。现在的出口（「发生什么了？」）要换掉。**

**★ 设计原则（按"她此刻能诚实说什么"排序）：**

```
候选 1（默认）：**承认这一句她接不住**，但不追问、不推介
   「……我听着。这个我一下接不住，你别急着往下说。」
   特征：短、不快、不给压力、**不提问**

候选 2（若他刚说了很重的事）：**只承重**
   「嗯。」
   特征：最短。`SILENCE` / `ACKNOWLEDGE_CLOSE` 档

候选 3（若他刚问了她一个问题）：**承认答不上来**（而不是反问他）
   「这个我真答不上来。」
   特征：直接对应"她答不了"，不把问题丢回去
```

**★★ 三条都必须满足一个硬条件：`output` 里不含「？」。**

**⇒ 这一条要**用代码保证**，不是靠提示词：**
```python
# 出口处断言：兜底输出的最后一档**必须不含问号**
# 违反了就是 bug，测试要能抓到
```

**★★★ 而这里有一个我必须指出的连带影响：**
```
一旦兜底不提问，那么"这一轮"就不会被 `observe()` 标成 QUESTION/ASK_DETAIL
⇒ **大脑失败率会从"动作统计"里分离出来**，不再污染 BOLD 判定。
这正好是用户要的「boldness 不作为行为依据」的前提之一。
```

---

### 第 4 层：把「大脑失败率」做成必报指标

**用户明确要求：「把大脑失败率列为每次实测必报的指标」。**

**★ 定义要写死，否则每次口径不同就没法比：**
```
大脑失败率 = 该批实测里 `mode != "brain"` 的轮数 / 总轮数

并且**按原因分列**（这是关键，只报一个总数没用）：
  A 网络/超时
  B 校验打回（附最常被打回的那条纪律）
  C 系统异常（附异常类型）
```

**★ 而且要报**分母**：一次实测跑了多少轮。**
**⇒ 3/36 = 8.3% 和 3/12 = 25% 是完全不同的两件事。**

**★★ 我还建议加一个数：`重试后成功的比例`。**
```
若重试后 100% 成功 ⇒ 说明失败是瞬时的，系统其实是健康的
若重试后仍然失败 ⇒ 说明是系统性的（可能是提示词或校验规则本身的问题）
⇒ 这两个结论指向**完全不同的修法**，只看失败率分不出来。
```

## 三、这套设计**没有**解决的事（我要先说清）

```
① 它不解决"内容校验本身有 bug"（轮 2 的 ValueError）
   ⇒ 那要单独查 `content_fidelity.py` / `review_loop.py`。
     我只是把它从"降级"改成"报警"，**没有修它**。

② 它不解决"退到兜底的那一轮，她的经历就断了一节"
   ⇒ 兜底输出也是她说过的话，也会进台账、也会被算进 BOLD/CONFIRMED。
     **要不要把兜底轮排除在遭遇结算之外，是一个产品判断，我不自己定。**

③ 它不解决"8.3% 的失败率是否可以接受"
   ⇒ 我只报数，不定阈值。
```

---

## 四、实施顺序（若批准）

```
第 1 步（最小、最安全）：把失败**分类**并落盘（A/B/C + 重试记录）
   —— 这一步不改任何行为，只是让"失败"这件事第一次**可观测**
第 2 步：A 类退避重试（离线/在线两套上限）
第 3 步：B 类带意见重试一次
第 4 步：换掉兜底出口（三条候选 + 「不含问号」的硬断言）
第 5 步：把失败率接进实测报告的固定字段
```

**★ 我建议第 1 步单独做、单独验** ——
因为现在连"失败了几次、什么原因"都只存在于 `notes` 的一句自由文本里，
**在它变成结构化数据之前，后面四步都是在猜。**
