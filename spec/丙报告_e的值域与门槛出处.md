## 一、`e` 是怎么算的

`engine/mechanism.py` 第 2 层（误差层），核心是**三行**：

```python
change = 0.0 if channel == self._channel_prev else 1.0     # 通道这一轮翻转了吗
self._stable_streak = self._stable_streak + 1 if change == 0.0 else 0
rigidity = min(1.0, self._stable_streak / 12.0)            # 12 轮不动 = 完全僵化
e = 0.75 * self.e + 0.25 * (change + rigidity) / 2.0       # ← 一阶 EMA
```

**设计意图**（代码注释原文）：

> 「系统的预期是什么？这里取一个**纯自指**的预期：下一轮仍是同一通道。
> 它不需要任何外部标准，且能被台账直接验证。
> e 的含义：**结构被压迫的程度** —— 通道越是长期不变（或越是频繁翻转），平衡化压力越大。
> 这样 e 不需要跟任何外部标准比较，也就不用标定常数。」

### 三个特性

| 问 | 答 |
|---|---|
| **怎么算** | 通道翻转（0/1）与结构僵化（streak/12，封顶 1.0）取平均 → 一阶 EMA 平滑 |
| **是否平滑** | **是**。一阶 EMA，记忆系数 `error_memory = 0.75` |
| **上下界** | **`e ∈ [0, 0.5]`** ← **上界不是 1.0，是 0.5**，理由见下 |

## 二、★ 上界为什么是 0.5（不是 1.0）

**单轮输入项 `(change + rigidity) / 2` 的上界恒为 0.5：**

```
不变更通道（change=0）：输入 = rigidity / 2 ≤ 1.0 / 2 = **0.5**
   （rigidity 封顶 1.0，要 streak ≥ 12；核验：streak=12 → rigidity=1.00 → 输入 0.500）
翻转通道（change=1）：streak 被**立刻清零** → rigidity = 0
   → 输入 = (1 + 0) / 2 = **0.5**
```

**关键在第二行**：翻转会把 `stable_streak` 清零，所以 `change=1` 和 `rigidity>0`
**永远不会同时出现**。`(change + rigidity)/2` 的取值只有两端——
不翻转时随 rigidity 从 0 爬到 0.5，翻转时直接是 0.5。**中间那 0.5~1.0 一段是空的。**

**而 `e` 是从 0 起步的一阶 EMA。EMA 的稳态等于输入，且**不会超过输入的最大值**：**

```
e_n = 0.75·e_{n-1} + 0.25·x_n,   x_n ∈ [0, 0.5]
⇒ e_n ∈ [0, 0.5]   （归纳：e_0 = 0 在区间内；凸组合仍在区间内）
```

**⇒ `|e|` 的数学上界是 0.5，而 `ERROR_HIGH = 0.60` 在它之上。**

## 四、`ERROR_HIGH = 0.60` / `ERROR_LOW = 0.15` 的出处

**`engine/mechanism.py` 第 20 行自己写着口径：**

> 「**每个常数必须标注来源。** `有据` = 原书给了数值或区间；
> **`待标定` = 我挑的工程占位**。」

**这两个常数的标注（第 119-121 行）：**

```python
error_memory: float = 0.75     # 预测误差的记忆系数 γ（ENG，待标定）
error_high: float = 0.60       # |e| 超过 → 平衡化压力"上涨"（ENG，待标定）
error_low: float = 0.15        # |e| 低于 → 结构停滞（ENG，待标定）
```

## 五、结论：不是"罕见"，是**构造上不可能**

```
ERROR_HIGH = 0.60
|e| 的数学上界 = 0.50        ← 差 0.10
310 轮真实数据的最大 |e| = 0.409
```

**⇒ `abs(e) >= ERROR_HIGH` 永远为假。**

**连锁后果（比 `not_grown` 拿不到样本严重得多）：**

```
e 永远够不到 ERROR_HIGH
  ⇒ self.failed 永远不置位（结构永不失效）
    ⇒ equilibration 永远不 +1
      ⇒ 水平永远停在 START_LEVEL = I-3
        ⇒ **"它长到哪了"这个问题永远没有第二个答案**
```

**通电之后，箭头 A5 的整条生长链是死的。** 不只是校准拿不到数据 ——
`dev:TENSION_GROWTH` 这个单元虽然状态标着「已建未启用」，即便通电，
它的**失效→重组分支一次都不会走到**。

**顺带**：`ERROR_LOW = 0.15` 倒是**一直在被满足**（96.1% 的轮次 `|e| ≤ 0.15`），
但因为 `failed` 从不置位，那个 `elif self.failed and e <= ERROR_LOW` 分支同样进不去。

## 六、修改方向（**只列，不改** —— 任何改动单独报批）

我看到三条路，**都涉及机制改动，请用户裁定**：

### (甲) 改门槛，不改公式

把 `ERROR_HIGH` 降到上界以内（如 0.35~0.40）。**代价**：`ERROR_LOW = 0.15` 也得跟着重定
（否则 `high < low` 或区间过窄）；且**门槛一改，`|e|` 的分布仍偏低位**（96% 在 0.15 以下），
能触发失效的轮次会很少。

### (乙) 改公式的输入，不改门槛

`(change + rigidity)/2` 这个均值**把两个信号各压了一半**，是上界 0.5 的直接原因。
候选：
- 去掉 `/2`（上界变 1.0）—— 但那等于把两个信号直接相加，语义变了吗？
- 用 `max(change, rigidity)` 而不是均值（上界仍是 1.0，且"任一信号强即压迫强"更贴合原意）
- `rigidity` 的 12 轮封顶是否过长（真实训练 178 轮里，有多少段连续 12 轮不翻转？**这个要另查**）

### (丙) 先不动，把"生长链永不执行"作为已知事实记档

T33 通电后**明确报告"生长链未激活"**，等有更多真实数据再谈。
**好处**：不在没有数据支撑时动机制。**代价**：T33 通电之后看不到任何"生长"。

### 我的倾向

**先做 (乙) 里那个零 API 的追加调查** —— 查真实台账里 `stable_streak` 的分布，
看 rigidity 到底爬到过多少。**如果 178 轮里 streak 从没超过 6，那 `min(1.0, streak/12)` 的
12 这个数也是拍脑袋的**，问题就不止两个门槛，而是三个常数。

**这一步只读台账、不花 API、不改代码。**
