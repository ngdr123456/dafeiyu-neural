## 二、★★★ 而在这个过程中，我抓到了**四处**让 `boldness` 永远不动的真 bug

**这四处**每一处都足以让整条链路失效**，而且它们串在一起 —— 修前修后都"看起来在跑"。**

### bug 1：`self.ledger_path` 从未赋值

```
`_refresh_milestones` 里用 `self.ledger_path`，但 `__init__` 只用了局部变量 `lp`
⇒ AttributeError ⇒ 被 except 吞成「里程碑刷新失败」× 4
```

### bug 2：差一位（**最隐蔽**）

```python
# 第 t 轮跑到这里时，台账里只有 t-1 条（索引 0..t-2）
self._settle_previous_encounter(t - 1, ...)      # ← t-1 正好 >= len(ents) ⇒ 立即返回
⇒ 结算一次都没发生
```
**修：`_prev_i = len(self.ledger.effective_entries) - 1`**

### bug 3：`polarity_from_mech()` 每轮把 `boldness` 冲回 0.50

```python
# update_state() 每轮都调 polarity_from_mech(mech)，
# 而它 new 一个 Polarity()，boldness 的默认值是 0.50
⇒ settle_encounter() 刚写进去的值，下一步就被覆盖
```
**修：`polarity_from_mech(mech, keep_boldness=现有值)`**

### bug 4：`while` 与 `try` 的缩进（`continue` 落到循环外）

**⇒ 这是我在改 `shell.py` 时自己造成的，用 `py_compile` 才抓到 ——
`ast.parse` **不检查** `continue` 位置（那是编译期检查）。**

**★★ 教训：`syntax_gate` 用 `ast.parse`，它抓不到「`continue` 在循环外」
这类**编译期**错误。以后改控制流必须补 `py_compile`。**

