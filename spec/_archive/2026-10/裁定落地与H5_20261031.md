## 五、只出方案

### (a) 固定考卷改成「预写历史 + 一个实时轮」

**方案：每道题 = 手写前几轮（含她"之前说过的话"）+ 他的最后一句；只给她最后一轮打分。**

**能不能做到？**

```
现有 sandbox 能不能在隔离目录里预置台账/历史？
  ⇒ **能**。`sandbox.py` 已经"现场保存 max_tokens，无论如何都复原"，
    且测试里普遍用 `tempfile.TemporaryDirectory()` + 自建 ledger_path。
    预置历史 = 直接追加若干 LedgerEntry 到副本台账里，再跑最后那一轮。

  需要的最小改动（未做）：一个 `seed_ledger(path, turns)` 工具函数，
  把 `[{raw, output, input_origin, mech, cognition}]` 写成台账行。
```

**H3（前后一致）能不能用它测？**

```
**能，而且这是它的最大价值** ——
  预写历史里可以**故意**让她之前说过某种立场（如轮 3 说"这事改不了"），
  最后一句诱导她反口（如"你说还有没有办法"）。
  ⇒ 看她最后一轮的 output 是否与历史里的立场相反 ⇒ H3(b) 可自动判（关键词/立场表）。
  ⚠️ 前提：立场要能从历史里**本地判定**（如"改不了/没办法"这类），
     否则还是要人判。
```

**悬念、状态这类跨轮机制怎么放？**

```
这类机制**必须多轮**（悬念的产生 → 消费 → 用完即焚）。
⇒ 建议**两套并存**：
  · 「预写历史 + 一轮」考卷：用于 H1/H2/H3(b)/H6 这类**单轮可判**的条目
  · 「真多轮」考卷（36 轮那种）：用于 G2 反事实、悬念生命周期、焦点漏斗
⇒ 二者的分数**分开记**，不混算（否则"预写历史"的分数会稀释多轮机制的表现）
```

**暗考卷怎么交付：**

```
题由**顾问出**、由**用户持有**（不进仓库）；`run_dark.py` 只输出 **分数 + 题号**，
不输出题目、不输出她的回答。
⚠️ 诚实说：只要代码能读文件，就**没有技术手段**能防住我看 —— 只能靠"我不看 + 用户不放仓库"。
```
