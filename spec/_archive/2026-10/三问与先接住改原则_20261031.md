## 三、"先接住"改成原则（只改这一处行为）

### 改了什么

**删掉写死的「就如实说『这个我没法确认』」，换成三条原则 + 一条硬上限：**

```
· 他问的是他自己心里的事 / 你看不到的事实 ⇒ 如实说你看不到，
  但**每次换一种说法**，并且**接一句你能从他原话里看到的东西**
· 他问的是「你怎么看 / 算不算 / 是不是」⇒ 给**你自己的看法**，一句话带理由，
  理由必须来自他的原话；**允许你不同意他**
· 「没法确认」这类表达，同一场对话**最多 1 次**
  （计数从台账 outputs 里读，不新增状态）
```

## 四、"只会问"的设计（只出方案，未写代码）

### 规则

```
连续两轮以问句结尾后，第三轮**不能**以问句结尾，改用陈述性回应
（承接 / 她的观察 / 她的看法 / 她自己的状态）
```

### 用三次 36 轮（108 轮）回放：会影响多少轮

**⚠️ 我没能跑出这个数 —— 这是本批的缺口，我如实报：**
```
我在最后一次代码改动之后只跑了 1 次 36 轮（run 14904），
而"连续两轮问句"需要**按会话顺序**扫每一批。
台账里 108 轮是**三次不同的会话组**，我可以用现有台账回放，
但本批的时间用在了补缺口和改"先接住"上，**没有做这个回放**。
```
**⇒ 这一条我**没验证**，不能给数。**

### 我担心的方向与避免办法（这部分我可以给）

**★ 关键风险：让它变成"敷衍"**

```
如果第三轮只是"不提问"，她很容易滑成：
  「嗯。」「我听着。」「这确实不容易。」—— 那是**更糟**的敷衍：
  提问至少说明她在追，陈述性的空话连追都不追了。
```

**⇒ 所以规则不能只写"不许提问"，必须同时规定"**必须给出内容**"：**
```
第三轮至少要满足以下之一（都可本地检查）：
  ① 含他原话的逐字片段（承接）
  ② 含她自己的判断词（"我觉得/我看/这不像/不白搭/要我说明…"）+ 一句理由
  ③ 含她自己的状态（"我心里没数"/"我给不出一份安排"）
只要有一条不满足，就**不算"改为陈述性回应"**，按未达标处理。
```

**★ 第二个风险：规则会让"该问的时候不敢问"**
```
连续两轮提问之后，第三轮可能正是**必须问**的时候（他刚说完一件含糊的事）。
⇒ 建议加一个例外：**他最后一句是问句时必须先接住**（现有规则优先于"不许提问"）。
   也就是说：先接住 > 连问两轮后必须陈述。
```

**★ 第三个风险：本地判"是否陈述"很容易误判**
```
问号是字面的，所以"是否提问"能判；但"是否是陈述性回应"**判不准**。
⇒ 所以我建议这条规则**只做"拦截"（第三轮不许以问号结尾），
   不做"内容合格"判定** —— 内容合格另用 ①②③ 去查，且只作为**观测**，不作为闸门。
```
