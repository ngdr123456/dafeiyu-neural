## 三、为什么必须做成**序列**（这是本轮最主要的发现）

**先后试过并否掉的方案：**

```
✗ 自足输入（一条里既有断言又有查询）
    实测两个原因都不成立：
    ① relational_memory.project() **故意**把当前输入排除在可引用来源之外
       （sources 过滤掉 current: 前缀）⇒ 当前输入里的断言无法被引用；
    ② 同一句段里既有断言又有查询 ⇒ 断言被判 unsafe ⇒ 降级 UNKNOWN。
       那道语义护栏是**故意的**，不动。
    ⇒ 断言必须先在**历史行**里。

✓ 序列：断言 → 更正 → 查询（3 轮）
```

**顺带修了一个真 bug（`relational_memory.py:76`，off-by-one）：**

```python
# 改前：evidence 常以「。」结尾 ⇒ 从这里往后找会跳过它自己那个「。」
finish = min([p for x in "。！？!?；;\n" if (p := raw.find(x, item["end"])) >= 0] + [len(raw)])
# 改后：从 end-1 开始找
finish = min([p for x in "。！？!?；;\n"
              if (p := raw.find(x, max(0, item["end"] - 1))) >= 0] + [len(raw)])
```

**后果举例（实测）：**

```
clause = '更正：甲项目押金由周老师收着。现在告诉我：甲项目押金由谁收着？'
                                                ↑ 越界捡到「？」
⇒ 整条真断言被判 assertion_requires_review ⇒ UNKNOWN ⇒ 分组没有值 ⇒ 目标不提供
```

## 五、两个必须说清的界限

```
① `QUOTE_SOURCE_SET_CONFIRMED` 证明的是「你确实逐字引用了指定的来源片段」。
   它**不**证明「这样引用是否回答了问题」—— semantic_goal_fit 仍是 UNKNOWN，
   literal_predicate.independent_semantics_verified 仍是 False。

② 序列要求 `session_len >= 3`。
   `train.py` 里那道判断是**故意的**：必须保住「每场恰好 session_len 轮」这个不变量
   （`sessions_added` / `rounds_added` / `target` 都依赖它）。
   第一版没加，3 轮序列把 2 轮的一场撑成 3 轮，计数全错 —— `test_training_interruptions` 抓到了。
   ⇒ 也就是说：**训练台里「每场轮数」要 ≥ 3 才能用上序列。**
```
