## 二、基线对齐（这轮最要紧的活）

### 根因①：`tools/重放对账.py` 退出码 1

```
**不是 bug —— 是它自带的「源码公式对账」守卫在正常工作**：
★ 源码公式变了，本脚本推的不是**代码**的行为，停止：
   ['e = 0.75 * self.e + 0.25 * (change + rigidity) / 2.0',
    'rigidity = min(1.0, self._stable_streak / 12.0)']
T33 换成 noisy-OR 后，它拒绝用旧公式推新代码 ⇒ 红得对。

⚠️ 但"跟上"**不等于把旧公式删掉** —— 台账里已有的 e **全是 v1 算出来的**，
   用 v2 去比必然全错。
⇒ 解法：**按每行的 `e_version` 选公式**
      v1（字段缺失或 ==1）→ 旧公式（**冻结在脚本里**，它已不在源码中）
      v2（==2）           → noisy-OR（**必须仍在源码里** —— 那才是"绑被测对象"）
```

### 根因②：会话数不一致（训练 42 vs 33｜会话 54 vs 49）

**三处口径分歧，逐条对齐：**

| # | 分歧点 | 旧内联实现 | `session_split`（对齐后） |
|---|---|---|---|
| **A** | `channel=None` 的行 | 跳过（且在边界判定**之前**） | **完全不看**（不判边界、不进会话） |
| **B** | 会话里记什么 | 非 META 的 **tid** | 非 META 的**行**（`session_turns`） |
| **C** | 纯 META 会话 | `if x` 过滤 | **切分时保留，出口由 `drop_empty()` 统一丢弃** |

**⇒ 出口过滤（用户裁定要求的"单一显式函数"就是 `drop_empty`）。**

### 结果

```
tools/重放对账.py 的旧内联切分**整段删除** → `sessions = SS.drop_empty(SS.split_sessions(rows))`
两处输出**逐格相同**：
   训练 会话数 33｜dist {1:10, 2:12, 3:3, 4:5, 5:1, 6:1, 8:1}
   会话 会话数 49｜dist {1:38, 2:3, 3:4, 4:2, 9:1, 13:1}
退出码 **1 → 0**
```
