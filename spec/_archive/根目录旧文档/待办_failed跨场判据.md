## 一、缺陷

```python
# devlevel.py::update()
if e >= ERROR_HIGH:                    # 第一半：结构失效
    if not self.failed:
        self.failed = True             # ★ failed 落在 devlevel.json，**跨场保留**
        self.fail_tension = tn
elif self.failed and e <= ERROR_LOW:   # 第二半：重组完成
    ...
    self.equilibration += 1
```

```python
# pipeline.py
self.mech = Mechanism(initial_tension=_t0)   # ★ 每场新建 ⇒ e / streak / prev 从 0
```

**⇒ `failed` 跨场保留，而 `e` 每场清零。**
**⇒ 场 A 置位 `failed` 后，场 B 的**第 1 轮** `e` 必然是一个固定小值**
**⇒ `e ≤ ERROR_LOW(0.15)` **几乎自动成立****

```
新场首轮：prev=None ⇒ change=0 ⇒ streak=1
          rigidity = 1/12
          x = 1-(1-0)(1-1/12) = 1/12
          e = 0.75×0 + 0.25×(1/12) = **0.0208333…**
实测台账记 0.021 ✓
```

**⇒ 「先失效、后重组」这个判据，在场 B **只跑 1 轮**时也成立。**

## 四、三个候选修法（**待用户裁**）

```
(甲) **判据要求场次连续性**
     失败后必须在**同一场**内观察到 e 回落才算重组
     ⇒ 代价：场短的会话永远不算重组（但那是"如实"）

(乙) **e 跨场携带（像 carry 那样）**
     新场不从 0 起，而是继承上一场的 e（可加衰减）
     ⇒ 与 D-011 的 carry 思路一致；但 e 是"本场结构受压"的即时读数，
        跨场携带会让它失去时间含义（D-011 当时讨论过这一点）

(丙) **给"重组"一个独立的判据，不用 e**
     比如：失效后连续 N 轮的 e 方差低于某阈值 ⇒ 新平衡稳定了
     ⇒ 最贴近 [E] 的原意（"重组出了新的**平衡**"，平衡是稳定性，
        不是"数值低"），但要新设计一个量
```

**⚠️ 无论选哪个，都要先想清一件事：**

```
「重组完成」到底该以**什么**为证据？
  现状用的是「e 变低了」 —— 而 e 变低可能是因为
     ① 真的重组了        ② 场重启了        ③ 通道变稳了
  三者当前**无法区分** ⇒ 这是判据的根本问题
```
