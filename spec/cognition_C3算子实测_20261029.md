## 三、根因：**抽取把语义要求丢了**

```
算子 4 的本意（[M]）：
  「他此刻痛苦的事里，哪半截是真的已经发生、无法挽回的事实，
    哪半截是他**误以为改不了、其实还握在自己手里**的选择」

实测抽出的：
  FIXED  = 任何事实陈述（鞋上有泥、水添多了、灯坏了）
  ACTION = 任何动作（挂了电话、开柜子、火我关了）

⇒ **"不可改变"与"他自己的选择"这两个语义要求，在抽取里完全没有约束。**
⇒ 所以算子逻辑没错（测试 T5/T6 证明了），**输入不够。**
```

## 四、另外三个算子为什么是 0 / 2

```
WANT_VS_COST_GAP = 0
  需要 mech.phase == "WANT_NO_LIKE"
  实测：215 行里只有 24 行有 phase，且**值全是 NO_TENSION**
  ⇒ 结构上不可能触发

HABITUATION_LOOP_BREAK = 0
  需要 signature_key 连续重复 ≥3
  实测：**signature_key 在 eval.jsonl 里零行有值**
  ⇒ 结构上不可能触发

CROSS_TURN_CONTRADICTION = 2
  需要同一会话内、同一 subject、本轮 ACTION/COST + 历史 WANT
  实测：session_id 只有 12/215 行有值（6 个真会话）；
        其余 12 段是 ts 间隔近似（**约定，不是事实**）
  ⇒ 能匹配的窗口太小
```

**⇒ 所以这一轮的结论不是"算子设计错"，而是：**

```
五个算子里，两个（2、3）**结构上无法被验证** —— 它们依赖的字段在历史数据里不存在。
一个（1）能验证，但窗口太小（6 个真会话）。
唯一产出量可观的那个（4），**假阳性 80%，因为抽取没约束语义。**
```

## 五、下一步（我建议的三件，都要用户批）

```
① 重写抽取 prompt，收紧 FIXED / ACTION 的语义
   FIXED  只能是：「已经发生且**无法改变**的处境」（人走了／离婚了／合同签了／时间过了）
          排除：当下细节（鞋上有泥）、做菜过程（水添多了）、他的困惑（别的什么没了）
   ACTION 只能是：「**他自己做的、带取舍的选择**」（说了"随便"／忍住没说／删了信／没敢翻）
          排除：时间状语（挂了电话）、身体反应（手抓着桌沿）、日常动作（开柜子）
   ⇒ 要重跑一次抽取（50 分钟 / 430 次调用）

② 补 signature_key 字段（算子 3 的前置）
   ⇒ 这是 Gemini 第一封信就建议的"补记字段"，一直没做
   ⇒ 改 train.py 的 eval 写入，不改行为

③ `hint` 的连接语要分算子写，不能共用一套句式
   现在 38 条里有 36 条用「这一半已经定了／这一半是你自己做的」
   ⇒ 同一句模板用 38 次，一眼就看出是模板
```
