## 一、★★★ 他的"死锁"假设不成立

**他的论证：** `idle_recombine` 要 `dist>=1`，零形回指只放宽到 `dist<=1`，
而 `think()` 先跑把 `dist==1` 全吃进 `seen_pairs` ⇒ 交集为空 ⇒ idle 永远 0。

**我拿刚跑完的 36 轮台账离线重算（0 次 API）：**

```
② idle_recombine 在当时的规则下就能配出 **15 条**
③ think() 只吃过 **4 对**，其中 3 对是 DILEMMA 的 `turn=-1`
   ⇒ **不在 seen_pairs 的作用域里**（-1 不是真实轮次）
⇒ 算法没有死锁，think() 也没把 dist==1 吃光
```

### ★★★ 真因：我把 `ruminate()` 写错了位置

```python
def _describe_last(self):        # ← 这个函数**每轮都会被调用**
    # ★ 惰性推演（Gemini Q7）
    self._idle_thought = None    # ← 每次进来先清空
    if use_cognition:
        self.ruminate()          # ← 再产生一条
    ...
# ⇒ 它一轮里被调不止一次 ⇒ 每次进来先把自己刚产生的 idle 抹掉
# ⇒ 60+ 轮里，idle 一次也到不了 Frame
```

**修法：整块搬到 `turn()` 最开头，顺序改成**先清上一轮的、再让这一轮产生新的**。**

**★ 修好之后第一次实测（2 场 × 6 轮）：**
```

当轮算子：DILEMMA 2｜CROSS_TURN 2｜IMMUTABLE 1｜CHAIN 1
```

### ★★ 我要记下这一条教训

**上一轮我在报告里写"要加埋点才能查清"，而真相是：
**只要拿现成台账离线重算一次（1 秒），就能看到"算法能配 15 条"。**

## 四、★ 我没做他第二条（`seen` 只排已说出口的）

**他的建议：「`seen_pairs` 只收集 `thought_level in (STRONG, WEAK)` 的引文对，
没说出口的留在池子里让下一轮 ruminate 捡起来。」**

**⇒ 没做，理由：**
```
· 它依赖一个前提："没说出口" = "还在肚子里" ——
  但那也可能意味着"她压根没在意那两段"。
· 而 `unfinished_focus` 已经在处理"想到了但没说透"
  （它的触发条件之一就是 `thought_level != STRONG`）。
· 两条路同时做，会让她反复咀嚼同一对原话 —— 那是**反刍**，不是回想。
```

**▶ 若他认为必须做，需要配一个「同一对最多被捡起几次」的上限。**
