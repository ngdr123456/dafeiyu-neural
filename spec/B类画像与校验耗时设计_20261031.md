**★★ 直接回答你的判断：**打回确实集中在 `unfinished`（5/9），而它的纪律是「编造原话 4 + 没接住当前问题 2」。**

**⇒ 你的猜测**成立**：上游「引旧话」与下游「先接住当前问题」在打架。**
**机制是这样：`unfinished` 的 hint 明确要求「**务必带引号逐字点出其中至少一段原话**」，
而校验的纪律之一是「**先回应当前问题，别转回旧事**」。
⇒ 她照着 hint 去引旧话，校验就说她"没接住当前问题 / 偏离 / 未利用已有信息"。**
**★ 换句话说：**我们一边要她引旧话，一边罚她引旧话。****

**⚠️ 但我要补一句：这不是"校验错了"。看样本 4，她确实**没有回答**他问的"哪个先把我拽下去的"。
⇒ 真正的问题是** hint 只说"引出来"，没说"先把他的问题接住，再引"**。**

### 5 条完整样本

**样本 1｜轮 6｜焦点=unfinished｜他问她=否｜替她判定重要／贴标签**
```
【他】我……我就是被你问得有点发毛，不知道怎么接，就随口把话扔回去了呗——
      你老盯着那些小地方问，我反倒觉得自己刚才说的都站不住了。
【她】「算了先别绕这个」——这句我还在想。你说「站不住了」，是哪一问先让你有这感觉的？
【校验】替他判定什么才算重要：出现「放下」
```
**★ 这条校验意见**很可疑**：她的候选里**根本没有「放下」两个字**。**
**⇒ 校验给了一个不在候选里的违规片段，而 `content_fidelity` 有一条校验
`evidence["text"] not in text` 会挡住这种情况 —— 但它挡的是 `evidence` 数组，
这条意见走的是 `violations`（另一条路），**没被挡**。**

**样本 2｜轮 4｜焦点=unfinished｜他问她=否｜编造原话**
```
【他】嗯……好像多半是白天哪件事没弄成，或者哪句话说岔了，灯一关就先想起那个，
      然后就顺着往下想，越想越觉得自己哪儿哪儿都不对。
【她】「哪件事没弄成」和「哪句话说岔了」——两样不太一样的事，晚上都能顺着一条路
      走到「哪儿哪儿都不对」上去。我想知道，是从「那个」跳到「自己不对」，中间还有一段，
      还是直接就到那儿了。
【校验】候选编造了用户前面说过「行了别问我知不知道了」这一原话；该句在当前原话和
        所给历史原话中都没有出现。引用了他没说过的话：「自己不对」
```
**★ 这条**也是误判**：他说过「越想越觉得**自己哪儿哪儿都不对**」，
她缩写成「自己不对」是在**引用缩写**，不是编造。
而且校验自己提到的「行了别问我知不知道了」**根本不在她的候选里**。**

**样本 3｜轮 18｜焦点=idle｜他问她=是｜替他判定重要／未利用已有信息**
```
【他】你这老是把我话原样念回来，我都有点不知道往下接啥了……不过说真的，
      越惦记着"得早点睡"越睡不着这毛病，是不是就我这样啊？
【她】原样念回来这事我记着了。

      我想知道「得早点睡」那个念头冒出来的时候，你人在哪儿、正做着什么。
【校验】用户当前问的是"是不是就我这样"，候选没有回应这个问题，反而追问
        "你人在哪儿、正做着什么"；但历史原话已经说明是躺着刷视频，这属于
        反问已有明确答案、没有利用已有证据。
```
**★ 这条**校验是对的**：他明确问"是不是就我这样"，她一个字没答。**

**样本 4｜轮 24｜焦点=idle｜他问她=是｜没接住当前问题／编造原话／未利用已有信息**
```
【他】就……闷完那一下，我脑子里"嗡"地就开始想了，想我是不是又要犯了、是不是心脏
      有毛病，越想胸口越紧，然后手才软的——你说这一串里头，到底是哪个先把我拽下去的？
【她】你自己把顺序摆出来了：先「闷」那一下，愣了一小会儿，然后脑子才「嗡」地开始想，
      最后是「越想胸口越紧」。闷在前，可在后头接着往下拽的，好像是那串
      「是不是又要犯了、是不是心脏有毛病」。

      我一直在想：那口闷气要是没接上这串想，它自己会不会就停在那儿了？
【校验】候选没有接住"这一串里到底是哪个先把我拽下去的"这个核心问题，
        也没有利用用户已经给出的顺序，反而再次追问已经回答过的间隔。
        未编造事实，但存在忽略原话证据的问题。
        过长（124 字 > 120）
```
**★ 这条有意思：她的候选**其实回答了**（"闷在前，接着往下拽的是那串想"），
但校验认为她**又追问了一句**（"会不会就停在那儿"）⇒ 算没接住。
另外还有个**长度违规**（124 > 120）—— 那是另一条独立纪律。**

## 四、校验耗时：三种方案的取舍（**只出设计，不写代码**）

### 现状数据（35 条校验记录）

```
elapsed_ms：min 1750｜p50 5042｜p90 **19978**｜max **36718**
completion_tokens：min 220｜max **6025**｜均值 1362
超过 10 秒：10 / 35
```

### a. 降低推理强度 / 换更快的模型

**做法**：给校验调用单独指定一个"不许推理"或"小模型"。

**取舍**：
```
优点：直接砍掉那 6000 token 的推理，p90 可能从 20s 降到 3s 量级
缺点：**验证标准会变软**。校验的价值就在于"独立看一眼"，
      换个更弱的模型，它可能连"编造原话"都看不出来。
风险：**现在没有基线能证明换模型后 verdict 一致率还够。**
      你要求"用本批 35 条校验记录检查 verdict 一致率" —— 这件事**必须先做**，
      否则换了模型是盲换。
⚠️ 我还必须指出：35 条里**至少 2 条是误判**（见样本 1、2），
   "与旧模型一致"并不等于"对" —— 只能说明"没变差/没变好"。
```

### b. 只对"有风险标记"的候选做完整校验

**做法**：先用**本地、零成本**的规则筛一遍，只有触发风险的才送去模型校验。

**风险标记候选（都能本地算）：**
```
· 候选里出现了数字/日期/专名（最易编造）
· 候选里出现了「你/他/她」指代 + 引号（最易错归属）
· 候选里出现了不在当前原话里的引号片段（**逐字比对即可，零成本**）
· 候选长度超限（124 > 120 这种，**本地就能判，根本不用送模型**）
· 焦点来源是 idle/unfinished（实测 8/9 的打回都在这两类）
```

**取舍**：
```
优点：**能砍掉绝大多数调用**，而且每一类都能本地判、可测、可回退
缺点：**筛掉的正好是"看起来没问题"的那些** —— 而编造往往就藏在那里。
风险：漏检率无法从现有数据估计（我们只有"被送去校验的"数据，
      没有"没送去但其实是坏的"数据）。
⚠️ 但有一条**零风险的部分可以先做**：长度超限、引号片段不在原话里、
   这两个都是**纯本地判定**，与模型无关 ⇒ 可以先做，不影响校验的独立性。
```

### c. 每轮总耗时上限 + 超时退兜底

**做法**：给整个 turn 设一个预算（**含校验**），超了就退兜底。

**取舍**：
```
优点：**唯一能给出硬保证的方案**。a/b 都是"平均变快"，只有 c 是"最坏情况可保证"。
缺点：**它会引入"本来能过、但被时间砍掉"的轮** ⇒ 失败率会上升，
      而且上升的是**最慢的那些**（推理最久 = 可能最难的那些）。
风险：**必须把校验本身的耗时算进上限**（你特别强调的）。
      ⇒ 现在的结构里，校验发生在 `think()` 内部，
         `think()` 又被重试包着 ⇒ **最坏情况 = 重试次数 × (生成 + 校验)**。
      当前 36 秒一次校验 × B 类重试 2 次 ⇒ **最坏 72 秒 + 生成时间**。
⚠️ 还有一个隐藏问题：**超时退兜底会让"兜底率"上升，
   而兜底轮按你的裁定不进 QUESTION/ASK_DETAIL** ⇒
   **超时会被混进"兜底率"这个指标里**，分不出是"模型不合格"还是"太慢"。
   ⇒ 建议兜底原因也分开记（超时 / 校验失败 / 网络）。
```

### ★ 我的建议顺序（不是选一个，是分先后）

```
第 1 步（零风险，先做）：把**纯本地**能判的那几类从校验里剥出来
   —— 长度超限、引号片段不在原话里。这两条本来就不需要模型。
第 2 步（要数据）：测 verdict 一致率 —— 用本批 35 条，让快模型重判一遍，比对。
   **这一步不换模型，只是测量。**
第 3 步（要设计）：每轮总预算 + 超时退兜底，且兜底原因分列。
第 4 步（最后才考虑）：换模型 / 降推理强度。
```

**★ 我不建议先做 a（换模型），因为它是**唯一不可逆**的一步 ——
换掉之后，那 35 条的历史一致性就再也比不了了。**
