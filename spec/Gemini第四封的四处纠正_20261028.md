## 一、V1–V3：`_pick_anchor` 在真实语料上切出残词 —— **成立，且比他说的更严重**

### 他的指认

> 「你的新版 `_PLACE_PAT` 在 215 行真实台账上切出了 18 条「半截残词」」

### 我的实测（同一批 215 行）

**跑我第二版的 `_pick_anchor`，命中可疑锚点 **41 行**（他说的 18 条是其中的地点残词一类）：**

```
「钥匙搁门口」      → **匙搁门口**
「听见冰箱」        → **见冰箱**
「搬那台打印机」    → **搬那台**
「别人台词」        → **别人台**
「收拾抽屉」        → **拾抽屉**
「柜子最里面」      → **子最里面**
「昨天开柜子」      → **天开柜**
「夹在里头」        → 夹在里头（这个碰巧是真话）
```

**另外两类他没单独列、但我一并测出：**

```
「我他妈真受不了」  → person = **「我他妈」**   （粗口被当人物锚点）
「我以前」/「你昨天」/「你刚才」 → time 前面拼了人称代词
```

### 根因

**第二版把地点模式写成 `[\u4e00-\u9fff]{1,2}(?:楼|栋)...` 和 `[\u4e00-\u9fff]{1,2}(?:桌|台|柜...)`。**

**⇒ `{1,2}` 会**从任意汉字起吞两字**，把动词、量词、名词的第一个字全当成地点前缀。**

### 修法（第三版）

```
① 地点模式改成**词根闭集 + 可选方位后缀**；楼层只认"方位字/数字/字母 + 楼 + 数字层"：
     (?:[东西南北中前后]|[\d一二三四五六七八九十百]+|[A-Za-z])(?:号)?(?:楼|栋|座)(?:[\d一二三四五六七八九十百]+(?:层|楼|室))?
     |(?:抽屉|柜子|衣柜|冰柜|冰箱|电脑桌|办公桌|书桌|饭桌|桌子|桌沿|桌上|桌下|车位|座位|床边|床上|窗前|高架)(?:最里面|里面|里头|底下|上面|上|里|边|前)?
② 屏蔽粗口「他妈(的)」：等长空格替换，保持下标不变。
③ 时间词**不拼代词前缀**；并把时间分两档：
     episodic（那天晚上/小时候/有一次…）> recent（昨天/前天/上周…）
   —— 因为问「你说的「昨天」，当时发生什么了？」是空转。同时**剔除「今天」**。
④ ★ **撤回"跨类比长度"**，改为按语义角色裁决：
     person > time_ep > place > thing > time_rec
     唯一例外：显式空间安置句（含 放在/搁在/留在/搬到/住在 且有地点）⇒ place 优先。
```

### 为什么"跨类比长度"必须撤回（他给的理由我认）

```
汉语里至亲之人只有 1–2 个字（我妈/我爸/他/她），
而地点/容器天然 4–5 个字（北楼三层/柜子最里面）。
⇒ 一旦跨类比字数，2 字的「我妈」**永远**赢不了 4 字的「夹在里头」。
⇒ 这与 _pick_concrete 当年"按字数挑小句，背景长句永远赢四字感官短句"
   在数学上是同一个坑：**用表面长度去跨类比较不同性质的语言单位**。
```

### 修后实测

```
残词/粗口/错拼：**0 行**（原 41 行）

「我他妈真受不了」        → ('', '')              ← 不再抽粗口
「我以前那股劲儿没了」     → ('time', '以前')      ← 代词不再拼进去
「丙项目资料放在北楼三层」  → ('place', '北楼三层') ← 空间安置句，place 优先
「我妈只问了一句第一是谁」  → ('person', '我妈')    ← person 优先
```

**★ 两处变成"抽不出"（原来抽错）：**
**「对，它不在里头……我他妈…」→ 空；「你刚才那句我没听清」→ 空。**
**⇒ 空着时 `_pick_ask_detail` 退回「发生什么了？」，那是安全的；抽错比抽不出坏。**

**测试**：`tests/test_anchor_concreteness.py` B1–B13（**13/13**）

## 三、`stance.py` 的越界：**成立，已改写**

### 他的指认

> 「你在 `02_stance.py` 里把这些工程代理量直接翻译成了**对用户的心理诊断断言**
>  （「他承重到了极点」「他在过度执着」）！这不仅把工程代理伪装成了心理事实，
> 而且一旦模型顺着这句提示词对用户说出「你现在承重到了极点」，当场就违反
> `FRAME_SYSTEM` 第 2 条（E4：不诊断、不贴标签）。」

### 我的核对

**确实如此。第一版的三条：**

```
"OVERLOADED":  "**他这会儿承重到了极点**。极简、沉静、落地：…"
"WANT_NO_LIKE": "**他拼命想要的，和他实际尝到的，不是一回事**。…"
"DRIVE_UNACKNOWLEDGED": "**他在过度执着于一个结果**。…"
```

**⇒ 主语是「他」 ⇒ 那是诊断。而 `tension` / `w` / `l` 在 `pipeline.signal_basis` 里
已明确声明只是**工程代理量**。**

### 修法（两条铁律 + 一个可执行的测试）

```
铁律一 主语归己：只说「本轮回应要求什么形式」，不说「他怎么样」
铁律二 显式分栏：[有据：…] 只放原书真有的话；[ENG·句法约束] 放我写的工程要求
```

**改写后的样子：**

```python
"OVERLOADED": (
    "【对应行为】ACKNOWLEDGE（承认）[有据：M-意义疗法师不作价值评判]｜"
    "[ENG·句法约束] 不追问，不复述整句，只用一句 ≤24 字的话接住他原话里的核心词。", 24),
```
