# 行为规则演化与可信基线（2026-10-06）

授权见决定记录 D-020，用户原话：「在三本书的边界内，允许形成、修改和淘汰自己的行为规则，剩下都按照你推荐来」。

## 本轮落地的规则学习

新增 behavior_learning.py，接在 Pipeline 的动作选择与原有退让链之间。学习的是“已选动作本轮无法实现时，该用哪个既有安全动作”，第一版实际使用目标限于 REFLECT / ASK_DETAIL。它是系统从经历中形成的条件规则，不增加新的表达行为或让模型生成规则代码。

条件包含已有标记集合、原拟动作，以及“本轮原动作确实无法实现”这一硬前提。正常可实现的动作不受此类规则干预。每次使用都检查当前硬约束，再走已有 responder.render；过度意向和不可改变场景禁止学到的 ASK_DETAIL 绕过原有边界。

三条不同输入先形成候选；之后两条此前没参与形成的输入验证动作实现结果，才启用。相同原文重放不重复计数。这些输入以原文 SHA256 区分，**不保证语义独立**。3+2 是 ENG 参数，不是三本书给出的心理发展门槛。验证只证明回退动作可执行，不证明它比原有退让链更懂用户、更受欢迎或更有疗效。

新会话读取同一台账目录下的 behavior_rules.json。候选与活动规则都保留版本；新反例立即撤销旧活动规则，留下旧结构和反例哈希，再形成下一版候选。事件历史不删。台账同步记录规则事件及实际使用的规则。没有评分到意义体验的回写，也不靠用户停留时长、字数或家教分数奖励行为。

**实际闭环实证（临时验收副本，非正式训练）**：五个不同的“我非拿下这个…不可”输入，形成并验证 ASK_MUST 无法实现时回退到 REFLECT 的规则。新会话第六个输入实际读回并使用，台账出现“经历规则：ASK_MUST → REFLECT”。这是程序性习惯的形成，不是独立的自我阶段提升证据；原有退让链也会得到 REFLECT，本轮不声称对话质量已改善。

## 三本书边界的处理

- E-158 / E-159：提供“结构及要素联系规则可以获得或变化”的方向。本轮只是窄范围的条件关系演化，不把两条观点的完整理论标成已经实现。E-167 的“新的组织原则”仍没有充分操作化。
- DB-153 的重复刺激反应减弱，与原 R1 的重复效果约束共同提供避免无效重复的参考。把它用于软件回退习惯是**跨域工程类比**，不是证明程序具有多巴胺回路。
- M-426 / M-429：保持不替用户作价值评判、提供观察机会的边界。原有 E1、过度意向、逐字材料闸门仍在新规则之后起作用。创造途径仍为 0。

第一版只学习动作可实现性，尚未学习“在什么经历下改变理解结构才能处理过去处理不了的输入”。后者需要旧、新结构的独立反事实检验，不能拿本轮习惯数量替代。

## 可信基线已经启用

默认发展状态来源改为 state/devlevel_verified.json：

- level=I-3，equilibration=0；I-3 是沿用的工程起点，不是对系统人格的新测量。
- 原 state/devlevel.json 的字节原样存入 state/development_legacy_20261006/devlevel.json，哈希记录在 canonical 的 legacy 字段；原台账和原先快照均保留。
- state/devlevel.json 现在是标有 display_projection 的显示副本，供已有 exe 的只读面板使用。canonical 才是未来门控的数据源；显式读显示副本的 DevLevel 也会转向 canonical。
- baseline_schema=1 / baseline_id=verified-20261006 随新快照写入。基线坏掉或丢失时拒绝退回未经核实的旧水平。
- 旧台账播种的历史机制状态可以继续使用，但其历史 dev 单独标记，当前 dev 用新基线覆盖，防止第一轮 META 将旧 I-3/4 当成当前水平。R3 不再因旧假升级解锁。
- 新基线**不允许单凭高误差后低误差增加平衡化**。本轮行为习惯变化同样不增加平衡化；未来独立结构证据接入前，计数维持 0。

迁移是用户已授权的状态纠正，不属于阶段随情境回退。archive 保存所有旧事件，包括被否证的三次计数。旧数据不会被改写成“当时就没发生计数”。

实际迁移只涉及 canonical、新 archive、原路径显示副本三项。第一次迁移后的审计白名单比较曾因 Windows 路径分隔符不一致报错，实际差异恰为这三项；已统一为 POSIX 路径，再次运行验证为幂等，36 个状态文件未新增变动。归档字节哈希与 legacy.sha256 相符，原训练台账 SHA256 仍为 473442cae55fb65f0f264c29dc40e76904b7d8fe959ef94095a96db3b7b01767。

没有启动正式项目训练或调用真实 API。只读 UI 的源码和 exe 未改，原有显示路径通过投影兼容。观测窗仍有历史有效轮 115；新的有效平衡化为 0，按既有规约会显示红灯。这反映独立发展证据尚缺，不是迁移失败，也不据此调低阈值。

## 验证与下一步

25 个测试脚本在门控 0 / 1 两环境共 50 次通过。新增 7 项回归覆盖不同输入与后续验证、修订与历史保留、非法动作、基线原件归档、损坏基线、旧快照污染、跨场实际使用与过度意向边界。两项变异（删除连续性保护、使用未验证候选）均被抓住。验证在临时项目副本，网络连接被审计钩子阻止；验证期间真实 36 个状态文件未变。

复现命令：

    python -B tools/verify_next_step.py --report spec/规则演化验证_20261006.json
    python -B tools/initialize_verified_baseline.py

第二条是幂等迁移核验，不会再次清零已有 canonical。原件和 canonical 保存在 state/；测试脚本不能对真实训练台账追加演示轮。

下一步聚焦“理解结构的变化”：寻找真实未能处理的输入，给出旧结构、独立经验约束、新结构，以及未参与修改的输入上的验证。先建立可证伪的新组织关系，再讨论是否能支持阶段门控变化。当前规则演化与经核实的平衡化计数保持独立。
