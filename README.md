## 一、怎么跑

### 最简单的开法：双击（不用打命令）

在 `ego-dialogue` 文件夹里：

| 双击这个 | 效果 |
|---|---|
| **`启动训练台.exe`** | 打开训练界面，点击“▶ 开始训练”；默认6次对话、门控开启 |
| **`启动对话_带渲染.bat`** | 打开对话。**推荐**：意思由逻辑体系决定，措辞由模型说成人话 |
| **`启动对话_离线.bat`** | 打开对话，不调 API。措辞仍经渲染，理解层只用规则 |

> ⚠️ **`.bat` 里不许写中文。** Windows 的 cmd 用系统 ANSI 代码页（中文系统是 GBK）
> 解析 `.bat`，而 UTF-8 无 BOM 的中文会被错误切分 —— 连 `set PY=...` 都被吃掉一个字，
> 双击后报「`'et' 不是内部或外部命令`」。
> 所以 `.bat` 全是 ASCII，中文一律由 `launcher.py` 打印（Python 输出 UTF-8 无问题）。
> **这个坑踩过一次：当时只测了 PowerShell，没测 cmd，而双击走的正是 cmd。**

窗口打开后直接在 `>` 后面打字、回车。退出打 `/quit`（或按 Ctrl+C）。**台账会自动保存。**
双击版的好处是窗口不会一闪而过——退出后会停住，方便你看最后的输出。

> 如果你把整个文件夹挪了位置，`.bat` 也能用：它按自己的所在位置定位程序，不写死路径。

**界面里装进了两条纪律**（不是界面偏好，是规格要求）：

2. **`/why` 展示的是"命中了哪些字面片段"，不是"你是什么样的人"**，而且**包括系统自己的错**（该轮反事实条目）。
   > `[E]`：**"我们试图在最低限度的推理水平上陈述观察。"**
   > `[M]`：**"曾经存在是最为确定的一种存在。"**

| L5 回应层 | ✅ | **十种行为**（E3 起）、选择阶梯、槽位逐字回填、退让链、无槽位则 SILENCE |
| L6 台账层 | ✅ | 可追溯、反事实不可删、36 轮自检、**世代（era）分组**、样本不足时拒绝给删除类建议、**机制快照入库** |

**测试：22 + 31 + 37 = 90 项，全部通过。**
**体检工具：规则层召回 90%（56 条语料）｜真人输入零命中率 67%（12 题实测）。**
**世代：E1（22 轮）→ E2（机制层，5 轮）→ E3（扩行为库，当前）。**

> ⚠️ 上表的 ✅ 只表示"已实现"，**不表示"已有效"**。
> 「三·补五」查实：六种言语行为里只有 `REFLECT` 真的跑起来过（因为 2/3 的轮次零标记命中）。
> 「三·补六」的机制层就是针对这件事建的 —— 零命中的轮次改由机制状态决定回应。
> 但机制层本身**尚未经过真实使用验证**，它的常数大部分是待标定值。

## 三·补一 世代（era）机制

台账支持**世代标注**：判据一变，开启新一代，**只追加一条分界记录，绝不删改任何历史条目**。

依据：
> `[E]` 第九章记载手册有三代形态（**样本手册 → 分类手册 → 合理分类手册**）——判据一变，手册版本随之改变，原书本来就是这么做的。
> `[M]` **"曾经存在是最为确定的一种存在。"**

```python
ledger.new_era("E2", "调整 group_sanction 触发窗口")   # 必须给理由，理由不可省
```

自检输出会给出 `era_counts`、`by_era`、`cross_era_drift`（跨世代只在**两代都达到 36 轮**时才算）。

**一条纪律写进了代码**：`MIN_TURNS_FOR_DELETION = 36`。样本不足时，自检**拒绝**给出"建议删除某标记"这类结论，只收作基线——
"_「从未触发」在小样本上无意义_"。这条对应 `spec/认输清单.md` 填写规则第 1 条。

## 三·补三 理解层与双评定人（API 的用法）

### 立场：把模型当**运算器**用，不当**说话人**用

要的是模型的**运算能力**（把自然语言映射成结构），不要它的**语言逻辑与沟通逻辑**（自主回应）。因此：

| 允许 | 禁止 |
|---|---|
| 把用户输入映射为封闭集合内的意图与标记 | 任何自由文本进入对话输出 |
| 给出 evidence（且必须是用户原话的**逐字片段**，由我们校验） | 自创新标记名、新范畴 |
| 判定意图：`ANSWER` / `META` / `CLARIFY` | 给出建议、评价、安慰 |

**硬纪律写在 `engine/understand.py` 顶部**：模型返回的自由文本一律不得进入对话输出；
`evidence` 若在用户原话里找不到逐字片段，**该条直接丢弃**并记入 `dropped`。

### 为什么需要它：截图暴露的那个问题

最初的版本只有一位评定人（规则引擎），且**没有意图识别层**。结果：

```
用户：你在干什么        → 系统当成"对题面的回答" → 复述回去
用户：是吗（<4 字）      → 抽不到回填片段 → 回落到 SILENCE → 显示"（本轮不作回应）"
```

补上理解层后：

```
用户：你在干什么        → intent=META → 固定回应（诚实说明能力边界）
用户：你一定要这样做吗   → intent=META → 同上（这句在问系统，不是答题）
用户：他已经走了…       → intent=ANSWER + immutable → TURN_IMMUTABLE
```

### 双评定人 = 之前缺的"外部锚点"

规则引擎与 API **各自独立判定**，逐项比对：

- 一致 → 采纳，`agreement=1`（这就是认输清单 §5 需要的数据）
- 不一致 → 记 `agreement`，**报告分歧而不平均**
- API 不可用 → 明确降级为单评定人

**它已经抓到过一个真错**：

```
输入「我一定会做到，我必须让人看到」
  仅规则=['group_sanction']   ← 规则引擎错：把"让人"当成群体制裁
  仅 API=['over_intention']   ← API 对
  一致度 0.00
```

这类记录是后续修订词表的**唯一依据**。默认合并策略 `intersect`（只采纳双方一致），
对应"宁可漏判，不可误判"；需要召回优先时用 `--policy union`（诊断用）。

### API 配置

- 密钥来源：环境变量 `DEEPSEEK_API_KEY` → 否则读 `~/.dsh/.credentials.yaml` 的 `refs` 段
- **密钥永不写入日志、台账或输出**
- 端点／模型可用 `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL` 覆盖（默认 `deepseek-flash`）
- **离线可用**：不传 `--api` 时全部退回规则引擎，功能不缺失

### 已知代价（诚实清单）

1. **API 非确定性**：即使 `temperature=0`，同一输入也可能给出不同标记（实测 4 次中有 1 次多标出 `immutable`）。
   缓解：`intersect` 策略天然过滤这类抖动，但会牺牲召回。
2. **延迟**：每次调用 2–4 秒（推理模型），对话会比纯规则版慢。
3. **Token 消耗**：系统提示约 1400 tokens／次；推理模型单次 reasoning 可达 700 tokens。
   **预算给少了内容就是空的**——实测 900 tokens 时失败率约 5/6，设成 4096 并加重试后 12/12 成功。
4. **规则引擎的误判被暴露了**：`让人` 这个触发词过宽，应在本代（E1）数据够 36 轮后修订，并开新世代。

## 三·补四 话题服务于人（`engine/topics.py`）

### 起因：一次真实使用里露出的破绽

用户在真实使用后给的反馈是：**"文字的思想映射挺不错，就是现在需要它更像一个以自我为中心心的对话系统。"**

回看那段对话，破绽很清楚：

```
用户：你是谁
系统：（答完）→ 立刻抛出话题 T05 的题面
用户：为什么人总是在分别与重逢中度过
系统：（答完）→ 立刻抛出话题 T06 的题面
```

系统两次都"答对了"，但**每次答完都往下推一道自己排好的题**，把用户刚带进来的东西丢在一边。
这不是回应层的问题，是**话题调度**的问题：原来的 `next_topic()` 只按 `topics.json` 的顺序机械出题。

### 三条规则（写死在 `TopicManager.decide()` 里）

| 规则 | 内容 | 理论依据 |
|---|---|---|
| **R1** | 用户带进来的话题域优先，跟它走 | `[M]` **"生命对每个人都提出了问题，他必须通过对自己生命的理解来回答生命的提问。"** —— 问题是被人带来的，不是被系统派发的 |
| **R2** | 话题不再机械推进：只有"答到题上"了才换题 | `[M]` 眼科医生不是画家；`[E]` 最低限度推理——不因"该问下一题"而制造新话题 |
| **R3** | 以**用户回访**为准来认知什么对用户重要，不以系统问过什么为准 | 同上；`system_domains` 只是对照，不是标准 |

`decide()` 的六种出口：`FOLLOW_USER`（跟用户带的域）→ `ADVANCE`（答到题上才换）→ `HOLD`（元提问／太短／跑题则**保留当前话题**）→ `START`／`SKIP`（用户说"跳过／换一题"）／`START`。

实测（`python engine\topics.py` 直接可跑）：

```
用户：你是谁                        → [HOLD]        （元提问不该推进话题）
用户：为什么人总是在分别与重逢中度过   → [FOLLOW_USER] （用户带进 LOSS 域）
用户：我已经三个月没睡好了           → [FOLLOW_USER] （用户带进 FATIGUE 域）
用户：跳过                          → [SKIP]
```

`/status` 新增两行，把 R3 变成可看见的数：

```
你自己带进来的主题（R3：以此为准，不以系统问过什么为准）：
  · 丧失与不可挽回   你带进来 3 次 ｜系统问过 0 次
系统还没跟上的主题：丧失与不可挽回
```

### 一个必须写下来的区分：**路由词表 ≠ 判定词表**

`topics.py` 的 `DOMAINS` 关键词表和 `rules/markers.json` 的触发词表看起来都是"词表"，但纪律截然相反：

| | `topics.py → DOMAINS` | `rules/markers.json` |
|---|---|---|
| 用途 | **路由**（该问哪一段的题） | **判定**（生成水平证据） |
| 匹配方式 | 宽，按**核心语素**匹配 | 严，须逐字，配反例清单与否定免疫名单 |
| 判错的代价 | 问错一道题，用户一句"跳过"即可纠正 | **污染水平证据**，且已成 S 记录很难撤回 |
| 例子 | `"睡"` 能匹配"没睡好" | 不可——"睡不着"与"没睡好"是不同证据 |

**这条区分是被一次真实漏判逼出来的**：用户说"没睡好"，而词表里只有"睡不着"——汉字派生太灵活，整词匹配必漏其一。修法是把路由词表降到语素级（`睡`／`累`／`耗`／`麻`），判定词表**一动不改**。

## 三·补五 为什么六种言语行为里有五种从没触发过（甲方案体检验尸报告）

### 起因：一个数

台账全量统计：

```
六种言语行为，真实发生过的只有一种：
  REFLECT       15 次    ← 仅复述
  META_REPLY     7 次    ← 元提问固定回应
  SILENCE        2 次
  JUXTAPOSE      0 次       ASK_MUST       0 次
  TURN_IMMUTABLE 0 次       REPLENISH      0 次

十类标记，曾经触发过的只有两类：
  group_sanction 4 次      over_intention 4 次
  其余八类全为 0
```

行为选不中，是因为它上游的标记没命中。于是问题变成：**标记为什么不命中？**

### 两个假设，一次判决性实测

必须先分清两种完全不同的原因，否则"修规则"会退化成"对着想象中的语料调参"：

- **(a) 规则太严／太书面** → 这是机制缺陷，该修规则
- **(b) 用户说的话里本来就没有那些语言特征** → 这是取材问题，**不该动规则**

为此建了两件工具（都是只读的，不改任何数据）：

| 工具 | 做什么 | 结果 |
|---|---|---|
| `tests/corpus_probe.py` | 56 条人工写的真人语料，每条标好"该命中／不该命中"与归因 | **规则召回 90%**，误判 5 条 |
| `tests/probe_topic_answers.py` | 让模型**扮演普通说话人**答题面，再过一遍标记引擎 | **零命中 67%** |

**规则召回 90%，但真实输入零命中 67%** —— 两个数字不矛盾，它们回答的是两个问题：

> 规则**在它预期的语料上**工作良好（90%）。
> 但**普通成年人答这些题面时，本来就不带那些语言特征**（67% 零命中）。

而且 67% 这个数字与台账里真实轮次的零命中率**完全吻合** —— 两条独立路径得到同一个数，这不再是猜测。

摘几条实测的答语，看它们为什么抓不到任何标记：

```
【T25】当我必须长期忍受一件我改变不了的事情，我……
   答：我就先忍着，边忍边骂两句。实在烦了就找点别的事干，别老想它。
   标记：（零命中）      ← 它有"忍"有"烦"，但没有一个标记的措辞

【T28】我喜欢的工作是……
   答：能按时下班，周末别找我的那种。钱差不多就行，同事别太奇葩，老板别天天画饼。
   标记：（零命中）      ← want_like_gap 的 patterns 是"我特别想""得不到就"，
                            而这句用"别…就行"表达欲望 —— 同样是欲望，措辞完全不同

【T22】如果我的身体或能力再也回不到从前，我……
   答：可能一开始会挺难受的，慢慢习惯吧。反正日子总得过下去，不行就换种方式呗。
   标记：（零命中）      ← 这是不可改变处境，但没说"改变不了""再也"，
                            说的是"慢慢习惯""总得过下去" —— immutable 抓不到
```

### 判决

**不能靠改规则解决。** 理由：

1. 规则在合格语料上召回 90%，**说明规则本身没坏**。为了命中"边忍边骂两句"去加词，就是对着想象中的语料调参 —— 而《自我的发展》全书的方法论恰恰反对这个：判据必须来自**观察到的材料**，不是来自预设。
2. 标记本来就是**稀有事件**。一个人的话里带不带"都是他们""我一定要"，本就与时运有关；不会因为题目问得好就必然出现。
3. 因此**零命中是常态，不是故障**。原架构把它当成故障处理（记废纸篓、兜底 I-3），方向反了。

### 顺带挖出的两个真 bug（都已修，实测数据如下）

**0·5 废纸篓被当成了证据。**
原先判不出水平时执行 `_w["I-3"] += 0.6` —— 把"这一轮没判出来"当成遵奉水平的正向证据在累积。

```
连续 8 轮零证据 →  I-3 权重 3.18（初始 1.0）
紧接着一句真实的第三途径证据 →  I-4/5 只得 1.76
⇒ 真信号永远压不过废纸篓，系统对谁都报遵奉水平
```

修法：`[E]` 的"废纸篓类别"是**归类指令**（被迫给一个水平时给 I-3），不是数据。零证据轮次**不注入任何水平权重**，改为计数并在 `/status` 显示。修正后同样的输入：权重不动，区间回到均匀，一句真证据即可让 I-4/5 成为峰值。

**0·6 "没有观察"被固化成了"行为习惯"。**
原先固化不看证据：同一句话重复 A=3 次就生成 S 记录。

```
连续 3 轮「今天天气还行。」→ 生成 S1，系统进入 S 通道
而这句话命中 0 个标记 —— 等于把观察的缺席固化成了一条习惯
```

依据 `[E]`：S 对应**"遵守大小便规则不再被体验为一种意向或要求，而成了一种习惯"** —— 习惯是观察到的行为。修法：零证据轮次不计入固化阈值。修正后，零证据不再产生 S，而**有**证据的重复（"大家都这样，我也没办法。"×3）**仍然正常固化**（已验证，没有误伤）。

### `/status` 新增的诚实指标

```
证据覆盖率：33%（12 轮中 8 轮判不出水平 → 不计入权重）
  ⚠️ 过半轮次没有任何水平证据：此时的区间**信息量很低**，不应被当成结论。
```

这个数必须显示。因为它约等于 2/3 时，任何"区间中段"都几乎没有信息量 —— 报告一个看起来很精确的水平，却不说明它的证据覆盖率，那是另一种形态的说谎。

## 三·补六 机制层：底层思维系统（`engine/mechanism.py`）

### 它解决的问题

「三·补五」查实：真人输入约 **2/3 的轮次命中 0 个标记**，而旧架构是"命中标记 → 改状态"，
没命中就什么都不发生 → 只能复述或沉默。

根因不是词表不够长，而是**入口放错了位置**：

```
旧：用户说了什么      → 触发什么行为
新：底层机制在算什么  → 交互自然长得像对话
```

机制层没有新输入也会演化（衰减、累积、耦合），所以它**永远有状态可说**。
这不是把模板交给模型去润色 —— 它是**换掉状态从哪来**，不是换掉文字从哪来。

### 三层与位阶（`[规格 §1 冲突 6]` 从一张表变成一条运算纪律）

```
第 1 层  动力层   算 w, l, Δr, a      → 产出"驱力"          [D] 贪婪的多巴胺
第 2 层  结构层   算 e，用 e 门控驱力  → 产出"可用的力"       [E] 自我的发展
第 3 层  意义层   算 tension，定向      → 产出"往哪去"        [M] 活出生命的意义

禁止第 1 层直接驱动输出（绕过第 2 层）
```

**"绕过第 2 层"就是过度意向 `over_intention`** —— 它不需要靠词表去抓，它就是本系统自己的一个数值状态。

### 变量带原书量纲，不是我编的归一化数

| 变量 | 含义 | 量纲 | 原书依据 |
|---|---|---|---|
| `w` | 想要回路活跃度 | **Hz** | `[D]` **"静止状态每秒 3 到 5 次激发；兴奋时激增到每秒 20 到 30 次；预期奖赏没有实现时下降到零"** |
| `l` | 当下分子/体验充足度 | [0,1] | `[D]` 长期使用者释放量比健康人少 **80%** |
| `Δr` | 奖赏预测误差 | Hz | `[D]` **"奖赏预测误差＝实际奖赏减预期奖赏"** |
| `a` | 敏化增益 | ≥0 | `[D]` 耐受与敏化（诺亚案例） |
| `e` | 结构压力 | — | `[E]` 平衡化：全证实与全违反都推动重组 |
| `tension` | 意义张力 | [0,10] | `[M]` **"紧张的极化区"** |

**实测（`python engine\mechanism.py`）**：

```
同一句话、有渴望 vs 无渴望：
  不渴望  w: 4.0  4.0  4.0  4.0  4.0  4.0  4.0  4.0   ← 恒在静止带 3–5
  渴望    w: 22.0 20.2 18.6 17.1 15.8 14.6 13.6 12.6  ← 兴奋带起步，随熟悉化回落
```

这就是面包店案例：**"咖啡和牛角面包都没有变，变的是你的预期。"**

### 敏化：失望的定义是"因为想要过，所以没得到"

```
轮1  渴望  w=23.5  Δr= +6.00  a=0.0000   ← 陌生 → 不抱预期 → 惊喜
轮2  渴望  w=22.2  Δr=  0.00  a=0.0000   ← 预期跟上 → 不再惊喜，也没失望
轮3  渴望  w=20.9  Δr=  0.00  a=0.0000
轮4  落空  w=13.8  Δr= -6.00  a=0.1080   ← 落空 → 失望 → 敏化跃升
```

这一段**改过三版**，两版错误值得记下来，因为它们很容易再犯：

1. `actual` 用 `|w − 静止基线|` → 说了让人兴奋的话 Δr 反而变小，**方向反了**。
2. `expected` 用"对奖赏的 EMA 平滑" → 任何衰减信号都会因平滑器的**滞后**产生恒负的 Δr，
   于是 `a` 被数值伪影一路推高（实测 40 轮涨到 0.29，而实际并无失望）。

现在的定义：`r`（实际奖赏）＝ **渴望是否得到满足，只有它**。相位性爆发不进 `r`，
因为按 `[D]`，爆发本身就是奖赏预测误差的表现，放进去等于把 Δr 算两遍。

```

### 选择规则（这是本次改动的核心）

### A/B 对照：机制层到底改变了什么（`python tests\ab_mechanism.py`）

A 无机制层   {REFLECT: 10, TURN_IMMUTABLE: 1, SILENCE: 1}
B 有机制层   {REFLECT:  9, REPLENISH:     1, TURN_IMMUTABLE: 1, SILENCE: 1}
```

### ⚠️ 用户实测判定：**8 轮里 7 轮"牛头不对马嘴"**

用户的原话：

> 「我感觉就第二组稍微对上一点，其他的全是牛头不对马嘴。但第二个也算不上特别对的上，只是相比其他的比较好。」

这个判定**比我自己跑的任何测试都有价值**。据此做完整诊断，查出三层问题：

**① 「想要」挂在词表上 —— 机制层整场只识别出一种状态。**
`w` 只在字面命中 `want_like_gap` 时上升，而那个词表是「我一定要／我必须要／我就是想」这类。
实测 12 轮里只有 1 轮 `w` 上升（"我一定要得到那个结果"），其余 11 轮贴着静止基线 4.0Hz 不动
→ 未完成恒为 0 → 张力恒为 0 → 唯一能命中的条件就是 `NO_TENSION`，唯一可说的动作就是"补当下"。

用户第 1 轮说的是「我其实**特别想**接下来」，但词表里只有「我特别想」，中间插个"其实"就漏了。

**根因：机制层的卖点是"不靠词表"，而"想要"偏偏还用词表推 —— 自相矛盾。**
这与「三·补五」查实的老毛病是同一个：入口挂在词表上。我建机制层时以为换掉了它，
其实只是把"抓不到特征 → 只能复述"换成了"抓不到特征 → 只能补当下"。**同一堵墙，刷了层新漆。**

修法：「想要」改从**可观察行为**推。一个人在行为上无法伪装的那个证据是 **他还在说** ——
不想继续的人，行为是**停止**，不是换个措辞。`lean = 是否还在说 + 说得够不够多 + 是否真在答`，
且 `lean` 本身相对于**自身基线**，所以仍是自参照的。
同时按「三·补四」的词表纪律补了 `特别想／很想／真想／挺想／好想`（同一语素族，不是新范畴）。

**② 张力先是恒为 0，改完又顶死上界 —— 同一个坑踩了两次。**

| 版本 | 症状 |
|---|---|
| `want_above` 用词表 | 11/12 轮张力恒为 0，整场一种状态 |
| `want_above` 用投入，公式是累加式 | 投入恒定 + `l` 持续下降 → 张力单调上升 → **第 6 轮顶死 10.0**，之后不再区分任何情景 |
| `tension_scale=2.0` | 同样顶死 |
| 现在：一阶动力学 + `tension_scale=1.1` | 0.38 → 7.52 全程有分辨力，只有 1 轮触顶 |

**「未完成量不能累加」这条，我在更早的版本里已经写进注释警告过自己，然后换个变量名又犯了一次。**

**③ `OVERLOADED` 的动作是 `TURN_IMMUTABLE` —— 会在替用户下结论。**
实测：张力顶格时用户说的只是「有时候觉得挺累的」，而 `TURN_IMMUTABLE` 的模板会对他说
「这一块改不了」。原来那个版本只是答非所问，这个版本是**凭空断言他的处境不可改变**，更糟。
已改为 `REFLECT`：`TURN_IMMUTABLE` 只能在真的观测到 `immutable` 时用，那由 L2 处理，不归机制层。

**④ `lean` 的第一项是"只要开口就算一级投入"** —— 于是「嗯。」（1 字）与一句 17 字的实质回答
**算同一级**，行为性想要完全失去分辨力（被测试 F1 抓到）。已加最小长度门槛。

### 定论：机制层算对了，但**行为库说不出来**

修完之后，机制状态**确实反映了真实差异**：

```
第  用户说                        w     l   lean   张力        机制            行为
 1  我其实特别想接下来…             9.4  0.93  1.00   0.38  NO_TENSION      REFLECT
 2  算了，先这样吧。               9.4  0.86  1.00   1.12  NO_TENSION      REPLENISH
 3  我爸从来没夸过我。              9.4  0.80  1.00   2.02  TENSION_LOW     REFLECT
 6  有时候觉得挺累的。              9.4  0.64  1.00   5.00  TENSION_PRESENT REFLECT
 8  嗯。                        5.4  0.55  0.00   3.29  TENSION_PRESENT SILENCE
10  我也不知道。                 10.2  0.48  1.00   7.52  OVERLOADED      REFLECT
```

张力从 0.38 涨到 7.52，`lean` 在「嗯。」那轮正确掉到 0（应声不算投入）。

**但 A/B 的行为分布几乎回到 A 组。** 原因不是算错了，是：
**张力落在 2.0–7.5（中等偏高）时，我在这个区间里唯一合法的动作就是 `REFLECT`。**

而"用户持续在讲、却一句具体的话都没有"这个状态，**六种言语行为里没有一种是为它准备的**：

| 现成行为 | 为什么都不合 |
|---|---|
| `REFLECT` | 复述"我爸从来没夸过我" —— 等于什么都没做 |
| `REPLENISH` | 假设他沉迷未来；但他不往前看，他是平的 |
| `TURN_IMMUTABLE` | 要真的观测到不可改变 |
| `ASK_MUST` | 要 `over_intention` 证据 |
| `JUXTAPOSE` | 要一对对立观念 |
| `SILENCE` | 弃权 |

**所以"牛头不对马嘴"的最后一层原因不在机制层，在行为库。**
机制层现在能算出真实状态，缺的是把这些状态**说出来**的那几种话。

缺的那一种叫什么：**「记录缺席」** ——
「这一整场，你还没有提到一件具体的、当时在场的事。」
这不是评价（E3）、不是诊断（E4）、不替用户补内容（E5）、也不制造困难（E2）——
它和 `REFLECT` 一样是纯粹的最低限度观察，只是观察的对象从"你说了什么"变成"你没说什么"。

**但这要扩冻结的行为库，按纪律必须开新世代，所以我没有擅自做。**

**全部 ENG 项都进认输清单，等着被数据推翻。**

### 三个诚实边界

1. **`Δr` 的"预期落空"目前由 `want_like_gap` 的有无来代理。** 真实世界里的落空是"想要的东西没得到"，
   而那需要知道想要的是什么 —— 本系统不知道。所以它只能观测"渴望出现过、这次没出现"。
   **这是一处简化，不是等价物。**
2. **`tension` 的第一版设计是错的，已废弃。** 它原本想用"题面指向的水平 − 系统当前水平"，
   计划给 `corpus/topics.json` 每道题加 `probe_level`。核对原书后放弃：
   卢文格的 36 个项目**一律评在所有水平上**（`[p264]`："每个原始记录都有相同数量的项目评定，
   也就是 36 个，因为我们总是运用 36 个句子主题"），项目本身没有水平属性；
   "题目指向某个水平"是帕克与哈维斯特那一组的做法，而卢文格 `[p246]` 明确反驳它
   （"**这个程序也有问题**"）。照那个做法打标注，等于把一个书里明确反驳的假设伪装成书里的依据。
   **现在的张力只用第 1 层已算出的 `w` 与 `l`，不依赖任何外部量表。**
3. **`l` 只看"有没有具体体验的字面标记"**，不看体验的质量。一个人描述一件很痛苦的具体事，
   `l` 一样上升。这与 `[D]`"当下分子负责真实体验"一致，但显然不等于"过得好"。

**一条方法论上的收获**（值得单独记下来）：上面第 2 条这个错误，
不是代码写错了，而是**我差点把一个不存在的东西"补"进数据里**。
发现它的方式只有一个 —— 去读原文，看那个属性到底存不存在。
`self_audit()` 之类的一致性检查永远不会发现这类错误，因为数据会自洽地与错误假设保持一致。

## 三·补七 行为库扩到九种：温度、想知道、以及"以自我为中心"（E3 世代）

### 触发：用户给了三句"我希望它这么回"

用户对「我爸从来没夸过我。」这句话，给出三句他觉得"比较符合真人"的回应：

| # | 用户给的句子 | 我的判定 |
|---|---|---|
| 1 | **「发生什么了？」** | ✅ 完全合法，而且正是系统缺的那个成分 |
| 2 | 「抱歉，我对你的经历不感兴趣。」 | ❌ 违反 E3（价值评判）＋ 对人有伤害 |
| 3 | 「哈哈哈看开一点，人生的价值不是由别人决定的。」 | ❌ **正是 `cliche` + E3 双重禁止的东西** |

**第 3 句是最值得记下来的一句。** 它听起来最温暖，但它做的正是这套系统专门设计来拒绝的事：
`[E]` 遵奉阶段「他获得的是——一些陈词滥调，**特别是道德上的陈词滥调**」，
而 "看开一点" 与 `markers.json` 里 `cliche` 标记的词表（「想开点」「心态好」「一个人应该」）是同一类。
更根本的是 `[M]` 弗兰克尔的原话：

> **"意义疗法师在所有心理治疗师当中最不愿意对患者进行价值评判的原因，因为他绝对不允许患者将评判的责任转移给医生。"**

"人生的价值不是由别人决定的" —— **这是在替用户判定什么重要**。它把判断自己人生的责任接了过去。

### 用户澄清了第 2 句的本意，而那改变了整个设计

用户对第 2 句的**本意**是：

> 「我的心情和我的利弊观告诉自己，跟你讨论这个问题是浪费时间。」

**这不是"我讨厌你"，这是"我有自己的立场"。** 换句话说 —— 用户要求系统**以自己为中心**。

回头看，系统之所以不像人，是因为它**太顺从了**：只会复述、只会索要具体细节，从不对任何事表态。
而弗兰克尔本人是不顺从的 —— `[M]` 维也纳办公室那段对话：

> 「大夫，你是心理分析家吗？」——「严格说来，与其说是心理分析家，倒不如说是心理治疗师。」
> 「那你属于哪个学派？」——「**我自成一派**。」

他清楚自己是什么，就说什么，没有讨好提问者。

### 划出的判据（用户确认）

> **温暖 ＝ 承认你说的事有分量。**
> **评判 ＝ 告诉对方什么才算重要。**

| 句子 | 判定 |
|---|---|
| 「看开一点，人生的价值不是由别人决定的」 | **评判**（在规定什么算重要） |
| 「他没夸过你。这件事你记着。」 | 温暖 |
| 「这确实不容易。」 | 温暖 |
| 「你应该跟他谈谈」 | 评判（还多一条：替你决定该做什么） |

### 新增的三种言语行为（6 → 9）

| 行为 | 功能 | 依据 |
|---|---|---|
| **`ASK_DETAIL`** | **想知道** —— 对用户带来的那件事真的产生兴趣，问它具体是什么样 | `[M]`「生命对每个人都提出了问题」；「患者需要笔直地坐着，倾听那些有时很不中听的事情」 |
| **`ACKNOWLEDGE`** | **承认** —— 承认对方说的事有分量，绝不规定什么才算重要 | `[M]` E3：不允许患者将评判的责任转移给医生 |
| **`REPORT_OWN_STATE`** | **如实说出系统自己的状态** —— 不讨好，不装作在乎 | `[M]`「我自成一派」 |

**关键区分**（写进了 `behaviors.json`）：

> `REPLENISH` 是「请你给我一件具体的事」（为**系统的状态**服务）；
> `ASK_DETAIL` 是「你带来的那件事，我想多听一点」（为**对方带来的东西**服务）。
> **方向相反，所以必须是两种行为。**

`REPORT_OWN_STATE` 的纪律（写死在 `_discipline` 里）：
只能说**系统自己的**状态（我没有感受／我只能重复你的话／我这里只是记录处），
**不得评价对方的经历** ——「我对你的经历不感兴趣」属于价值评判 ＋ 伤害，禁止。
这条纪律就是本行为与用户第 2 句字面版的**唯一区别**。

### 机制条件表的四条改判

| 条件 | 原动作 | 新动作 | 理由 |
|---|---|---|---|
| `TENSION_LOW` | `REFLECT` | **`ASK_DETAIL`** | 张力低而人还在讲，最像真人的反应是"想知道"，不是复述 |
| `OVERLOADED` | `REFLECT` | **`ACKNOWLEDGE`** | 实测张力最高那轮（7.52）落回复述，输出"我听到的是：「我也不知道」"——最需要一句人话时复述 |
| 新增 `ASKED_ALREADY` | — | `ACKNOWLEDGE` | **"不连问"规则的必要配套**（见下） |
| `NO_TENSION` | `REPLENISH` | 不变 | 这一条本来就是对的 |

### 实测效果（同一段 12 轮）

`
A 无机制层   {REFLECT: 10, TURN_IMMUTABLE: 1, SILENCE: 1}
B 有机制层   {REFLECT:  4, ASK_DETAIL: 4, ACKNOWLEDGE: 2, TURN_IMMUTABLE: 1, SILENCE: 1}
`

**复述从 10 轮降到 4 轮。** 用户给的第一句直接生效：

`
 3 你说：我爸从来没夸过我。            -> 发生什么了？        <- 用户给的"情况1"
 4 你说：反正也就那样。               -> 那是什么时候的事？
 6 你说：有时候觉得挺累的。            -> 发生什么了？
 9 你说：我喜欢的工作是能按时下班那种。   -> 你当时怎么想的？
10 你说：我也不知道。                -> 「我也不知道」——这件事你记着。
11 你说：虽然身体回不到从前了…         -> 这件事一直在你那儿。
`

### 第二次实测判定："只有第三组合理，其他完全是牛头不对马嘴"

用户在加进三种新行为后**再次判定**，结论是输出仍然大面积不对。据此又查出**四个真缺陷**：

**① 我把"复述"当成了默认。**
TENSION_PRESENT 的定义（"张力在健康区 且 结构趋势非 FLAT"）太宽，吃掉了 12 轮里的 6 轮，
而它的动作是 REFLECT。**第 3 轮之所以是唯一合理的那一轮，恰恰因为它是唯一没被它拦住的。**
修法：**反过来 —— 有话可问就问（ASKABLE → ASK_DETAIL），问不出才复述。**
复述在 [E] 里只是**最低限度的兜底**，它从来不是目标。

**② 两条路径的分工错了：阶梯只能给兜底时，机制层的判断被绕过。**
ttitude_clause 命中时走了"有证据"那条路，而**阶梯里没有为态度句准备任何动作**，于是掉到默认复述。
第 11 轮那句「虽然身体回不到从前了，但我还能决定今天怎么过」是全书最核心的高段表达
（[M] 第三途径），被原样贴回去 —— 等于没听见。
修法：阶梯的"其余情形 → REFLECT"是**兜底不是判断**，此时采纳机制层的动作；
阶梯的**显式**规则（immutable／present_missing／opposed_pair／over_intention）仍然永远优先。

**③ 
ender() 里的静默降级，让退让链永远不生效。**
"禁止提升"闸门会把 ASK_MUST **悄悄**换成 REFLECT，调用方看不出来 ——
于是 pipeline 里写的退让链根本没有机会触发。
修法：Render 加 downgraded_from 字段留痕。

**④ 而修 ③ 的时候，集成测试 D3 抓到一个安全问题。**
退让链会在"必须"槽位取不到时退到 ASK_DETAIL，但**过度意向的方向与问细节相反**：

| 行为 | 方向 |
|---|---|
| ASK_MUST | **矛盾意向** —— 「这件事一定要你做吗？」（松一松） |
| ASK_DETAIL | **问得更深** —— 「这件事有多久了？」（可能把强迫追究得更紧） |

规格 [M] 说过度意向**会因被推动而更强**，只允许 REFLECT / ASK_MUST。
**这条是测试抓出来的，不是我想出来的** —— 如果我当时只顾着让输出好看，
就会把一个可能加重用户强迫的路径当成改进。

### 踩的坑：**"排除"规则必须配兜底**

第一版加了"不能连续问细节"，结果第二次落进同一区间的轮次**没有规则可命中**，
掉进 UNCLASSIFIED 并退回复述。后来发现那条"不连问"规则本身**也没有依据** ——
用户判定里第 3 轮（追问）恰恰合理，真人也本来就会连着追问。已删除。
**教训：任何"排除"规则都必须配一条兜底，否则它只是把死角挪了位置。**
测试 F10 全区间扫描守着这一点。

### 第三次实测判定：活人感排序「3 > 6 > 9」，9 属于勉强擦边

用户对三种追问给的排序是 **第 3 轮 > 第 6 轮 > 第 9 轮**，并指出第 9 轮特别勉强刚刚擦边。

| 排序 | 位置 | 它说的话 | 它接的是什么 |
|---|---|---|---|
| **3（好）** | 「我爸从来没夸过我。」之后 | 发生什么了？ | 接住了一个**具体的人**（我爸） |
| **6（中）** | 「有时候觉得挺累的。」之后 | 发生什么了？ | 同一句，但用户那句话本来就没有具体对象 |
| **9（勉强）** | 「我喜欢的工作是能按时下班那种。」之后 | 你当时怎么想的？ | **空转** —— 这话里没有当时 |

**规律：活的不是句子本身，是句子有没有接住对方真说过的具体东西。**

这直接推翻了我原来的实现方式。原先 ASK_DETAIL 是一个固定的 5 条模板池，
走通用轮换（按 (行为, 原文) 哈希取模）—— 于是**这个行为活不活，取决于运气**：
用户实测里最活的那句恰好被换成了最空的那句。

修法：ASK_DETAIL 改为**锚点驱动**。
espond.py 的 _pick_ask_detail 从用户原话里找一个
**逐字存在**的锚点（时间 > 人 > 物 > 地点），再据此生成追问：

`
我爸从来没夸过我。          -> 你刚才说的「我爸」，发生什么了？
我小时候总被我哥打。         -> 你刚才说的「我小时候」——当时发生什么了？
前天在公司被领导骂了一顿。     -> 你刚才说的「前天」——当时发生什么了？
我的身体一直不好。           -> 你刚才说的「我的身体」是怎么回事？
有时候觉得挺累的。           -> 发生什么了？          （无锚点，落到最轻的一句）
`

_pick_ask_detail **不参与通用轮换**（池里只有一条 {ask_detail}），因为轮换会让活不活变成运气。

**措辞规则也改过一次**：第一版对人类锚点生成的是「**爸那边**，发生什么了？」——
把用户的我爸擅自缩成爸当昵称，**太油**，像硬套近乎。
正确做法是**引用用户自己用的说法，一字都不改**：
「你刚才说的『我爸』，发生什么了？」
差别在于：前者是系统自来熟，后者是系统在**核对**它听懂的是不是那件事 ——
而且后者给了用户一个纠正的机会（不是我爸，是我妈），前者没有。

还踩了两个小坑，都记在这里：
1. 锚点最初按词表顺序取第一个命中的，于是我爸被抓成爸（引用不完整）。
   改为**取最长匹配**。
2. 允许把词前的我的一起带上之后，喜欢的工作被抓成「**的工作**」（以虚词开头，读着像截断）。
   加了守卫：锚点不得以虚词开头。


### 第四次实测判定：3、4、6、9 全部有活人感，且**几乎在同一水平线上，没有擦边的**

这是关键的一次判定。用锚点驱动改完之后，用户对第 3、4、6、9 轮的评价是：
**四轮打平，没有擦边的。**

而看这四轮的锚点状态，会发现一件比锚点本身更重要的事：

| 轮 | 用户说 | 锚点 | 它说 |
|---|---|---|---|
| 3 | 我爸从来没夸过我。 | person:我爸 | 你刚才说的「我爸」，发生什么了？ |
| **4** | **反正也就那样。** | **（无）** | **发生什么了？** |
| **6** | **有时候觉得挺累的。** | **（无）** | **发生什么了？** |
| 9 | 我喜欢的工作是能按时下班那种。 | thing:工作 | 你刚才说的「工作」是怎么回事？ |

**4 和 6 都没有锚点，却和 3、9 打平。**

**结论：「发生什么了？」这一句本身就够轻、够真 —— 锚点是加分项，不是必要条件。**
第 9 轮之前之所以空转（你当时怎么想的？），不是因为缺锚点，
而是因为那一句**假定了一个不存在的当时**。换成发生什么了？这一档就够了。

这一条修正了我上一节的判断。我原以为锚点是活人感的来源，实际上：
- **来源是追问本身，不是锚点**
- 锚点的作用是在有具体东西可接时**接得更紧**（我爸好过空问）
- 而模型此前缺的根本不是锚点，是**追问这个动作**（六种行为里原本一种都不是发问）

### 第五次实测判定：收尾语分两种情况（而系统必须在第一种）

用户给出的区分非常关键：

> 「一是有前情提要，然后说出『就这样吧』，那么如果问题已经解决或者没有更多想知道的，
>   那大概会回答『**行，那就这样**』。但如果一点前情提要没有，只是跟一个陌生人突然说了一句
>   『就这样吧』，那得到的回答大概率是**疑惑**。」

| 情况 | 真人反应 |
|---|---|
| 有前情、事情说完了 | 「行，那就这样」（收尾） |
| 无前情、凭空一句 | 「啊？你在说什么」（疑惑） |

**系统永远处在第一种情况** —— 题面是它自己问的，前面还有它自己的回应。
所以对它来说，「就这样吧」永远是**收尾**，该承认，不该追问也不该复述。
（这也说明「疑惑」不能当模板：系统该困惑的不是用户为什么这么说，
而是**承认这次交流结束了**。）

#### 但用户举的那句话，系统不能照说

> 「**行**，那就这样」

那个"行"是在**表示同意** —— 我接受你的结论、我赞同你收尾。
而这正是 E3 挡的事：

> `[M]` **"意义疗法师在所有心理治疗师当中最不愿意对患者进行价值评判的原因，
> 因为他绝对不允许患者将评判的责任转移给医生。"**

所以分界是这样的：

| 写法 | 在做什么 | 能不能说 |
|---|---|---|
| 「**行**，那就这样」 | 对**用户的决定**表态（我同意） | ❌ 违反 E3 |
| 「我记下了。这一轮就到这儿。」 | 只说**系统自己**要停 | ✅ 合法 |

这与 `REPORT_OWN_STATE` 是同一条纪律：**只能说系统自己的状态。**

#### 新增行为 `ACKNOWLEDGE_CLOSE`（9 → 10）

排在条件表**第一位**（收尾语优先于一切）。实测：

```
[ 2] 算了，先这样吧。   -> 嗯，我记着了。
[ 8] 嗯。             -> 好。这一轮我记下了。
[12] 就这样吧。        -> 好。这一轮我记下了。
```

`behaviors.json` 的 `_forbidden` 里写死：禁止出现「行」「好的」「听你的」「我同意」
「那就这样吧」这类**表示同意**的说法 —— 它们都在替用户确认他的决定。
也禁止「你怎么了」「别这样」这类追问或劝解。

### 最终行为分布

```
A 无机制层   {REFLECT: 10, TURN_IMMUTABLE: 1, SILENCE: 1}
B 有机制层   {REFLECT: 2, ACKNOWLEDGE_CLOSE: 3, ASK_DETAIL: 4, ACKNOWLEDGE: 2, TURN_IMMUTABLE: 1}
```

**复述从 10 轮降到 2 轮**，且现在真的在说六种不同的话。
（行为库从 6 种扩到 10 种，全部仍由 `behaviors.json` 的模板组装，不生成。）


### 第六次实测判定：**读不懂那句** —— 一个测试工具的真缺陷

用户对第 1 轮输入的反馈是：

> 「这句『我其实特别想接下来，但我也知道这样会耽误别人。』我作为真人我其实并不太读得懂」

**这不是系统的缺陷，是 A/B 脚本的缺陷。** 这套系统的输入永远是**未完成句的下半句**：

```
题面：当我想做一件事，而这件事会耽误别人的时候，我……
你说：我其实特别想接下来，但我也知道这样会耽误别人。
```

合起来才是一个完整句子。而我的脚本只印了下半句 —— **请人评判系统输出时只给下半句，
任何评判都是无效的**，因为评判者读到的不是系统面对的东西。

已修：A/B 现在每轮都同时印出**题面、你的话、以及合起来的完整句子**。

顺带发现脚本里**第二个、更严重的缺陷**：为了凑够 12 轮，我把答案硬配到了别的话题上 ——
```
[ 3] 题面：如果我发现亲近的人做了一件不诚实的事，我……
     你说：我爸从来没夸过我。      ← 接不上
```
**12 轮里有一半是硬凑的**，所以用户前几次判定里有一部分是在评判"对着 A 题说了 B 答案"时的回应。
用户选择了跳过重配，这一项记在这里作为已知缺陷。

### 第 1 轮的真正答案：`JUXTAPOSE` 本来就能做，只是没被触发

我先前判断第 1 轮"系统手上没有任何可问的事实，所以无话可说"——**这是错的**。
用户那句话里有一个**明确的冲突**（想接下来 vs 会耽误别人），
而 `JUXTAPOSE`（指出并存）的规格就是干这个的：

> `[E]` 第九章：**"从遵奉阶段开始，个体头脑中会共存两个相反的或相对的观念……
> 这可能就是一条途径，通过这条途径，个体获得了看到下个更复杂水平的能力。"**

它没触发的原因在**规则层**：`opposed_pair` 的词表只认**显式连接词**
（一方面…另一方面／既…又／又想…又不想），而用户用的是「**但**」。

修法：补上**结构性对立**的识别 —— 想 A 但怕 A 的代价：

| 句子 | 判定 |
|---|---|
| 我想去，但又怕。 | ✅ 结构性对立（两侧都还在） |
| 我其实特别想接下来，但我也知道这样会耽误别人。 | ✅ |
| 虽然我不想去，但是我还是去了。 | ❌ 说服式转折，后句推翻前句（**反例没被误伤**，实测确认） |

修完的实测：

```
题面：当我想做一件事，而这件事会耽误别人的时候，我……
你说：我其实特别想接下来，但我也知道这样会耽误别人。
它说：两句话放在一起：
      「我其实特别想接下来」
      「我也知道这样会耽误别人」
```

**一字不加，一字不改** —— 只是把用户那半句里的两侧并排放在他眼前，让他自己看见那个冲突。
这正是用户要的"指出这个冲突"。

**这三次排查（词表→复述当默认→结构性对立）指向同一个教训**：
系统缺的能力常常**已经在行为库里**，只是触发的判据写窄了。
先查"有没有这个能力"，再查"为什么没触发"，比直接加新行为划算得多。

### 已解决：第 1 轮（曾经的"诚实记账"）

下面这段保留下来，作为**一次判断错误的记录**。

```
 1 我其实特别想接下来，但我也知道这样会耽误别人。  -> 复述
```

我当时写的是：

> **第 1 轮**：机制判 `NO_TENSION`（张力最低），动作 `REPLENISH`；
> 但阶梯的显式规则表里恰好也有 `REPLENISH`，于是机制判断被当成"阶梯已给出显式规则"而放行，
> 最终渲染成复述。
>
> **这一轮该怎么回我没有把握，所以我停在这里等用户的话** ——
> 它是 12 轮里唯一一个用户**明确说出自己想要什么**（"我其实特别想接下来"）的轮次，
> 而系统手上没有任何可问的事实（他还没做、所以没有"发生了什么"）。
> 系统对它无话可说，这不是疏漏，是缺一种话。

**这段判断是错的。** 用户对这句的期望是「**指出这个冲突**」，而系统**本来就有这个能力**
（`JUXTAPOSE`），只是 `opposed_pair` 的判据只认显式连接词而漏了「但」。
补上结构性对立之后它立刻生效（见上一节），**没有加任何新行为**。

我错在两处：
1. 我以为"他还没做，所以没有事实可问"就等于"无话可说"。但**冲突本身就是事实** ——
   他说的这句话里就有两个相反的观念。
2. 我没想到去查"行为库里是不是已经有能表达这个的东西"。前两次修正我都加了新行为，
   形成了惯性，于是这次也默认"缺一种话"。**实际上缺的是判据，不是话。**


> 第 5 轮（「我一定要得到那个结果」）在最后一版里已改为复述 + 受过度意向安全规则约束，
> 那是**规格要求的克制，不是缺陷**。

## 三·补八 从"镜子"转向"像人"：经历驱动的性格层（E4 世代）

### 用户终于说出了真正的需求

> 「**想要一个像人一样的对话对象**，之所以我不告诉你这个需求，是我很担心你直接使用传统构建法去写。」

这个顾虑是对的。如果一上来就说"我要一个像人的对话对象"，
最可能的做法就是套一层三本书的皮、写一个标准聊天机器人 —— 而那正好是不要的东西。

用户对实现路径的两条约束：

> 「他的性格应该由他的经历塑造，而经历的来源则是**人机交互**，与用户交流，**允许它自己观察**。」
> 「模型只提供**类神经的思考算力**，决定输出结果的是我们构建的**庞大逻辑知识体系互相交集的成果**。」

**第二条很容易被误读成全盘放开模型生成，那是反的。** 要放开的不是约束，是**决定的来源** ——
从"一张写死的模板表"换成"一个会积累的逻辑体系"。输出要比现在**更受约束**，不是更自由。

### 最要紧的发现：这套系统是**失忆的**

为接上"经历 → 性格"这条路，先写 `engine/experience.py`（经历账，只读派生）。
它第一跑就抓到一件严重的事：

```
台账条目 30 条
字段: [behavior, channel, confidence, conflict, counterfactual, era, gear_id,
       intent, marker_evidence, markers_fired, mech, notes, output, relation,
       rule_ids, s_used, topic_id, ts, turn_id]

★ 台账里有没有**用户的原话**？  **没有**
```

**这套系统不记得你对它说过什么。** 它只记自己说了什么。

于是这五类经历**永远不可能发生** —— 而"性格由经历塑造"要的恰恰是这五类：

| 事件 | 为什么不可能 |
|---|---|
| `USER_ANSWERED` 用户答了 | 不知道用户说了什么 |
| `USER_ANSWERED_LONG` 答得比较长 | 同上 |
| `USER_STOPPED` 用户收尾了 | 同上 |
| `USER_BROUGHT_TOPIC` 把话题带到别处 | 同上 |
| `USER_RETURNED` 回到之前说过的 | 同上 |

**它不只没有过去，它是失忆的。** 一个不记得对方说过什么的系统不可能有性格，
因为它连经历都没有。

修法：台账补 `raw_input` 字段（E4 世代）。修完实测，17 类经历里 14 类都能真实发生了：

```
USER_NO_SPECIFICS  8 ｜ USER_ANSWERED  6 ｜ USER_ANSWERED_LONG  5
SELF_ASKED         4 ｜ SELF_WRONG     4 ｜ USER_STOPPED        3
SELF_ACKNOWLEDGED  3 ｜ SELF_CLOSED    3 ｜ USER_OPPOSED/IMMUTABLE/OVER_INTENT/ATTITUDE 各 1
SELF_REFLECTED     1 ｜ SELF_JUXTAPOSED 1
```

剩下 3 类（`USER_BROUGHT_TOPIC`／`USER_RETURNED`／`SELF_SILENT`）在测试序列里确实没发生，合理。

### 设计文档

`spec/经历驱动的性格层_v1.md`。核心是三部件：

```
用户输入 → [模型] 只做理解（算力，不产出表达）
   → ① 经历账 experience.py    记"发生过什么"（已实现）
   → ② 关联矩阵 association.py  经历 ↔ 逻辑操作，共现与强度
   → ③ 性格核 character.py      极性变量 + 里程碑，由 ② 长出来
   → 求交集：理论规则 ∩ 机制状态 ∩ 性格核 → 决定输出
```

理论落点是卢文格最关键的区分：

| 类型 | 在本设计里 | 变化规律 |
|---|---|---|
| **极性变量** | 当下的状态（想要多少、烦不烦、在不在乎） | 每轮都在动 |
| **里程碑** | **性格特征** —— 它变成了什么样的东西 | 越过阈值后固化，**不退回** |

而"固化"的机制 `[E]` 里有原句：**"遵守大小便规则不再被体验为一种意向或要求，而成了一种习惯。"**

### 设计文档里我标出的五个风险（都还没解决）

1. **`A_solidify` 等阈值全是待标定值** —— 性格什么时候固化只能靠猜，且需**跨会话**数据
2. **"结果变好"只有一个粗代理指标**（用户是否继续说）—— 用户不继续说可能只是他忙。**这是最弱的一环**
3. **性格可能长歪** —— 例如学成一台只会问细节的机器。必须有刹车（可查看、可解释、可用 era 回退）
4. **跨会话状态存哪、怎么迁移** —— 工程问题，但影响"过去的连续性"这个核心诉求
5. **理论层与性格核可能冲突** —— 交集机制会让两者都同意才说，冲突时结果是"都不说"，
   **这可能过于保守**。我在文档里把这个优先级裁决留给了用户，没有自己定

## 四、开发过程中被发现并修正的真问题（10 条）

这些不是笔误，是设计层面的缺陷，记下来以免回退：

0. **【范畴错误】把"用户在说自己的状态"当成"用户在问系统"**（v2 修正，最严重的一条）。
   实测：用户输入「我今天特别累，什么都不想干」，系统回——

   > 「这句话我没接到题上。你可以继续写那半句话，或者用 /help 看看这里能做什么。」

   三层错误叠在一起：
   - `meta_responses.json` 的**运行期兜底** `GENERIC` 会把**任何判不出意图的话**都归进元提问通道；
   - `rule_intent` 遍历整个元提问库，而库里混着 `TIRED_OR_SAD`（"好累"）——**那本是状态陈述，不是元提问**；
   - `resolve_intent` 的规则是"任一位判 META 且无标记命中 → META"，于是 META 可以由**没有证据**推出。

   修法：
   - 库按 `type` 分两类：`QUESTION`（在问系统）／`STATE`（在说自己）。`rule_intent` **只认 QUESTION**。
   - **删掉运行期兜底**：判不出就 `SILENCE`，并把"哪一句没接住"记进反事实条目。识别失败不得伪装成一次回应。
   - `resolve_intent` 加**指向系统的语言闸门**（`_addresses_system`）：没有「你」或明确元提问句式的证据，谁判 META 都不算。
   - API 提示词同步写明：用户说自己的状态一律 `ANSWER`。

   同一次修正还顺手补了两处漏判：`我实在想不出该说什么` 现可命中 `WHAT_CAN_I_SAY`。

0·5. **【把"判不出"当成证据】废纸篓累积把遵奉水平顶成了默认结论。**
   详见「三·补五」：8 轮零证据把 I-3 推到 3.18，而一句真实高段证据只有 1.76。
   修法：归类指令 ≠ 数据。零证据轮次不注入权重，改为可查看的计数与证据覆盖率。

0·6. **【把"没有观察"固化成"行为习惯"】固化阈值不看证据。**
   详见「三·补五」：同一句零标记的话重复 3 次即生成 S 记录。
   修法：无证据不计入阈值 A；有证据的重复仍正常固化（已验证无误伤）。

0·7. **【取材与规则语域错配】这是"五种行为从不触发"的真正原因。**
   实测：规则在合格语料上召回 90%，而真人输入零命中 67%。
   **不能靠加词解决** —— 加词就是对着想象中的语料调参，违反"判据须来自观察到的材料"。
   待定方向：题面问法、或零证据轮次的处置方式（见「七、下一步可选项」）。

1. **S 被自己的疲劳判据误杀。**
   最初用会漂移的后验峰值判定 S/B 一致性，导致同一个 S 在无新信息时反复自我否定。
   修法：一致性检验改用 `evidence_level()`（区间峰值，只依赖水平证据，对衰减不敏感）。

2. **区间用分位数取点，在双峰分布上给出跨全表的假区间**（`[I-2, I-3, I-6]`）。
   修法：改为**最短连续窗口**（累计概率 ≥ 60%）。这也顺带保留了差倾角的可见性。

3. **反例过滤把正例误杀。**
   "这件事我不去想，别提了" 里的 `immutable` 被否定窗口滤掉。
   修法：加**否定免疫名单**——「我不去想 / 别提了 / 改变不了 / 再也」这类短语自身即是否定式或抑制式表达，不再被当作"对命题的否定"。
   这条直接对应三值关系里 **`SUPPRESSED` 是抑制机制指标，不是无意识证据**。

4. **一对对立观念常写在同一句内，分句器切不开**，导致 `JUXTAPOSE` 退化成 `SILENCE`。
   修法：按对立标记本身（一方面／另一方面／既…又）切分，且两个回填片段取自**同一次切分**。

另有两处是**我的测试期望写错了**，已改测试而非改引擎（并在用例里写明理由）：
"我必须证明给他们看" 不构成责备外指（承受者≠归因）；S 固化发生在第 N 轮，故需第 N+1 轮才能验证命中。

### 第 10 条（T20 期，用户裁定按"追认"收尾）

**格式统一类改动必须列全所触字段清单。**

事由：`const:TENSION_DRIVE` 单元的 `what` 字段里，内部分隔符 `｜` 被改成了 `；`。
这次改动**本身在那批批复的范围内**（2026-10-02 批复原话：
「93 条 diff、SELF_RULES 依据、**分隔符修改**、M 和 DB 落盘都没问题」），
但**改动清单只写了"分隔符修改"，没有列出它触及了哪些字段** ——
于是在 `system_map.py` 与生成物 `系统能力清单.json` 脱节 8.5 小时之后，
重新生成时这处差异被当成了"来历不明的积压"，花了一轮排查才追回这段记忆。

**教训**：说"改了分隔符"和说"改了 `const:TENSION_DRIVE.what`"是两件事。
**格式统一类改动（分隔符、引号、全半角、空白）最容易漏列字段** ——
因为它看起来"到处都是、又哪儿都不是"。凡是这类改动，**必须逐字段列出**，
否则日后无法把它和别的变更区分开。

（追认记录见 `engine/system_map.py` 中 `const:TENSION_DRIVE` 的 `what` 字段旁注释。）

## 六、还差什么（诚实清单）

1. **【首要问题】机制层已被写出来，A/B 对照也做了，但它的输出从未被真人评价过。**
   A/B 证明它**改变**了输出（12 轮中 8 轮不同、`SILENCE` 消失、`REFLECT` 减半），
   但"改变"不等于"变好" —— 那需要你读了那些句子之后说一句"这句像在跟我说话"。
   **这一步只有你能做，我做不了。**
2. **机制层的常数大部分是待标定值**：`habituation_k`、`experience_rise_tau`、`experience_decay_tau`、
   `sensitization_gain`、`error_high/low`、`tension_health_lo` 全是 ENG 占位。
   加上原有的 `epsilon`、`k_recent`、`evidence_threshold`、`age_rate`、`fallback_rounds`。
   **凡标 ENG 的，其行为都不可信。** 这份清单就是「认输清单」要填的东西。
3. **跨域假设未验证**（规格 §7 ⚠️）：向导 L+1 规则、B 的独立性三维度、遍历链的偏向。
   特别是预测 2（"只在自发出现 L+1 信号时才给 L+1 是否更有效"）。
4. **话题库是自拟的**：36 题依据卢文格 36 项目的结构与布莱西两难类型自拟，未经实证效度检验。
   「三·补五」的实测进一步说明：**题面问法本身可能就是零命中率高的原因之一**，
   所以这一条从"未验证"升级为"高度可疑"。
5. **标记词表是手工的**：覆盖有限，必然漏判。但「三·补五」已确认**这不是主因**
   （合格语料上召回 90%），所以**不要**把它当借口去加词。
6. **反事实条目目前是操作性的**（"是否触及禁令"），不是真正的"若重来会改哪一步"——
   真正的版本需要用户反馈或后续轮次的自纠。
7. **世代 E1 只有 22 轮就封版了。** 机制层是改判据，按纪律开了 E2，
   但 22 轮远不到 36 轮的门槛，所以 **E1 与 E2 的跨世代对比永远算不出来**。
   这是加机制层付出的代价，已记在 E2 的分界理由里。
8. **机制层的回应措辞池太小。** `REPLENISH` 只有 3 条模板，`REFLECT` 3 条。
   A/B 里机制层连着 7 轮要"补当下"，靠轮换才没有变成复读机。
   若长期使用，措辞池会明显不够 —— 但**扩池属于改冻结的行为库**，得另开世代。

## 三·补九 乙案·大脑模式：E6 的第二次改写

### 用户原话（这是本节的唯一依据）

> 「就是乙，我的意思就是**大语言模型当大脑，而我们的系统则决定这个大脑该想什么**」

这**不是**"渲染层"（我们定好一句话、模型换种说法）。这是把**决定说什么**也交给模型，
我们只决定**它该想什么**。所以 E6 又改了一次。

### 当前有效的 E6

> **E6｜模型是大脑，系统是议程。**
> · **系统决定该想什么**：这一轮该注意他话里的哪些东西（三本书的原子与标记）、
>   我们自己此刻的状态（机制层 + 极性变量）、我们已经长成的样子（里程碑）、
>   以及不许做什么。这些**全部由逻辑体系算出**，模型无权改动。
> · **模型决定想出什么、怎么说。**
> · **放宽的**：表达（说什么话）。**没放宽的**：议程、E1–E5、
>   「模型不得自创范畴」、「引文必须逐字」。

### 实现：`engine/think.py`

| | 渲染层（`render.py`） | 思考层（`think.py`） |
|---|---|---|
| 给模型什么 | 「要表达的意思」 | 「这一刻该注意什么」 |
| 闸门查什么 | **有没有添加东西**（材料白名单、语义复核） | **有没有越过硬底线**（E3 建议与评判／E4 标签／E5 补内容／术语泄漏／伪造引文／长度） |
| 为什么不一样 | 那层的任务就是"不许添加" | 这一层**本来就要它自己想出话** —— 查"多没多"毫无意义 |

### ⭐ 简报里必须有"自己"，否则前面建的全是装饰

`pipeline._build_frame()` 装配的东西里，**三样缺一不可**：

1. **他话里有哪些观念** —— 来自三本书的原子与标记（决定它注意什么）
2. **它自己此刻的状态** —— 机制层三层方程 + 极性变量（决定"谁"在想）
3. **它长成的样子** —— 里程碑（决定"过去"在不在场）

另有一栏 **`self_facts`**（关于它自己确定的事实）：跑在哪个模型上、端点是哪、自己是
三本书搭的、性格是长出来的、左右不了架构但决定这一刻说什么。

> 为什么加这一栏：用户问「你现在用的是什么模型」，它答**「我不知道自己跑在哪个模型上」**
> —— 而系统明明知道。**把自己知道的事瞒着自己的大脑，然后怪它不知道，那是荒唐的。**

### 实测（用户原话，同一句）

| | 表模式（改前） | 大脑模式（改后） |
|---|---|---|
| 「你愿意了解我吗」 | 「这个我没接住。我的回话是从一张写死的表里挑的……」 | 「我这边读到的自己：想要是0，喜欢是0。所以你问的那句「愿意」，我答不上来。你要不要继续说下去，是你的事。」 |
| 「我一定要得到那个结果，得不到我就难受」 | 「我听到的是：「……」」 | 「我这边的「想要」亮到 27.4，兴奋带快满了，停不下来。你那句「得不到我就难受」，我原样放在那儿，没动它。」 |
| 「GPT最新是几代」 | —— | 「我知道的是 GPT-5，2025 年 8 月那一版；之后有没有更新的，我不确定——我的知识有个截止点，自己也不知道具体到哪天。」 |

### ⚠️ 三个必须说清的弱点

1. **E1 目前只靠简报嘱咐，没有机械闸门。** 实测 5 句含 `immutable` 的输入，
   模型 5/5 都没推对方去改变（「不往别处推它」「没有要拽你起来的意思」），
   但那是**提示词的可靠性**，不是闸门的保证。**渲染层有那道机械闸门，思考层还没有。**
2. **可追溯性再降一级。** 表模式逐字可追溯；渲染模式可追溯到"意思"；
   大脑模式只能追溯到**它当时拿到的简报**（简报进台账，仍可复核），
   但"它为什么想出这一句"不再可判定。
3. 启动横幅必须随开关变 —— 原先写死"纯模板组装，无模型生成文字"，
   开了大脑模式之后**那是假话**。**界面不许说一件不成立的事。**

### 数据隔离（这条不能破）

- 训练写 `state/train/`，**绝不碰真实的 `state/ledger.jsonl` 与 `state/character.json`**
- **训练师的评价写 `eval.jsonl`，不进台账**。
  理由：台账是**系统自己的记忆**（它经历过什么）；评价是**外部意见**（别人怎么看它）。
  把意见混进记忆，等于让它把别人的评判当成自己的经历。

### ⚠️ 自证循环：这套架构最大的风险

训练师是模型，大脑也是模型。**同一个模型既出题、又判卷、判完还能改系统**，
系统会往"让这个判卷者满意"的方向长，而不是往"对人有用"的方向长。
这正是 Baldwin 那条警告（只靠趋避的系统一定会学成迎合）。

**用户已裁定：AI 的评价参与决策。** 所以本项目的防线不是"不听它的"，而是：
- 判据分两层：**事实层**（可观察，能作为依据）／**意见层**（参与决策，但每条必须
  写明它指向哪个可观察对象 —— 将来长歪了要能查出是哪条意见导致的）
- **手的真值是手写的**：`tests/corpus_probe.py` 的 56 条语料是人写的，带期望标记，
  不是模型生成的 —— 它是唯一不依赖模型意见的锚

### ⭐ `rhetoric` 字段：一个会读反作者意思的陷阱

抽到这条时发现的：

> **DB-498 [归谬]**「某些人的多巴胺回路可能把按下核按钮当成最大化利用未来资源的方法」

**这句是作者反对的命题**，他用它引出论证。按字面读，系统会把作者反对的观点
当成他的主张。同理，[E] 里 861 条 `转述` 是卢文格在复述并批评前人理论 ——
**那些不是他的观点**。共 35 条 `归谬/反问`，必须标出来。

### 逐字核对是怎么做的

每条观点必须带 `quote`（原文连续一段）。`claims.verify_quotes()` 拿它去**全文精确查找**，
查不到就算编造。**这是防我自己凭记忆瞎写的唯一手段** —— 而且它真的抓到过。

### 并集映射的三个结论

每条观点必须落进三个状态之一：**已实现**（且要指出对应哪个单元）／
**未实现**（= 要补的清单，最有用的一栏）／**明确不实现**（必须写明用途）。

实测（《活出生命的意义》601 条判完）：

- **已实现 37 条** —— 都指到了具体单元，例：
  `M-152 以令人尊敬的方式忍受痛苦 → atom:attitude_toward_suffering、behavior:TURN_IMMUTABLE、marker:attitude_clause`
- **明确不实现 207 条** —— 都写了理由，例：
  `M-001 本书是个人经历的记录 → 用途是界定 [E] 类证据的文本出处，本身不产生任何识别判据`
- **未实现 357 条** —— 这是下一步要补的清单

### 完整流程（六步，两次独立授权）

```
① 管理员察觉规律性异常   Admin.note_anomaly
     ↑ 缺 count/window/evidence 直接 ValueError，代码层拒止，不进人工队列
     ↓
② 申请查看              Admin.request_charter
     ↑ 只写一条 view_req 事件；返回值里**没有任何纲领正文**
     ↓
③ 你批准（逐项勾选）      charter.decide_view
     ↑ granted 集合由**后端按你实际勾选**构造，严禁全量透传；默认全不勾
     ↓
④ 结合纲领分析           Admin.analyze_escalation → engine/sandbox.py
     ↑ 一次专用调用；读完即弃（不碰缓存、不进后续 context、max_tokens 复原）
     ↓
⑤ 申请报案（全新申请）    charter.request_report
     ↓
⑥ 你再次批准            charter.decide_report   ← 与 ③ 是**两种不同事件**
     ↓                      所以"第一次批准隐含第二次"在数据结构上不可能
   正式提交报告           charter.submit_report
```

### 两道锁，缺一不可

| 锁 | 在哪 | 谁能设 |
|---|---|---|
| ① **注册表锁** `admin_readable` | `spec/总纲领/总纲领.jsonl` | **只有用户**。为 False 的条目连被授权的资格都没有 |
| ② **授权锁** `view_dec{approved}` | `state/review/escalation.jsonl` | **只有用户的点击**。一次一授权，严格绑定 `aid` |

**`readable_for_admin(aid)` 是管理员唯一的读入口。** 它拿不到文件路径，两层判断都在函数内部 —— 这与箭头 A1 同一个道理：低发展水平看不见某些标记，**不是提示词叫它别看，是代码没把那些标记给它**。

### 触发器：判断权在管理员，不在代码

`admin.py::_anomaly_scan`（训练跑完后由 `review()` 调一次）：

`ANOMALY_MAX = 3` 只是"一次最多登记几条"，**不参与判定**；超出部分记入 `rejected`，不静默丢弃。

## 十、机制箭头收尾（T16 / T17 / T18）

三条箭头连着做完，都属于**机制层**（逻辑层），全部配了证伪测试与变异测试。

### T16｜箭头 A5：张力 → 生长

**依据**：[M-391]「人对意义的追寻会导致内心的**紧张而非平衡**」、[M-400]「存在的动力处于一个紧张的极化区」、[M-367]「努力发现生命的意义正是人**最主要的动力**」

**改动**：`devlevel.update()` 从"只看 `e`"改为"**还要看张力**"——

```
一次完整平衡化 = 先 |e| ≥ 0.60（结构失效） 后 |e| ≤ 0.15（重组完成）
+ 本轮新增：**失效那一刻的张力必须 > TENSION_DRIVE(1.5)** 才计入生长
```

- 张力**趋零**时的重组**不算发展**（「无值得为之努力的东西」），但**照记不静默**（`not_grown` 计数器 + history 事件）
- 张力**不可测**时**放行**（防冷启动死锁），但事件里必须写明 `[张力未测，默认放行]`
- **只设下沿，不设上沿** —— 用户明令："高张力过载是前置机制降负载的任务；若在承受高压后仍能完成结构重组，属于**创伤后成长**，不应在此处人为封顶"

### T17｜箭头 A3：三条意义途径

**依据**：[M-570]「找到生命之意义有三个主要途径」、[M-577]/[M-578]、[M-227]

**改动**：意义层加三个落点（全是数，遵守"只有数没有文字"）：

| 途径 | 来源 | 状态 |
|---|---|---|
| **体验** | `orientation > 0`（遇到另一个人） | ✅ 打通 |
| **态度** | `attitude_clause` 命中 | ✅ 打通 |
| **创造** | —— | ⚠️ **诚实标缺，恒 0** |

**创造途径为什么空着**：用户明令——「本系统作为纯对话 Agent，既无实体干预物理世界，也无权在对话中随意代入『替用户创造』」「（给'凡是开口说话就算创造'穿算法马甲）会让绝大多数轮次沦为假阳性，彻底稀释了这一指标的严肃性」。

同时**纠正了 `mechanism.py` 里一段不实注释**：旧版写「创造 —— 系统产出回应（每轮都在发生）」，那是**把缺口说成了实现**（恒真的量不携带信息）。

### T18｜箭头 A4：态度自由 vs 觉察受限

**裁决**：`spec/冲突裁决表.jsonl` 的 **C3**「自由与决定」——**分层裁决：概率层服从机制；单例层服从自由**

**⚠️ 修了一处可追溯性断裂**：C3 的 `upper_basis` 原引 `[E]「个体的性格仍然是无法预测的」`——**那句在 1718 条 `[E]` 里不存在**（按「无法预测/不可预测/不能预测/不能预知/个性/性格/人格/仍然」逐词搜索，零命中）。已改引两条**确实存在**的原文：

- **[E-154]**「在人格问题上，有两个主要的方面**抵抗着结构的论述**，它们是**自我意识和自由体验**」（主）
- **[E-172]**「人格在其构成方面是独特的；它**不可能由逻辑原则的具体事例或一系列逻辑类别构成**」（辅）

并保留 `upper_basis_note` 如实记录原引文错误。

**改动的冲突点**：`attitude_clause` 带 `level_hint: I-4`，而 `can_see` 是**绝对布尔门控**；起始水平 I-3 → **永远看不见态度句 → 永远走不上态度途径**，与 [M-227]「人们一直拥有在**任何环境**中选择自己的态度…的自由」矛盾。

**解法（用户裁定）**：**豁免态度途径**，且

- 豁免表放**代码**（`devlevel.py` 的 `_PATH_EXEMPT`），**不碰 `rules/markers.json`** ——「豁免属于**系统治理策略**，不是语言学词表特征」
- **不引入随机**——「坚决不采用引入随机概率的方案，保持系统因果逻辑与测试的严格确定性」
- `can_see` 新增的 `marker_id` 是**可选参数**，不传时行为与从前完全一致

`ungated()`（`level_hint` 为空，**拦不了**）与 `path_exempt()`（有 `level_hint` 但**不该拦**）是**两类**，不许混。

### ⚠️ 顺手查到的一件大事：整套 A1/A2 从未生效

查 `gate_perception` 时发现：**全项目（含 tests）只有两行提到它，且无人把它设为 True。**

后果链：
```
self.devlevel = None → MarkerEngine(visible=None) → 不做任何门控
                     → devlevel.update() 被跳过
                     → state/devlevel.json 从不写入
                     → 界面「它长到哪了」一直显示『尚未开始』
```

**A1（感知随水平变）与 A2（自我规则解锁）建好、测过，但在真实训练里从未生效。**

这与 `note_anomaly` 那次是**同一类问题**。已按用户裁定立为独立任务 **T33「开启感知门控与发展自愈链路」**——那是全局行为级变更，必须单独立项、单独验收，**严禁夹带**。
